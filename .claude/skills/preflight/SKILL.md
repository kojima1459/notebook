# 実装前プリフライト報告

CLAUDE.mdの2層ルールに従い、以下のテンプレートで報告を作成する。専門用語は使わず、使う場合は1文で説明を添える。各項目1-2文で簡潔に。

## テンプレート

**対象**: （ユーザーの報告番号・要望の要約1行）

1. **何が起きているか**: 原因を1-2文で。「〜のはず」ではなく調査で確定した機序を書く。未確定なら「2つの可能性があり、実機の〜で切り分ける」と正直に書く。
2. **何をどう直すか**: 変更する場所と方法。ファイル名でなく「どの画面のどの動作」で言う。
3. **直すとどうなるか**: ユーザーの体感で何が変わるか。
4. **壊れるリスクがある場所**: この修正が触る繋ぎ目（例:「本棚の描画も同じ処理を通るので、そちらの表示も確認対象」）。無ければ「独立した修正で波及なし」と明言。
5. **実機での確認方法**: ユーザーが1-3分でできる確認手順。

## 層の判定（CLAUDE.md準拠）

- 層1（新機能・設計変更・ロジック変更・解釈が割れる修正）→ 末尾に「**GOをください。GOまで実装しません**」を付けて待つ。
- 層2（原因確定済みの明白なバグ修正・文言・1行）→ 末尾に「**明白な修正のため着手します。方針が違えば止めてください**」を付けて進める。
- 複数項目が混在するラウンドでは、項目ごとに層を明記した一覧表にする。
