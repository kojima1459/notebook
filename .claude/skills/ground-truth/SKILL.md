# 資料の事実確認（外へ出る前に）

**設計書は「そうしたい」と書いてある。出荷ビルドは「そうなっている」とは限らない。
外へ出る資料の典拠は、必ず後者にする。**

2026-09-01、発表資料に `DESIGN_v3_運用設計.md` を典拠として
「個人情報検査で自動中止」「30日で自動消去」と書いた。
実際の出荷既定値は **`pii_scan_enabled=FALSE`** と
**`knowledge_expire_days=0`（無効）** で、どちらも動いていなかった。
部長への説明の直前に気付いて止めた。**設計書を読んだこと自体は正しく、
それを実装の現状として書いたことが誤り。**

## 手順1: 一次情報の入口を1つにしない

資料を組む前に、**必ず `docs/` 直下と `docs/dev/` の見出しを一覧**する。

```bash
ls docs/ docs/dev/
cat docs/dev/INDEX.md
```

2026-09-01、`README` と `docs/dev/FEATURES.md`（機能一覧）だけを起点に
発表資料を組み、**部門ナレッジ配信の章がまるごと抜けた**。
`DESIGN_v3_運用設計.md` は「運用設計」という別カテゴリの文書で、
機能一覧からは辿れなかった。ユーザーに指摘されて発覚した。

## 手順2: 主張を「実測できる形」に割る

資料の中の断定文を洗い出し、それぞれ何で裏を取るか決める。

| 主張の型 | 典拠にするもの | 取り方 |
|---|---|---|
| 「〜という設定になっている」 | **出荷ビルドの config シート** | 手順3 |
| 「画面に〜と出る」「〜ボタンがある」 | **実装の文字列そのもの** | 手順4 |
| 「〜件まで入る」「〜秒で返る」 | 実測値・ベンチ | `tools/bench_retrieval.py`・実測ログ |
| 「〜する方針」「〜を目指す」 | 設計書でよい（**未実装と明記する**） | `docs/dev/`・`docs/DESIGN_v3` |

## 手順3: config の既定値は「ビルド成果物」から読む

`build/build_mybookshelf.py` のソースではなく、**実際に配るファイル**を読む。

```bash
python3 -c "
import openpyxl
wb=openpyxl.load_workbook('dist/MyBookshelf.xlsm', read_only=True, keep_vba=True)
d={r[0]:r[1] for r in wb['config'].iter_rows(min_row=2,max_col=2,values_only=True) if r[0]}
for k in ['mock_llm','embed_transport','azure_embed_key','publish_key',
          'pii_scan_enabled','allowed_domain','knowledge_expire_days',
          'telemetry_enabled','chunk_limit']:
    print(f'{k:24}= {d.get(k,\"(なし)\")!r}')
wb.close()"
```

**機能フラグが `False` / `0` / 空なら、その機能は「ある」ではなく
「入っているが既定オフ」。資料にはその区別を書く。**

## 手順4: 画面の文言は grep で現物を取る

想像で書かない。ボタン名・絵文字・ダイアログ文は実装から転記する。

```bash
grep -rn '"[^"]*<探す語>' src/ui/*.bas src/qa/*.bas | head -20
```

絵文字は `ChrW(&HD83D) & ChrW(&HDCE4)` のようなサロゲートペアで書かれている。
コードポイントを実際の絵文字に直してから資料に載せる（📤＝DCE4、🔍＝DD0D、
🌐＝DF10、💡＝DCA1、🗑＝DDD1）。

## 手順5: 「動くが、条件つき」を隠さない

**制約を書かない資料は、書いた本人以外には嘘になる。**

実例（2026-09-02、Teams向けの使い方案内）: モード切替で会話は引き継がれるが、
**一般→社内ナレッジの向きだけは「深掘り(続けて質問)」を押さないと効かない**
（`modConvBridge` 冒頭に既知の非対称として明記されている）。
これを書かずに「引き継がれます」とだけ案内すると、全員が「覚えていない」と
報告してくる。**アプリ自身がトーストで案内している文言を先に読むこと。**

## 手順6: 報告のしかた

資料を渡すとき、**確認できなかったものを黙って落とさない**。

```
【この資料の典拠】
・config の既定値: dist/MyBookshelf.xlsm を実測（<日付>ビルド）
・画面文言: src/ 実装から転記
・未確認: <実機でしか確かめられない項目>
【設計書と出荷の食い違い】
・<項目>: 設計書は<X>／出荷既定は<Y>。資料は<どちらで書いたか>
```
