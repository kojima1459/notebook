# 部門ナレッジ（正典）の作り方 ― ステップバイステップ

> **この文書は誰向けか**: 部門の正典を作る担当の方向けです。**エンジニアである必要はありません。**
> **`46_正典発行ガイド` との違い**: 46は「**配るボタンの押し方**」。この文書は「**何を書くか**」です。
> **今日やること**: 手を止めているなら、**§1 の30分だけ**やってください。それで最初の版が出せます。

---

## 0. 先に、いちばん大事なことを1つだけ

> ## 正典に入れるのは「**資料**」ではなく「**答え**」です。

100ページの規程PDFを入れるのは**間違い**です。入れるのは、

> 「経費精算の締切っていつ？」→ **「毎月5日の17時までです。過ぎた分は翌月払いになります（経理部確認済み・2026-09）」**

この形の、**すでに答えが確定している質問と答え**だけです。

**なぜか**（数字で説明します）

このツールは資料を細かく切って覚えます。入れ物の上限は**1人あたり20,000個**。

| | 使う量 |
|---|---|
| Q&A形式の正典 500件 × 6部門 | 3,000〜6,000個 |
| 各自が自分で入れる資料 20冊 | 〜2,800個 |
| **合計** | **6,000〜9,000個**（上限20,000に余裕） |

ところが**100ページの規程を丸ごと入れると、それだけで1部門で数千個**。6部門が同じことをすると上限を超え、**部門全員のツールが使えなくなります**。

原文が要る人は、その人が自分の本棚に個別に入れます。**正典は「答え」だけを持つ。** これが唯一の運用ルールです。

## 1. 今日の30分：最初の10件を作る 🚀

**完璧を目指さないでください。10件で十分に始まります。** あとから何度でも更新できます。

### ステップ1-1（10分）：材料を集める

**ゼロから考えないでください。すでにある質問を使います。**

材料になるもの（上から順におすすめ）:

1. **「教えてBOX」に実際に来た質問** ← **最高の材料**。実在の質問で、答えも出ています
2. メールやTeamsで**何度も同じことを聞かれた**やりとり
3. 新人研修で毎年説明していること
4. 「これ、〇〇さんしか知らない」という業務のコツ

**選ぶ基準はこれだけです。**

- [ ] **2回以上聞かれたことがある**
- [ ] **答えが確定している**（「たぶん」でなく、確認済み）
- [ ] **部門の人なら誰が聞いても同じ答えになる**

3つとも○なら入れる。1つでも×なら**今回は入れない**（次の版でいい）。

### ステップ1-2（15分）：この型で書く

Windowsの**メモ帳**でも、**Word**でも、何でも構いません。1つのファイルに続けて書きます。

```
【Q】経費精算の締切はいつですか？
【A】毎月5日の17時までです。過ぎた分は翌月払いになります。
　　 領収書の原本は経理部の所定ボックスへ、締切と同じ5日までに提出します。
　　 5日が土日祝の場合は前営業日に繰り上がります。
【補足】システム上は5日23:59まで入力できてしまいますが、17時以降の
　　　　入力分は当月に間に合いません。
【確認】経理部・2026-09時点

【Q】出張申請は何日前までに出せばいいですか？
【A】出発の5営業日前までです。
　　 航空券・新幹線の手配が必要な場合は10営業日前を推奨します。
【確認】総務部・2026-09時点
```

**書き方のコツ**

| コツ | 理由 |
|---|---|
| **1問1答を400〜700字**くらいに | このツールは約700字を1つの塊として覚えます。この長さがいちばん探しやすい |
| **質問は、実際に聞かれた言い回しのまま**書く | 利用者も同じ言い方で聞くので、当たりやすくなる |
| **「いつ時点の情報か」を必ず入れる** | 古くなったときに気づけます |
| **答えを1行で終わらせない** | 「毎月5日」だけだと、土日のとき・過ぎたときが分からず、結局人に聞かれます |
| **同じ意味の別の言い方も入れる** | 例:「経費精算」と書いたら「立替精算」「精算」も本文のどこかに入れておくと当たります |

### ステップ1-3（5分）：保存する

- **ファイル名**: `商品部_正典_2026-09.txt` のように、**部門名と日付**を入れる
- **形式**: `.txt` `.md` `.docx` `.xlsx` いずれも可（**迷ったら .txt かWordの .docx**）
- **置き場所**: **自分のPCのどこでも構いません**（D ドライブでもデスクトップでも可。§4参照）

**ここまでで「配れる中身」は完成です。**

## 2. 取り込んで、発行する

1. `MyBookshelf_発行者用.xlsm` を開く
2. 「📁 資料を入れる」で、いま作ったファイルを取り込む
3. 「ナレッジ」画面 →「📤 正典を発行」
4. 以降は **`46_正典発行ガイド` の §4** のとおり

**発行後は、自分で1つ質問して確かめてください。**
書いたはずのことが答えとして返ってくれば成功です。返ってこなければ §6 を見てください。

---

## 3. 1ファイルにする？ 分ける？

**最初は1ファイルで構いません。** 増えてきたら**テーマで分ける**と管理が楽です。

```
商品部_正典_経費関係_2026-09.txt
商品部_正典_申請手続き_2026-09.txt
商品部_正典_システム操作_2026-09.txt
```

> **分けても、発行は1回です。** 発行は「いま本棚に入っている自分の資料**全部**」をまとめて出します。ファイルを何個に分けても、部門の人には1つの正典として届きます。

---

## 4. ファイルの置き場所について（D ドライブでも大丈夫です）

**結論: 材料ファイルは D ドライブに置いて構いません。何も変わりません。**

このツールには**性質の違う置き場所が2つ**あり、混同しやすいので整理します。

| | 何を置くか | どこに置く | D ドライブでいい？ |
|---|---|---|---|
| **A. 材料ファイル** | あなたが書いた Q&A の元ファイル | **どこでも**（D:／デスクトップ／自分のフォルダ） | ✅ **問題なし** |
| **B. 共有フォルダ** | 発行された正典（`pack.xlsx`） | **全員が読み書きできるネットワーク上の場所** | ❌ **不可** |

**なぜ B は D ドライブではだめか**: D ドライブは**その PC の中だけ**にあります。他の人からは見えないので、そこに正典を置いても誰にも届きません。

**B のフォルダ構成は、材料をどこに置いても一切変わりません。** アプリが自動で作ります。

```
<共有フォルダ>\                 ← config の nexus_share_path で指定する1箇所だけ
    channels\
        商品部\
            pack.xlsx           ← 正典の本体（アプリが作る）
            version.txt         ← 版番号
            publish_log.txt     ← 誰がいつ何件出したかの記録
            _archive\           ← 過去版（戻すときに使う）
        人事部\
            ...
```

> **全部門の正典は「1つの場所の下」にぶら下げます。** 部門ごとに別の共有フォルダを指定することはできません（各PCは `nexus_share_path` という**1つの設定値**だけを見て、その下の `channels\<部門名>\` を探すため）。

## 5. 育て方（作りっぱなしにしない）

**正典は1回作って終わりではありません。いちばん楽な育て方はこれです。**

1. アプリの「**💡 みんなの困りごと**」を開く
2. **答えが見つからなかった質問**が溜まっています
3. その中から「答えられるはずのもの」を選ぶ
4. §1-2 の型で書き足して、**もう一度発行**

**利用者が勝手に「次に書くべきネタ」を集めてくれる仕組みです。** ネタ切れになりません。

**更新の頻度**: 週1回程度でまとめて出すのが現実的です（版が変わると全員が受け取り直すため、頻繁すぎると共有フォルダの負荷になります）。急ぎの訂正だけ随時。

---

## 6. うまく答えてくれないとき

| 症状 | よくある原因 | 直し方 |
|---|---|---|
| 書いたはずのことが出てこない | 質問の言い回しが、書いた言い回しと違いすぎる | 本文に**別の言い方も入れる**（「経費精算」＋「立替精算」） |
| 関係ない答えが返る | 1つのQ&Aに複数の話題を詰め込んでいる | **1問1答に分ける** |
| 答えが途中で切れている感じ | 1件が長すぎる（1,800字を超えている） | **2件に分ける** |
| 古い内容で答える | 前の版がまだ残っている | 発行し直す。それでも直らなければ利用者にファイルを開き直してもらう |
| 使用量が80%を超えた警告が出た | 原文を丸ごと入れてしまっている可能性 | §0 に戻る。原文は本棚から外し、要点だけ残す |

## 7. やりがちな失敗（先に知っておくと得します）

| ❌ やりがちなこと | なぜだめか | ✅ こうする |
|---|---|---|
| 規程・マニュアルPDFを丸ごと入れる | 容量を数千個食い、**部門全員が使えなくなる** | 要点とQ&Aだけを書き起こす |
| 「たぶんこうだと思う」を入れる | **間違いが部門全員に配られる**。人が聞きに来るより悪い | 確認できたものだけ。確認中は入れない |
| 契約者名・電話番号などを入れる | 個人情報が部門全員に配られる。**自動チェックは既定オフです** | 固有名詞は伏せる。発行前に自分の目で見る |
| 完璧な100件を目指して着手しない | **いつまでも誰にも届かない** | **10件で出す。** あとから何度でも更新できる |
| 「全社共通」チャンネルを作る | 管理する部署が決まらず必ず破綻する | 実在の部門名と1対1にする |
| 他部門から受け取った正典を混ぜて再発行 | — | **心配不要**。発行対象は「自分で入れた資料のみ」で、アプリが自動で分けています |

> **「これ、部門の人に口で説明したことがあるか？」**
>
> ある → 正典に入れる価値があります。
> ない → 今回は見送ってよいです。
