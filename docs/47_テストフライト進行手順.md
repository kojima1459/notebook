# テストフライト進行手順（開発側リーダー用）

> **この文書は誰向けか**: 実機テストを主催する**開発側リーダー**向けです。
> **何が分かるか**: 誰に何を渡すか、どの順番で進めるか、報告をどう受けるか。
> **想定体制**: 発行担当 1名（事務局） / テスター 数名 / 開発側リーダー 1名（あなた）

---

## 1. 配役と、渡すもの

| 役 | 誰 | 渡すファイル | 渡す文書 |
|---|---|---|---|
| **正典発行者** | 事務局リーダー | `MyBookshelf_発行者用_配布.zip` | **`46_正典発行ガイド_発行担当者向け.md`** + `41_実機テスト手順` |
| **テスター** | PJメンバー | `MyBookshelf_配布.zip` | `00_はじめての方へ.md` + **`41_実機テスト依頼手順_同僚向け.md`** |
| **開発側リーダー** | あなた | （両方） | この文書 + `30_運用保守ガイド.md`（エラーコード表） |

> ### ⚠️ 配り間違いだけは絶対に避ける
> **`_発行者用` の付いたファイルをテスターに渡さないでください。** 受け取った人全員が部門の正典を上書きできます。
> ファイル名で見分けられるように、あえて名前を変えてあります。zip の名前も違います。
>
> 発行キー（合言葉）も、**発行担当の1名にだけ**個別に伝えてください（メールの本文に平文で書かず、口頭かチャットのDMが安全です）。

---

## 2. 事前にあなたが決めておくこと（テスト開始前）

- [ ] **共有フォルダのパスを1つ決める**（例: `\\ファイルサーバ\共有\NexusAgent\`）
      - 全部門ぶんを**1つの場所の下**にぶら下げます。部門ごとに分けてはいけません
      - **全員に読み書き両方**の権限が必要（読み取り専用では動きません）
      - テストだけなら「2台から見えるフォルダ」なら何でも可。1台完結なら `C:\Temp\NexusShare\` でも通ります
- [ ] **発行キー**を決めて、発行担当にだけ伝える
- [ ] **テスト用の正典に何を入れるか**を発行担当と決める
      - 部門で確定しているQ&Aを **20〜50件**あれば十分です
      - **原文マニュアルを丸ごと入れない**（理由は `46_` の §3）
- [ ] 参加者の PC が **Windows 版デスクトップ Excel** であることを確認（Mac・Excel Online・スマホは動きません）
- [ ] 参加者が **社内AIリボン（リボンちゃん）を自分で使える**ことを確認（これが無いと質問に答えられません）

---

## 3. 進行の順番（この順でないと詰まります）

```
【1日目・準備】
  ① あなた   : 共有フォルダを用意し、パスを全員に通知
  ② 発行担当 : Excel設定 → 発行者用ファイルを開く → 共有フォルダを設定
  ③ 発行担当 : 正典を1本発行する（テスト用でOK）
       ↓  ここまで終わってからテスターに配る
【2日目・テスト】
  ④ テスター : Excel設定 → 配布版を開く → 共有フォルダを設定
  ⑤ テスター : 部門の正典を受け取る → 質問してみる
  ⑥ テスター : 41_ の手順どおりに触り、気づいたことを報告
【3日目・更新テスト】
  ⑦ 発行担当 : 正典を1件足して「もう一度発行」
  ⑧ テスター : 開き直して「更新があります」が出るか、内容が入れ替わるか
  ⑨ 発行担当 : 「いいえ」で直前の版に戻す → テスターに戻ったか確認
```

### ⚠️ ③ を先にやる理由

**今回の配布物には、初期ナレッジ（最初から入っている資料）が入っていません。**
本棚が空の状態で配ると、テスターは開いた直後に質問できず、「壊れている」と感じます。

**先に発行担当が正典を1本出しておけば、テスターは開いて受け取るだけで質問できます。**
これが一番スムーズな導線です。

> `41_実機テスト依頼手順_同僚向け.md` の **§A-4** は「最初から入っている資料に質問する」と書かれています。
> 今回はそこを **「部門の正典を受け取ってから質問する」** に読み替えるよう、テスターに一言添えてください。
> （もしくは、テスター自身に手元のPDFを1つ取り込んでもらってから A-4 に進んでもらっても構いません。）

## 4. テスト当日の「まずここを見る」5点

テスターからの報告を待つ前に、あなた自身が最初に確認する項目です。ここが崩れていると、以降の報告が全部ノイズになります。

1. **起動するか**（コンテンツの有効化 → 数秒で画面が組み上がる）
2. **「❓ ガイド」→「🩺 診断を開く」がすべて ✅ か**（1つでも ⚠️ があれば、そこから潰す）
3. **質問して回答が返り、下に「出典」ボタンが出るか**（出典ゼロは過去に実害があった箇所）
4. **正典を受け取れるか**（Hub のお知らせ →「部門の公式ナレッジをまだ読み込んでいません」）
5. **閉じて開き直しても壊れないか**

---

## 5. 報告の受けかた

テスターには**この3行だけ**書いてもらいます。書式を統一すると、あとで並べ替えられます。

```
【何をしたか】 例：PDFを取り込んだあと「第3条の適用範囲は？」と質問した
【どうなったか】例：回答は出たが、下の「出典」ボタンが1つも出なかった
【どう思ったか】例：本当にその資料を見て答えたのか確認できず、不安に感じた
```

**「エラーが出た」より「エラーは出ないが期待と違った」の方が価値があります。**
このアプリで過去に見つかった不具合の大半は、**落ちずに静かに間違える**類でした。

### エラー報告が来たときのあなたの動き

1. 報告に `(コード: Exxxx)` があれば、`30_運用保守ガイド.md` §1 のエラーコード表を引く
   → 意味・よくある原因・対処が全部そこに書いてあります
2. コードが無ければ、`diag_report` シートのスクリーンショットを依頼
3. それでも分からなければ `err_log` シートを依頼（手順は `41_` の §4 に記載。手間がかかるので最後の手段）

---

## 6. 優先度のつけかた（受けた報告の仕分け）

| 優先 | 症状の型 | 例 |
|---|---|---|
| **即対応** | データが壊れる / 消える | 編集中のブックが勝手に閉じられた、取り込んだ資料が消えた |
| **即対応** | 誤った内容が配られる | 正典を戻したのに古い版のまま、違う部門の内容が混ざる |
| **高** | 落ちずに静かに間違える | 出典が1枚も出ない、部門名の表示が違う、打った文章が捨てられる |
| **中** | 止まる・固まる | 起動が30秒以上、終了が数十秒、取込が返ってこない |
| **低** | 見た目・文言 | 文字が重なる、言い回しが分かりにくい |
| **記録のみ** | 環境起因で回避不能 | 会社の方針でマクロ自体が禁止されている |

> **「これは不具合か分からない」も全部受けてください。** 判断はあなたがします。
> 「なんとなく使う気にならなかった」は、**最も価値が高く、最も報告されにくい**情報です。明示的に聞き出してください。

---

## 7. 既知の前提（テスターに先に伝えておくと事故が減る）

| 項目 | いまの状態 |
|---|---|
| 初期ナレッジ | **入っていません**（§3 参照） |
| AIへの接続 | 社内AIリボン経由。**リボンが使えないPCでは質問できません** |
| PDF の取り込み | **Word を使います。** Word を開いた状態にしておくと確実です。画像だけのPDF（スキャン）はそのままでは読めません |
| 起動のしかた | 同梱の **`MyBookshelfを起動.bat`** から開くのが安全（他のExcelを巻き込まないため） |
| 個人情報の自動チェック | **既定オフ**。発行前の確認は人の目で行ってください |
| 端末の所属チェック・知識の自動失効 | **既定オフ**（本格展開時に有効化を判断する項目） |
| 利用状況の送信 | **既定オン**。質問文は**先頭40字まで**しか送りません。テスターにこの事実を先に伝えてください |

---

## 8. テストが終わったら

- [ ] 報告を §6 の優先度で仕分けし、**即対応・高だけをまず直す**
- [ ] 直したら **同じテスターに同じ手順をもう一度**踏んでもらう（直した箇所の再現確認は本人が一番速い）
- [ ] 「記録のみ」の項目は、**閉じずに残す**。「たぶん大丈夫」で消さない
- [ ] 共有フォルダのテスト用データ（`channels\` 配下）は、本番前に整理する
