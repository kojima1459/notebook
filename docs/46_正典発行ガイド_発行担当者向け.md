# 正典（部門の公式ナレッジ）発行ガイド ― 発行担当者向け

> **この文書は誰向けか**: 部門の「正典」を発行する担当の方向けです。**エンジニアである必要はまったくありません。**
> **何ができるようになるか**: あなたの本棚に集めた資料を、ボタン1回で部門全員へ配れるようになります。間違えたら、同じボタンから数十秒で取り消せます。
> **所要時間**: 最初の準備 15分 → 2回目以降の発行は 3分

---

## 0. 最初に読む3行

1. **配るのはボタン1回**。保存先を選ぶ操作はありません（アプリが知っています）。
2. **間違えても戻せます**。前の版は自動で保存され、同じボタンから「いいえ」で戻せます。
3. **正典に原文マニュアルを丸ごと入れないでください**。ここだけが唯一の運用ルールです（理由は §3）。

---

## 1. あなたの役割 ―「正典発行者」とは

このツールには、性質の違う置き場所が3つあります。**あなたが担当するのは B だけ**です。

| | 何のため | 誰がやる |
|---|---|---|
| A. 本棚フォルダ | 自分の資料を自動で取り込む | 各利用者ひとりひとり |
| **B. 部門の公式ナレッジ（正典）** | **部門全員へ同じ内容を配る** | **← あなた** |
| C. 初期ナレッジ | 配布ファイルに最初から入れておく | 開発担当のみ |

### 「正典」とは何か

**部門の全員に、同じ答えを返してほしい内容**のことです。

- 〇 「経費精算の締切はいつ？」→ 部門で確定している答え
- 〇 よくある問い合わせと、確認済みの回答
- 〇 制度・ルールの要点
- ✕ 100ページの約款の全文
- ✕ 個人が参考にしているだけの資料

あなたが発行すると、**部門の全員が次にファイルを開いたときに自動で受け取ります**。
受け取る側は何の操作もしません。これがこのツールの一番の狙いです。

### あなたと利用者の違い

あなたが受け取るファイルは `MyBookshelf_発行者用.xlsm` です。
一般の利用者が受け取る `MyBookshelf.xlsm` とは、**「📤 正典を発行」ボタンが出るかどうか**だけが違います。

> **⚠️ 発行者用のファイルを、そのまま部門の人に配らないでください。**
> 受け取った人全員が正典を上書きできてしまいます。
> 利用者へ配るのは必ず `MyBookshelf.xlsm`（発行者用でない方）です。

---

## 2. 最初の準備（15分・最初の1回だけ）

### 2-1. 共有フォルダを決める

正典を置く場所を1つ決めます。**部門の全員が読み書きできる場所**である必要があります。

```
例) \\ファイルサーバ\共有\NexusAgent\
```

**決まりごと**

| 疑問 | 答え |
|---|---|
| 部門ごとに別々の場所に置いてもいい？ | **いけません。** 全部門の正典を「1つの場所の下」にぶら下げます |
| 発行側と受け取り側で別の場所を指定できる？ | **できません。** 同じ場所を指す必要があります |
| フォルダは手で作る？ | **不要です。** 自動で作られます |
| 必要な権限は？ | **全員に読み書き両方**。読み取り専用では動きません。あなたはさらにフォルダを作れる必要があります |

自動で、こういう形になります。

```
\\ファイルサーバ\共有\NexusAgent\
    channels\
        商品部\
            pack.xlsx           ← 正典の本体
            version.txt         ← 版番号
            publish_log.txt     ← 誰がいつ何件出したかの記録
            _archive\           ← 過去の版（戻すときに使う）
        人事部\
            ...
    thanks\      ← 「ありがとう」のやりとり
    insights\    ← 解決済みQ&A・みんなの困りごと
    telemetry\   ← 利用状況
```

### 2-2. アプリに共有フォルダを教える

1. `MyBookshelf_発行者用.xlsm` を開く
2. 右上の **❓ヘルプ** → **「⚙ P2P接続設定（共有フォルダ）」**
3. §2-1 で決めたパスを貼り付けて OK

**確認**: わざと存在しないパスを入れると「そのフォルダが見つかりませんでした」と出て、設定は変わりません。これが正しい動作です。

> **同じパスを、利用者全員にも設定してもらう必要があります。** 手順は同じです（❓ヘルプ →「⚙ P2P接続設定」）。テスト時は開発担当が案内します。

### 2-3. 発行キーを手元に控える

発行するたびに「発行キー（合言葉）」を聞かれます。**開発担当から別途お伝えします。**

> これはパスワードではなく、**誤操作を防ぐための関所**です。「押すつもりがなかったのに配ってしまった」を止めるためのものなので、複雑である必要はありません。
> ただし、**部門の人には教えないでください**（教えると、その人も一般配布版から…ではなく、発行者用ファイルさえあれば発行できてしまいます）。

---

## 3. 正典に何を入れるか ―【最重要】

### 唯一守っていただきたいルール

> ## 正典には「確認済みQ&A・要点」だけを入れる。原文マニュアルを丸ごと入れない。

**理由**（数字で説明します）

このツールは資料を細かく切って覚えます。その入れ物の上限が **1人あたり 20,000 個**です。

| 対象 | 1件あたり | 件数 | 使う量 |
|---|---|---|---|
| 部門の正典（Q&A形式） | 1〜2個 | 500件/部門 | 500〜1,000 |
| 6部門ぶんの合計 | | 3,000件 | 3,000〜6,000 |
| 個人が自分で入れる資料 | 140個/100ページ | 20冊 | 〜2,800 |
| **合計** | | | **6,000〜9,000** |

上限 20,000 に対して十分な余裕があります。**この試算が成り立つ条件はただ1つ**、正典を Q&A に絞ることです。

100ページの約款を丸ごと入れると、**1部門だけで数千個**を食います。6部門が同じことをすると上限を超え、**部門全員のツールが使えなくなります**。

原文が必要な人は、**その人が自分の本棚に個別に入れます**。正典は「答え」だけを持ちます。

### 部門名の決めかた

- **実在する部門の名前をそのまま**使ってください（例: `商品部` `システム部` `人事部` `法務部`）
- **「全社共通」は作らないでください。** 定義できる人も管理する部署も決まらないため、必ず運用が破綻します
- 更新するときは、**前と同じ名前**を入れてください（違う名前を入れると別の部門として新しく作られます）
- `/` `\` `:` `*` `?` `"` `<` `>` `|` は使えません。入れると発行前に止めてくれます

### 個人情報について

**⚠️ 正典に個人情報を入れないでください。**

自動チェックの機能はありますが、**現在は既定でオフです**（`config` の `pii_scan_enabled`）。
発行の確認画面には、現在の状態が正直に表示されます。

- オンのとき: `・個人情報が見つかった場合は自動で中止します`
- **オフのとき: `・(個人情報の自動チェックは現在オフです)`** ← いまはこちら

> **なぜオフなのか**: このチェックは「メールアドレスの形」か「10桁以上の数字の並び」を見ています。氏名は見ていません。そのため**部品番号・条番号・フリーダイヤルが誤検知**され、正しい資料の発行まで止まってしまう事故がありました。オンにするかどうかは開発担当と相談してください。
>
> **いずれにせよ、最後は人の目です。** 発行前に「この内容が部門の全員に見えても問題ないか」を必ず自分で確認してください。

## 4. 発行のしかた（3分）

### 手順

**① 配りたい内容を、自分の本棚に入れる**

「📁 資料を入れる」から、正典にしたい資料を取り込みます。
すでに入っている資料も対象になります。

**② 「ナレッジ」画面を開き、「📤 正典を発行」を押す**

> このボタンは発行者用のファイルにしか出ません。出ていない場合は、一般配布版を開いています。

**③ 部門名を入れる**

説明が出ます。読んだら部門名（例: `商品部`）を入れて OK。

**④ 発行キーを入れる**

§2-3 で控えた合言葉を入れます。違うと「発行キーが違います。発行は行いませんでした」と出て、何も起きません。

**⑤ 確認画面を読む** ←【ここが本番です】

```
【商品部】として発行します。

  発行する件数: 240 チャンク(自分で入れた資料のみ)
  配置先: \\ファイルサーバ\共有\NexusAgent\channels\商品部\pack.xlsx

【発行前の確認】
  ・正典には『確認済みQ&A・要点』を入れてください
  ・(個人情報の自動チェックは現在オフです)

【この部門の発行履歴】
  ...

このまま発行しますか?
(「いいえ」= 直前の版に戻す操作に進みます)
```

**必ず確認すること**

- [ ] 部門名は合っているか
- [ ] **件数が想定どおりか**（極端に多いときは、原文を丸ごと入れてしまっている可能性）
- [ ] 配置先のパスが合っているか

> **件数は「自分で入れた資料のみ」です。** 他部門から受け取った正典は含まれません（他部門のものを自部門の名前で再配布しないため）。そのため、**本棚の総数より小さい数字が出るのが正常**です。

**⑥ 「はい」で発行**

数十秒待つと完了します。

```
発行しました。

  部門: 商品部
  件数: 240 チャンク
  版: 2026-09-01-1

部内の全員が、次にファイルを開いたときに受け取れます。
内容に誤りが見つかったら、この画面から「いいえ」で戻せます。
```

### 裏で何が起きているか（読まなくても使えます）

1. 今の内容を、**自分のPCの一時フォルダ**に書き出す（共有フォルダに「書きかけのファイル」が見えている時間を最短にするため）
2. 共有フォルダの**今の版を `_archive` へ退避**する（戻せるようにするため）
3. 新しい `pack.xlsx` を置く
4. **最後に** `version.txt` を書く

4 が最後なのが大事です。逆だと「版番号は新しいのに中身が古い」を掴む人が出ます。

---

## 5. 間違えたときの戻しかた ―【これが一番大事】

**誤った正典が配られ続ける事故を、あなたが1人で・数十秒で止められます。**
承認フローも、開発担当への連絡も要りません。まず止めてください。

### 手順

1. **「📤 正典を発行」をもう一度押す**
2. 同じ部門名を入れる
3. 発行キーを入れる
4. 確認画面で **「いいえ」** を選ぶ ← ここです
5. 戻す版が表示されるので OK

```
戻しました。全員に自動で配信されます。
```

部内の全員が、次にファイルを開いたときに**自動で前の版に戻ります**。
誤った内容は各PCから消えます。

### ⚠️ 戻せるのは「1つ前」までです

一度巻き戻した直後に、もう一度巻き戻そうとすると警告が出ます。

```
【商品部】は直前に巻き戻しを実行済みです。
ここでもう一度戻すと、取り下げたはずの版が全員へ配られます。
```

**戻すボタンは「行ったり来たり」します。** 2回押すと、取り下げたはずの誤った版が復活します。
さらに前の状態にしたい場合は、**正しい資料を用意して発行し直してください**（戻すのではなく、進んで直します）。

### 「前の版に戻せません」と出たとき

退避に失敗しているときに出ます。**そのまま進めると戻せなくなります。**
急ぎでなければ、いったん中止して開発担当へ連絡してください。

---

## 6. 更新のしかた

初回とまったく同じです。**前と同じ部門名**を入れて発行するだけ。

利用者側では、次にファイルを開いたとき Hub のお知らせに
**「【商品部】に更新があります」** と出ます。押すと最新版に入れ替わります。

> **古い内容と新しい内容が混ざることはありません。** 版が変われば必ず丸ごと置き換わります。

### 更新の頻度について

**毎日出す必要はありません。** 版が変わると全員がダウンロードするため、頻繁すぎると共有フォルダの負荷になります。
**週1回程度、まとめて**が現実的です。急ぎの訂正だけ随時、が良いバランスです。

---

## 7. 容量の見張り

「ナレッジ」画面に **「本棚の使用量: 36%」** のように出ます。

| 使用量 | 状態 |
|---|---|
| 〜79% | 問題なし |
| **80%以上** | **警告が出ます。** 正典に原文を入れていないか見直してください |

**勝手に消える仕組みはありません。** 警告が出たら、あなた（と各利用者）が判断して減らします。

---

## 8. 発行の記録

`channels\<部門名>\publish_log.txt` に、**日時・発行者・件数・版番号**が追記されていきます。
直近の履歴は発行の確認画面にも表示されます。

「誰がいつ何を出したか」は常に追えます。**責任の所在が曖昧にならないための仕組み**であって、あなたを監視するものではありません。

---

## 9. 2人が同時に発行したら

同じ部門を2人が同時に発行しようとすると、後から押した方に出ます。

```
いま別の方が【商品部】を発行中です。
  発行を始めた方: 〇〇
今回は発行しませんでした。数分おいてもう一度お試しください。
```

**数分待ってからもう一度**押してください。データは壊れていません。

---

## 10. やってはいけないこと

| やってはいけないこと | 何が起きるか |
|---|---|
| **発行者用ファイルを部門の人に配る** | 受け取った全員が正典を上書きできてしまう |
| **発行キーを部門の人に教える** | 同上 |
| 正典に原文マニュアルを丸ごと入れる | 上限を食いつぶし、**部門全員のツールが使えなくなる** |
| 「全社共通」チャンネルを作る | 管理する人が決まらず必ず破綻する |
| 共有フォルダの `pack.xlsx` を手で開いて編集する | 版番号と中身が食い違う。必ずアプリから発行する |
| `_archive` フォルダを手で消す | 戻せなくなる |
| 巻き戻しを2回続けて押す | 取り下げたはずの誤った版が復活する |
| 部門ごとに別々の共有フォルダを使う | 利用者側が見つけられない（設定は1つだけ） |

## 11. 困ったときの早見表

| 症状 | 考えられること・対処 |
|---|---|
| 「📤 正典を発行」ボタンが出ない | 一般配布版を開いている。`MyBookshelf_発行者用.xlsm` を開く |
| 「発行キーが違います」 | 全角/半角、前後の空白を確認。分からなければ開発担当へ |
| 「共有フォルダが未設定か、接続できません」 | ❓ヘルプ →「⚙ P2P接続設定」でパスを確認。VPN 接続も確認 |
| 「発行できませんでした」＋権限の案内 | 共有フォルダへの**書き込み**権限が無い。IT 部門へ依頼 |
| 件数が想定よりずっと多い | 原文を丸ごと取り込んでいる可能性。§3 を確認 |
| 件数が本棚の総数より少ない | **正常です。** 「自分で入れた資料のみ」が対象 |
| 発行したのに利用者に届かない | ①利用者側の共有フォルダ設定が同じパスか ②利用者がファイルを開き直したか |
| 利用者に違う部門名で通知が出る | **不具合です。開発担当へ報告してください** |
| 起動・終了が異常に遅い | 共有フォルダに到達できていない可能性。パスと VPN を確認 |

## 12. 開発担当への連絡のしかた

**判断はこちらでします。「不具合か分からない」まま送ってください。**

```
【何をしたか】 例：商品部で2回目の発行をした
【どうなったか】例：発行は成功したが、利用者側に「人事部に更新があります」と出た
【どう思ったか】例：部門名が違うので、間違ったものを配ったのではと不安になった
```

**画面のスクリーンショット**があると非常に助かります。

エラーが出た場合は、「ホーム」タブ右上の **「🩺 診断」** を押して、
出てきた `diag_report` シートをそのままスクリーンショットして送ってください。

---

## 付録：この文書に書いていない設定について

以下は**現時点では既定でオフ**です。本格展開の前に、開発担当と組織で判断する項目です。
（テストフライトの段階では、オフのまま触っていただいて構いません。）

| 設定 | 既定 | 何をするもの |
|---|---|---|
| `pii_scan_enabled` | **オフ** | 発行前に個人情報らしき文字列を探し、1件でもあれば発行を中止する。誤検知の実害があるため既定オフ |
| `allowed_domain` | **空（チェックしない）** | 許可した Windows ドメイン以外の端末では知識を表示しない（PC 紛失対策） |
| `knowledge_expire_days` | **0（無効）** | 共有フォルダに最後に到達できた日から N 日で知識を自動消去する。本格展開時に 30 以上を設定する |
| `admin_users` | **空** | 「📊 利用状況」を見られる管理者。空のあいだは発行担当者へ暫定的に開放される |
