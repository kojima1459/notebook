## パターン1：1台で完結するテストだけをお願いする場合（推奨・まずはこちら）

**件名**: 【お願い】Excel版 社内AI「Nexus Agent」実機テストのご協力（30分程度）

```
【お名前】さん

お疲れさまです。【自分の名前】です。

以前ご相談していたExcel版の社内AI検索ツール（Nexus Agent）ですが、
外部レビューで見つかった不具合の修正が一通り終わりました。

つきましては、実際のPCで触っていただく確認をお願いできないでしょうか。
所要は30分程度、手順書のとおりに触っていただくだけで大丈夫です。


■ お願いしたいこと（ここが本題です）

「エラーが出たら教えてください」ではありません。

  ・エラーは出ないが、期待と違った
  ・押しても何も起こらなかった
  ・これで合っているのか分からなかった
  ・なんとなく使う気にならなかった

こういう報告が一番ありがたいです。

今回の修正で直したものの多くは、
「落ちないけれど静かに間違っている」類の不具合でした。

  例：回答は返るのに、根拠の資料へのリンクが1つも出ていなかった
  例：部門を切り替えても、前の部門の資料が残ったままだった
  例：聞き返しへの返信に数字が入っていると、打った文章が捨てられていた

いずれも画面上はエラーが出ないため、
実際に触った方が「あれ？」と思わない限り、誰も気づけません。

直し方を考えていただく必要は一切ありません。
「何をしたら、どうなって、どう感じたか」の3つだけ教えてください。


■ 用意していただくもの

  ・Windows版のExcel（デスクトップ版）
    ※Mac・Excel Online・スマホでは動きません
  ・リボンちゃん（社内AI）が使える状態
  ・Word（PDFの読み取りに使います）
  ・お手元のPDFを1つ、Excelファイルを1つ
    （Excelは #N/A などのエラー表示が入っているものが理想です）


■ 最初に1回だけ必要な設定

Excelの
  [ファイル]→[オプション]→[トラストセンター]→[トラストセンターの設定]→[マクロの設定]
で
  「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」
にチェックを入れて、Excelを再起動してください。

このアプリは開くたびに自分自身へプログラムを組み込む方式のため、
この設定が無いと起動しません。

もしチェックがグレーアウトして押せない場合は、
会社の方針で禁止されている可能性があります。
その場合は、そこで止めてご連絡ください。
（それ自体が最重要の確認事項です。配布方式を見直す判断材料になります）


■ 添付・格納場所

  ・アプリ本体：【添付 または 置き場所のパス】
  ・手順書：docs/41_実機テスト依頼手順_同僚向け.md
    → 「パターンA」の部分だけで結構です

手順書はチェックリスト形式にしてあります。
上から順に触っていただき、気になったところに印を付けていただければ十分です。


■ 報告のしかた

このメールへの返信で構いません。形式も自由です。

  【何をしたか】 例：PDFを取り込んで「第3条の適用範囲は？」と質問した
  【どうなったか】例：回答は出たが、下の「出典」ボタンが1つも出なかった
  【どう思ったか】例：本当に資料を見て答えたのか確認できず、不安に感じた

画面のスクリーンショットがあると非常に助かります。

「不具合かどうか分からない」ものも、分からないまま送ってください。
判断はこちらでします。


■ 期限

【MM月DD日】までにいただけると助かります。
難しい場合はご相談ください。


お忙しいところ恐れ入りますが、よろしくお願いいたします。

【自分の名前】
```

## パターン2：2台使う部門配信テストまでお願いする場合

**件名**: 【お願い】Excel版 社内AI「Nexus Agent」実機テストのご協力（50分程度・2台使用）

パターン1の本文に、以下を「■ 用意していただくもの」の後に差し込んでください。

```
■ 部門配信のテストについて（追加で20分ほど）

このツールの中心機能は
「部門が資料を1回登録すると、全員の手元へ自動で届く」
という配信の仕組みです。ここも確認していただけると大変助かります。

必要なのは「2台のPCから読み書きできるフォルダ」が1つだけです。
専用の共有サーバは不要で、テストだけなら
【共有フォルダのパス（例：\\サーバ名\共有\NexusTest\）】
をお使いください。

  ※1台のPCだけで試すことも可能です。
    その場合は C:\Temp\NexusShare\ のようなローカルフォルダで通せます。

なお、部門ごとに別々の場所へ置くことはできません。
全部門の資料が1つの場所の下にぶら下がる構造で、
各PCはその1か所だけを見に行きます。
（フォルダは自動で作られますので、手で作っていただく必要はありません）

配信テスト用に、発行者用のファイルも別途お送りします。
  ・一般配布版：MyBookshelf.xlsm       … 発行ボタンが出ません
  ・発行者用　：MyBookshelf_発行者用.xlsm … 発行ボタンが出ます
この2つが見た目で区別できるよう、ファイル名を分けています。

手順書は「パターンB」の部分です。

特に見ていただきたいのは、更新配信のところです。

  1. 発行側で資料を足して、もう一度発行する
  2. 受け取り側を開き直す
  3. 「更新があります」を押す

このとき
  ・表示される部門名が正しいか
  ・押したあとに、お知らせがちゃんと消えるか
  ・古い内容と新しい内容が混ざっていないか

を見てください。ここは直前まで正しく動いていなかった箇所で、
今回の修正の中でも最も影響が大きいところです。
```

## 補足：なぜ「バグを探して」と書かないか

前回、テストをお願いした際に「すごいですね」で止まってしまったのは、
**何を報告すればいいのか分からなかった**ためだと考えられます。

「バグを探してください」は、相手に
「バグとは何か」「どこまでが仕様か」の判断を丸投げしています。
エンジニアでない方には答えようがありません。

そこで本文では

  ・**判断を求めない**（「どう感じたか」だけ聞く）
  ・**何が起きうるかを具体例で先に見せる**（出典が出ない等）
  ・**分からないまま送ってよい**と明示する

の3点を意識しています。手順書側も同じ方針でチェックリスト化してあります。
