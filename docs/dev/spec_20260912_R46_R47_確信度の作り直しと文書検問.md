## §0. このラウンドの起点

R45 まで検問全緑・実機受入待ちだった状態に対し、利用者から実機報告が届いた。
報告は11件。うち P0（取込中に最小化すると復旧不能）だけが**他の項目のテスト

> 今って人間が細かく実機テストしてエラー発見→また修正→テストのループで修正

## §1. P0 — 取込中に最小化すると PC 再起動しか手が無くなる

### 事実
`user32.DisableProcessWindowsGhosting`（`modWorkExcel.bas`）を、実況の1行を出す
たびに通るチョークポイント（`modLive.PaintStage`）から呼んでいた。
config `freeze_keep_banner` の既定が on だったため、実質すべてのセッションで
ゴースト化抑止が効いていた（**呼ぶとプロセス終了まで解除できない**）。

ゴーストウィンドウは OS が無応答アプリへ用意した**唯一の復旧経路**で、
タスクバーからの復元・右クリック→閉じる・タスクの終了はすべてそこを通る。
抑止すると3つが同時に死ぬ。

**設定の説明文には「移動・最小化・×が効かなくなる」までは書いてあった。**
書かれていなかったのは、逃げ道として案内していた「強制終了はタスクマネー
ジャーから」も同時に塞がること。既知の代償のつもりで、実は代償の大きさを
測り違えていた。

### 裁定
`freeze_keep_banner` の既定を **False** へ。VBA 側の `GetBool` 第2引数（config に
キーが無いときの値）も False にする（True のままだと旧 config で抑止が復活する）。
あわせて `optGsTxt` の `Application.Wait`（Ghostscript の完了待ち・最悪20分）を
`Timer`+`DoEvents` へ。`Application.Wait` は Excel の活動を全部止めるため、
その間ウィンドウがメッセージを一切処理できない。

**バナーの見た目より復旧手段を優先する。**

## §2. R46 A-4 — 確信度バッジを検索スコアから切り離す

### 事実
旧 `modAsk.LastConfidence` は**しきい値1本**しか持っていなかった。
上位ヒットのうち `score >= confidence_score_x100/100`（=0.55）が2件以上なら🟢、
1件なら🟡、0件なら🔴。3値に見えて実際に分けているのは「0.55 を超えた件数」
だけで、似た文書はまとまって上位に来るため「ちょうど1件」はほとんど起きない
＝**実質2値**。実機報告「△マークはでない」はこの構造の帰結。

さらに 0.55 は**埋め込みの絶対スケールに依存する数字**で、固有名詞が一致する
だけで超える。実機報告「MSAD、三井住友の株価は？って聞いたら緑の〇印が出た、
もちろんそんな資料は入れてない」は、主語（三井住友）だけで 0.55 を超え、
述語（株価）が本棚に無いことを一度も見ていなかったため。

### 裁定（案 (c) 根治・利用者承認済み）
確信度を検索スコアから分離し、**スケール非依存の比だけ**で決める。
埋め込みが変わっても意味が変わらないので、実機での再校正に依存しない
（旧実装が壊れた理由そのものを設計から外す）。

- **coverage** … 質問から抜いた「効く語」のうち採用チャンクに実在する割合
- **flatness** … 1位スコア ÷ 上位の平均

### 実測（2026-09-11・教えてBOX 10,996かけら）
「火災保険(法人)」440かけらを本棚から丸ごと抜き、**その分野の実際の質問87件**を
投げる＝「いかにも社内資料にありそうで、実は入っていない」という実務で一番
危ない形で測った（単なる off-topic では簡単すぎて意味が無い）。

| | coverage 中央 | flatness 中央 |
|---|---|---|
| 答えがある（n=362） | 1.000 | 1.801 |
| 答えが無い（n=87） | 0.750 | 1.170 |

採用（🟢= cov≥1.0 かつ flat≥1.6 ／ 🟡= cov≥0.9）での出方:

| | 🟢 | 🟡 | 🔴 |
|---|---|---|---|
| 答えがある | 69.6% | 29.0% | 1.4% |
| 答えが無い | 5.7% | 12.6% | 81.6% |

個別確認: 「MSAD、三井住友の株価は？」cov=0.33 flat=1.05 → 🔴 ／
「今日の食堂のメニューは？」cov=0.67 → 🔴。

**margin（1位÷2位）は採用しない。** 測ったら flatness と相関していて分離に
寄与しなかった。**効かない設定を残さない**（同じ理由で R46 は部門設定も落とした）。

### 出典表示をバッジに繋ぐ
実機報告「十分な根拠なしのバッジでも出典が表示される、まぎらわしい」。
バッジと出典が別々の判断で動いていた。🔴 のときは**消さずに呼び名を変える** ――
消すと確かめる手段まで奪うが、「出典」と呼ぶと根拠として通用してしまう。

## §3. R47 — 回答本文の数字が資料に実在するか（modGround 新設）

### なぜ
R46 のバッジが測っているのは「検索が材料を取れたか」までで、**AIがその材料
どおりに書いたか**は一度も見ていない。損保の実務では営業がその数字をそのまま
客へ伝える。1桁違えば事故になる。ここは「回答が上手いか」ではなく**誠実か**の
問題なので、点数ではなく事実で守る。

### 実測（本番と同じ条件）
質問250件について「検索の上位5件だけを根拠に、その質問の正解回答を照合」:

- 「資料に無い数字がある」と出た回答 **13件（5.2%）** ―― 中身は 080101 / 第8条 /
  証券番号など、**上位5件に本当に入っていない値**。本番では AI もその5件しか
  見ないので、書いたとすれば補ったことになる＝指摘として正しい
- 実在しない金額を1つ混ぜると **250/250（100%）** 検出

### バッジは下げない（設計判断）
「検索が材料を取れたか」と「AIが材料どおり書いたか」は別の事実なので、
1つの点数に混ぜない。混ぜると R44 で潰した「性質の違う信号を足して絶対値の
しきい値と比べる」のと同じ構造の誤りになる。注記として別に出す。

## §4. R47 の本体 — 「作ったのに繋いでいない」を機械で止める

### この型の実例（このラウンド中に自分でもやった）
R46 で `modAsk` へ「nHits=0 の回にも常設ガードを付ける」という `Else` を足したが、
**二重に誤りだった**:

1. **到達不能だった。** `ok = True` が立つのは `nHits > 0` の枝の内側だけなので、
   `If ok Then` の内側に置いた `Else` は一度も実行されない
2. **前提も違った。** `nHits=0` の枝は LLM を一度も呼ばず、
   `modClarify.MissingDocGuide` の**自前の定型文**を返す。AI の回答でないものに
   「※ AIが資料から作った回答です」を付けるのはそれ自体が嘘

**実装した本人が、コミットメッセージに「直した」と書いた状態で気付いていない。**
人の注意力では止まらない型である証拠として記録する。

### 新設した検査

| 検査 | 何を止めるか |
|---|---|
| `vba_lint check_orphan_public` | 呼び出しが1件も無い Public を ERROR。OnAction / OnTime / `Application.Run` の宛先、build/tools/docs の文字列、`@unused:理由` は救済 |
| `vba_lint check_emoji_vs16` | 既定がテキスト字形の絵文字（`Emoji_Presentation=No`）の FE0F 無し直書きを ERROR |
| `tools/doc_gate.py`（新設） | ①文書の「既定N」vs `build_config_rows` ②CLAUDE.md の容量台帳 vs 実測 ③`src` が吐く E**** ⊆ FriendlyMessage ⊆ 運用ガイド ④配布文書が現行UIに無いボタン名を説明していないか |

### 絵文字の単一情報源（modEmj 新設）
R46 の実機報告「削除ボタンの絵文字が出ない」の原因は幅でも CP932 でもなく、
**異体字セレクタ U+FE0F の付け忘れ**だった。そして R46 の修正は 🗑 を2箇所
直しただけで、同じ文字の残り6箇所と ⚠（20箇所中15箇所）・🖼・⚙・☀・◀▶ を
取りこぼしていた。

**R46 のコミットには「⚠ には全箇所で FE0F を付けている」と書いたが、それは
事実ではなかった（実測 20箇所中5箇所）。誤った記述だったのでここで訂正する。**

呼び出し側で `ChrW` を並べる限り同じ取りこぼしが続くので、文字ごとに名前を
付けて `modEmj` へ集約した。副次効果として**呼び出しの字数が減る**ため、
残り10字の `modUIShelf` のようなモジュールへも容量を増やさずに FE0F を入れられる。

## §5. 文書検問が見つけたもの（100件 → 0件）

新設した `doc_gate.py` の初回実行で **ERROR 100件**。内訳:

- 配布zip に同梱する利用者向け文書が、**存在しない画面**を説明していた
  （「マイ本棚」タブ・「ホーム」タブ・🩺 診断・🟢 解決した! など計60箇所）
- CLAUDE.md の容量台帳が実測とズレていた（14箇所。**同じ段落が同じモジュールに
  ついて2つの違う数字を書いていた**）
- config の既定値の嘘 11箇所（`vision_pdf_max_pages` 100→実際300、
  `knowledge_expire_days` 30→実際0 ほか）
- `E0906` を `src` が吐くのに `FriendlyMessage` に分岐が無く、汎用文だけが出ていた

**これが「実機テストのループが終わらない」の上流だった。** テスターが読む手順書が
古いと、報告に「本当のバグ」と「文書が古いだけ」が混ざる。司令塔はそれを毎回
人力で切り分け、後者を「修正」として実装ラウンドへ投入してしまう。
**バグが多いのではなく、バグでないものがバグとして入ってくる。**

### 検査自身の誤検知も直した（2件）
- 正しい呼び名「🩺 診断を開く」を、禁止語「🩺 診断」の部分一致で赤くしていた
- 1行に複数キーが並ぶ表で、全キー×全数値を総当たりしていた

**検査が正しい書き方を叱ると、書き手は検査を無視するようになる。**
誤検知を残した検査は、無い検査より悪い。

### 検査の適用範囲
`docs/dev/spec_*` / `audit_*` / 日付つきの記録文書は**対象外**。
裁定書は「そのとき何を何へ変えたか」の記録で、旧値が書いてあるのが正しい。
そこを赤くすると、書き手は歴史を書き換えるか検査を無視するかを選ぶことになる。

## §6. プロセスの裁定（憲章へ追加する）

1. **裁定書の無いラウンドはクローズできない。** R46 がそうなった。
2. **裁定書の「文言を更新」項目には、更新後の逐語か、保持すべき条件の列挙を
   必ず書く。** R13-5 は 5c に条件を4つ持っていたのに、5d の「文言を新しい
   役割定義に合わせて更新」がそれを1行へ潰し、**裁定書自身が誤伝の発生点**に
   なった（実機で「直前までに使った資料しか見ないの?」という疑義を生んだ）。
3. **`final-gates` に `doc_gate.py` を入れる。** コードだけ守って文書を守らない
   検問は、外へ出る言葉を守れない。
