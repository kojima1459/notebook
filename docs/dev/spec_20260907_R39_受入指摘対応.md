## §1 F001 の設計（Sonnet）

- **コマンド**: `optOcrCore.BuildGsTextCommand` の `-sOutputFile=` を **ページごとの別ファイル**にする: `<folder>\gstext_%04d.txt`（`%04d` は GS がページ番号で置換。1始まり）。それ以外の引数は不変。
- **読み取り**: `optGsTxt.ExtractPdfTextNoOcr` の `txt = ReadUtf8Text(outTxt, …)` を、`ReadPageFilesJoined(folderPath, totalPages)` に置換。N = max(`totalPages`（gs_out.log の "Processing pages 1 through N"）, 実在する `gstext_%04d.txt` の最大番号)。i=1..N を順に読み、**無いページ・空ページは空文字**として、`page1 & Chr$(12) & page2 & Chr$(12) & … & pageN & Chr$(12)`（各ページ末尾に改ページ）で連結する。以降の `GsPageBounds`／`BuildPagesFromGsText`／`GsPageCount`／`GsTextVerdict` は**不変**（`pages(i).page = firstIdx + i + 1` で物理ページになる）。
- **進捗監視** `WaitGsTextDone`: `FileSizeOf(outTxt, …)` を「存在する最大番号の `gstext_%04d.txt` のサイズ」に置き換える（log の "Page N" 進捗はそのまま）。1ページが重い PDF でも無進捗と誤判定しないため。
- **後始末** `CleanupTxtFolder`: `Kill outTxt` に加えて `Kill folderPath & "\gstext_*.txt"`（On Error Resume Next の中）。
- **診断** `GsFailureDetail`／`ReadTextTail(outTxt)` は、outTxt が無ければ最大番号のページファイルを読む（無ければ従来どおり空）。
- **純関数（Pure44 で固定）**: `optOcrCore.PageTxtName(folderPath, i)`（`\gstext_0001.txt` 形式・4桁ゼロ埋め・10000 以上はそのまま桁数増）／`optOcrCore.JoinPageTexts(parts() As String, n)`（各要素の末尾に Chr$(12)。n=0 は空）／`JoinPageTexts` の結果を `modUtilText.GsPageBounds` に通すと keptN=n（空ページ混在で先頭・末尾の空を落とし、中間の空は残す）／`BuildGsTextCommand` に `%04d` が含まれ `gstext.txt` が含まれない。
- **max_pages_per_file**: 従来どおり連結後に `BuildPagesFromGsText` が打ち切る（GS の `-dLastPage` は使わない＝`sparse/image` の判定に総ページが要る）。
- 変更ファイル: `src/opt/optOcrCore.bas`（残 5,369）・`src/opt/optGsTxt.bas`（残 2,004。**逼迫**: 実体は optOcrCore 側へ置き、optGsTxt は呼び出し行の差し替えに留める）・`src/test/modTestsPure44.bas`（新規）・`modTestRunner`・`build/modules.json`・`tools/run_lo_tests.py` の注入一覧・`vba_lint.py` CONTRACT（optOcrCore が載っていれば）。
- **確認できないこと**: この環境に Ghostscript が無い（`dist/Ghostscript` は Windows DLL）。GS が空白ページにも空ファイルを作るか／`%04d` の挙動は**実Excel＋同梱 GS でしか確認できない**。§4 の再試験で確かめる。

## §2 F002〜F006・C001（Fable のマイクロ修正）

- F002: `modShelf.IngestFile` の `hashHex = Fnv1a64Hex(NormalizeForHash(bodyText))` を `…(chunks(ci).full_text)`（見出しを付ける**前**）に。保存する本文（bodyText）は不変。**過去に取り込んだ行のハッシュは旧基準のまま**なので、既存の別名重複は消えず、新規取込から効く（記録）。パック取込の重複判定は行に保存されたハッシュ同士の照合なので、出力側が新基準で出せば揃う。
- F003: `modTestsPure8.TestTruncateAndRenorm` の `Dim v1(0 To 4)` を `Dim v1() As Double: ReDim v1(0 To 4)` に（他の固定長があれば同様）。CLAUDE.md §10 に「配列を丸ごと代入（`vec = cut`）する関数へ固定長配列を渡すと、LO は通り実Excel は Err 13」。
- F004: `modTestsExcel.TEST_QUERY` を「ゾウガメ工房の年次点検はいつ実施しますか」に（11字超・資料と目的が明確）。
- F006: `build_mybookshelf.py` の zip 同梱 docs に `10_使い方ガイド.md` と `44_P2P実機テスト手順.md` を追加。README の一覧にも2行。
- C001: README（build スクリプト内の文面）に「起動 bat は1台のPCにつき1系統だけ使う（複数の配布フォルダから同じPCで起動しない）」を1行。

## §4 再試験（実Excel・髙橋さんの環境で可能）

1. `five_pages.pdf`（5物理ページ）: page 列が 1〜5、`max_pages_per_file=2` で 2 ページまで＋`partial`。
2. 表紙が画像＋本文文字の PDF: 表紙は空ページとして残り、本文は p.2 から。
3. 途中に空白ページがある PDF: 番号が飛ばない。
4. 同じ中身を別名で取込 → チャンク数不変。E2E の重複テストが PASS。
5. 純ロジック `TestTruncateAndRenorm` が実Excel で PASS。E2E 16/16。
6. zip の docs に 10 と 44 がある。
7. **完了フラグの中身**（レビュー M1）: PDF を1本取り込んだ直後に `%TEMP%\nxocr_*\done.flag` を開き、中身が `0`（成功）か `1`/`255`（失敗）の数字であること。数字でなければ cmd の `%` 展開が想定と違う＝err_log の `rc=` が常に `?` になる（取込結果は壊れない）。
8. **GS の出力ファイル**: 同じフォルダに `gstext_0001.txt` … が物理ページ数ぶんある（空白ページは空ファイル）。無い番号があるなら「空白ページに空ファイルを作らない GS」＝番号は `Processing pages 1 through N` で補うので結果は同じ。
