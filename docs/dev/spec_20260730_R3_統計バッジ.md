# 要件定義 R3: Hub統計の空表示とバッジ授与の一貫性（実装: Sonnet / 起草: Fable 司令塔）

## 背景（コードで確定した事実）

1. `modBoot.Boot()` の実行順: Hub描画(`modHub.EnsureHubLayout`, modBoot.bas:229) が
   `modStats.TouchToday`(250) / `modStats.EvaluateBadges`(254) / `modBoard.BootBoard`
   (LaunchNexus内=さらに後) より**先**。そのため初回描画の Hub は
   「連続ログイン」「節約できた時間」「みんな(今日/今月)」が更新前の値で固まる。
   Hub は明示的に再描画されるまでそのまま。
2. バッジの付与は `modStats.EvaluateBadges` が唯一の入口（`CheckBadge` はPrivate）。
   呼び出しは modBoot:254 / modUIMain:601 / modUIShelf:478 / modApp:347 の4箇所のみ。
   `modShelf.IngestFile` は `ingest_files_total` を加算するが EvaluateBadges を呼ばない。
   スクショ取込(modUIShelf.OnIngestScreenshot:368)は直後に呼ぶ、
   ナレッジ登録(modVault.OnVaultSubmit→RegisterKnowledgeText)は**どこも呼ばない**
   —— これが「ナレッジ登録ではバッジが出ず、スクショ取込では出る」の正体。
3. 「はじめの一歩」相当のウェルカムバッジはカタログに存在しない
   （利用者は初回の名前入力でバッジが出ることを期待している）。
4. 実機写真では4タイル(節約できた時間/みんな今日/みんな今月/連続ログイン)が
   ラベルのみで値が空。静的解析では空文字を返す経路を特定できなかったため、
   観測手段も入れる（下記E）。

## 変更要件

### A. 起動順序の是正（modBoot.bas）
- `modStats.TouchToday` と `modStats.EvaluateBadges` を、
  `modUIMain.EnsureLayout` / `modHub.EnsureHubLayout` **より前**に移動する。
  既存の bootStage 文字列・エラーハンドリング作法(On Error Resume Next +
  LogBootStageErrorIfAny)は維持。
- 移動により初回描画時点で streak_days とバッジが最新になる。

### B. IngestFile を単一のバッジ評価点にする（modShelf.bas）
- `modShelf.IngestFile` の stats 加算箇所（isSelf かつ done/partial のブロック、
  modShelf.bas:370-379 付近）の直後に `modStats.EvaluateBadges` を On Error 保護
  付きで呼ぶ。これで取込の全入口（ダイアログ/同期/ナレッジ登録/スクショ/チャット）
  が同じ評価を通る。
- 既存の RefreshBadgesAndDashboard 呼び出しは冪等なので削除しない。
- 注意: フォルダ同期の大量取込中に MsgBox が出るのは「新規獲得の瞬間」だけ
  （CheckBadge は取得済みなら即Exit）なので許容する。silent 同期でどうしても
  避けたい場合でも、本タスクでは挙動を変えない（変えるなら理由を報告書へ）。

### C. ウェルカムバッジの追加（modStats.bas）
- バッジID `welcome`、表示名は「はじめの一歩(名前を登録した)」程度の日本語。
  条件: `LenB(modConfig.GetString("pack_author", "")) > 0`。
- `EvaluateBadges` の先頭に追加し、`BadgeCatalog`（単一情報源）にも追加する。
  BadgeCatalog を参照する表示(modHub.DrawBadges / modStats.BadgeEarnedOn)が
  自動で拾うことを確認する。
- A の順序是正により「名前入力→(同じBoot内で)EvaluateBadges→ポップアップ→
  Hubのバッジ棚に点灯」まで一続きで起きること。

### D. Hubタイルの鮮度と自己修復（modHub.bas / modHubStat.bas / modBoard.bas）
- `EnsureHubLayout` のタイル描画前に、共有フォルダ由来の「みんな(今日/今月)」を
  可能な範囲で更新する: `modShare.Reachable()` が真のときだけ
  `modBoard.RefreshBoard` 相当を On Error 保護付きで呼ぶ（到達不能なら呼ばず
  0 表示でよい。ブロッキングさせない）。既存の BootBoard 経路は壊さない。
- タイル値は**絶対に空文字にしない**: 描画ループで値の LenB=0 を検出したら
  "0" 系の既定値（"0分"/"0日"/"0" 等、タイルに応じた形）に置換して描く。

### E. 観測手段（原因未特定の「空」への保険）
- 描画時に LenB=0 の値を検出した場合、`modLog.LogUsage "hub_tile_empty", "",
  "タイル<index>:<label> の値が空でした"` を1行残す（1描画で複数出てよい）。
  次に実機で空が出たとき、どの関数が空を返したか特定できるようにする。
