1. **テスト基盤を最初の波にする**。テストが嘘をついている状態で他の46件を直しても、検証自体が信用できない。土台が先。

3. **`modExtractor:717`(txt/md/csv を UTF-8 固定で読む)を確定46件と同じ波に入れる**。カテゴリ上は未検証だが、確定した `optDiffDoc:174` と**根が同一**(CP932資料の無言化け)で、片方だけ直すと本体側が壊れたまま残る。実装役にはまず事実確認をさせる。
4. **`modAsk:292` は凍結モジュールに当たる**。R28波4に「modAsk最小手術」の先例があるため、同じ扱い(仕様で手術範囲を1関数・数行に限定し、他所へ波及させない)とする。判定ロジックの実体は `modChrome`(open契約)側へ置き、modAsk からは1行呼び出しに留める。

6. **重大度の補正を採用する**。`modBoard:410` は申告 BLOCKER → 検証2本とも「現在の数十人規模では実害ゼロ」として MAJOR へ補正。よって**配布ブロッカーではない**が、全社展開の前提条件として今回直す。

## 波3の実施結果と追加裁定(2026-08-16 ユーザー裁定を受領)

### W3-2 差し戻しの根拠(承認済み)

仕様に書いた「DisplayAlerts退避+ダミーPassword作法へ揃える」は**効かない**。`modExtractorWord` は既に `word.DisplayAlerts = 0`(wdAlertsNone) を Open 前に設定済みなのに、`openMode 2/3/4` が `PasswordDocument` を外して開くため同じプロンプトが出る = **DisplayAlerts はパスワード入力プロンプトを抑止しない**ことの実コードによる反証。
かつ、症状を確実に閉じる「引数なし再試行の削除」は 2026-07-29 の実機事故(Password 引数のせいで `Workbooks.Open` が全滅)対策を復活させる = 「Aを直すとBが壊れる」型。

### 追加裁定(ユーザー選択)

- **W3-11(実装・波3・案C採用)**: `Workbooks.Open` を呼ぶ**前に**先頭バイトで暗号化を判別する。暗号化 .xlsx/.xlsm は ZIP の `PK` ではなく OLE の `D0 CF 11 E0`。暗号化と判った時点で開かずに失敗させる。**7/29 の事故対策(引数なし再試行)は残す**。
  - **`.xls` は暗号化の有無にかかわらず OLE なので判別不能**。判別不能は「暗号化ではない」ではなく「判別不能」として従来経路へ流す。ここを取り違えると正常な .xls が全滅するため、テストで固定必須。
  - `modExtractorWord.bas:369-383` にも同じ手当てを行う(.docx の先頭バイトの意味は思い込まず確認する)。
  - 判別の実体は純関数へ切り出し `modTestsPure34` でゴールデン固定。新エラーコードは勝手に採番しない。
- **W5-26(実装・波5へ移送)**: **使い方ページのFAQに「Excel資料の検索結果がおかしい場合は取り込み直してください」を載せる**。W3-1 の修正は**これから取り込む資料にしか効かず**、既存の取込済みデータは列がずれたまま残るため。コードは増やさない。
