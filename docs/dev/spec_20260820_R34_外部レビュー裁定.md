### 却下（理由つき）

1. **Mega-Context 全文注入（ヒット資料の全文5万〜15万字を注入）**: 前提が事実誤認。実モデルは gpt-5.5（`gpt-5.6` はコードに一度も出現しない）、チャットは Azure 直叩きではなく社内リボンアドイン `ChatGPT()` の `Application.Run` 経由（modGateway.bas:112）で、**コンテキスト上限もペイロード上限も検証不能なブラックボックス**。LOでも検査できず、失敗の初検出が12,000人の実機フリーズになる。段階案（B2/B3/C）で同方向を安全に取る。
2. **多段パイプラインの1パス統合**: 検証段+機械的出典突合は過去ラウンドで実害を止めてきた設計資産。「6段が直列で20〜40秒浪費」も誇張——実測の直列API回数は ⚡=1回/🔍=4回/🧠=6〜9回で、速さが欲しい利用者には⚡が既に在る。むしろ本当の穴は一般モード側の検証欠落（A1）だった。
3. **⚡（新規質問）への会話履歴注入**: `modAsk.Answer` が prevU/prevA="" をハードコード（modAsk.bas:84-86）しており注入点が無い=凍結解除の大手術。かつ「続けて質問」ボタンが既にこの用途を担い（AskFollowup 経由なら⚡にも履歴が渡る実装済み）、新規質問に古い履歴を混ぜる文脈汚染の逆リスクがある。
4. **UI: リアルタイム・ステップインジケーター**: 既存。modLive が段階イベント駆動で「いま何をしているか」を書き換え済み。
5. **UI: 原文プレビュー・フライアウト**: 既存。modPeek が出典チップ→ワンクリック原文ポップアップ（最大600字）+実ファイルを開く導線まで実装済み。
6. **UI: Ctrl+Enter 送信**: 既存（modUI.bas:429-462）。Ctrl+K パレット/Ctrl+Shift+C コピーは価値はあるが容量限界のため次ラウンド以降へ。
7. **👍/👎 フィードバック**: 既存の🟢🟡🔴3値が上位互換。
8. **チャンク 700→1000字**: 実態は PDF/Word=450字への意図的オーバーライド済み（過去ラウンド裁定）。変更すると全資料の取り込み直しが必要で益が薄い。
9. **summary の updated_at ガード**: 既に M7/M12 の二重防御が同目的を達成済み。
10. **登録時LLM要約（Contextual Chunking）**: Gemini 自身も却下。同意（登録0秒の要件違反）。

## 3. 実装仕様

### 波1（Sonnet・層2の3件）

**A1: modGenPipe.ParseVerdict — PASS+後続文の可視化と安全化**
- 変更: 1行目が PASS のとき、2行目以降（trailing）を取り出し、
  - `Len(TrimWs(trailing)) > 100` なら `VERDICT_FINDINGS` を返し `findings = s`（全文）。
  - それ以外（空・短い装飾）は従来通り PASS。**ただし trailing が非空なら `findings = trailing` をセットしたまま PASS を返す**（純関数のまま可観測化）。
- 呼び出し元 `RunThorough`: `verdictKind = VERDICT_PASS And LenB(findings) > 0` のとき `modLog.LogUsage "gen_verify_pass_trailing", ...` を1行追加（LOで走らない経路なので副作用可）。
- 既存テスト `R26-1_verdict装飾付きでもPASS`（trailing="(問題ありません)"=9字）は**そのまま通ること**（閾値100の根拠）。
- 新テスト: (a) PASS+101字以上の懸念文→FINDINGS (b) PASS+短い装飾→PASSかつfindings=装飾文 (c) PASSのみ→PASSかつfindings空。ネガティブ確認必須。
- 容量: modGenPipe 残9,232。余裕。

**A2: 古い summary_*.bak の掃除**
- 実体は `modTelemetry`（残17,381・Board系ヘルパーの現住所）へ新設:
  `Public Sub BoardSweepStaleBak(ByVal folderPath As String)` — `Dir(folderPath & "summary_*.bak")` を列挙し、`FileDateTime` が**24時間より古い**ものだけ `Kill`（On Error Resume Next で1件ずつ握る。自分の hash も含めてよい=書く直前に呼ぶ設計のため）。
- 判定の純部分 `Public Function BakIsStale(ByVal fileTime As Date, ByVal nowTime As Date) As Boolean`（86400秒比較）を分離し、これだけ純テスト。
- 呼び出し: `modShare.BoardWriteSummary` の成功 Exit 直前に1行（modShare 残248・1行約40字は入る。**入らなければ実装役は独断で削らず司令塔へ報告**）。
- 新テスト: BakIsStale の境界（24h±1秒）。ファイル操作部はLO対象外（実機観点として記録）。

**A3: modChunker.bas:606 生 Left$ → modUtil.SafeLeft**
- `Left$(b, room)` → `modUtil.SafeLeft(b, room)` の1箇所置換のみ。
- 容量: modChunker 残72。+13字で残約59。**この1置換以外は一切触らない**（実質凍結）。
- テスト: AppendStructChunk が純テスト可能なら境界絵文字ケースを1本。不可能なら SafeLeft 既存テストで足りる旨を報告。

- 波1のテストは **modTestsPure37（新設）** に置く。tools/run_lo_tests.py と EXPECTED_PASS_MIN は**触らない**（司令塔が最後に一括更新）。

### 波2（Opus・層1の5件）

**B0: modApp 分割手術（B1 の前提）**
- `modApp.SaveTurnForRestore`（modApp.bas:56付近）の実体を `modAppState`（残13,810）へ移設。
- 手順: (1) 全呼び出し箇所を grep（シグネチャ変更ルール） (2) modApp 内の呼び出しを `modAppState.SaveTurnForRestore q, ans` へ直し、modApp から Sub 本体を削除（デリゲート残しより解放量優先。外部呼び出しが modApp 経由で在る場合のみ1行デリゲートを残す） (3) 移設先で modApp 私有状態への依存が無いか確認。**依存があれば独断で解決せず司令塔へ報告**。
- 目的: modApp に B1 の配線1行（約50字）を入れる容量を作る。移設後の modApp 残容量を python len で実測して報告。

**B1: 出典突合を ⚡/🔍 にも適用**
- 実体は `modMode`（残14,392・R33 で NoteAnswered 等の回答状態を既に保持）へ新設:
  `Public Function AnnotateIfNeeded(ByVal ans As String) As String`
  - 直近の回答モードが quick/deep のときだけ動く（thorough は modAskThorough が内部で突合済み=二重付与禁止。一般モードは呼び出し側の grounded ガードで来ない）。モード判定は modMode が NoteAnswered で記録済みの状態を使う。**「続けて質問」経由の回答でモードが記録されているか必ず実機コードで確認し、記録されない経路があれば司令塔へ報告**（勝手に別ソースから推測しない）。
  - `modAsk.LastHitCount/LastHitSource(i)/LastHitPage(i)/LastHitOrigin(i)`（Public・modAsk.bas:354-366）から出典タグ文字列を再構築し（**modPrompts.SourceTag と同一書式**: `[本棚:資料名 p.N]` / パック形。書式は modPrompts を読んで一字一句合わせる）、citeIndex を組んで `modAskThorough.AnnotateCitations(ans, citeIndex, mismatchN)` を呼ぶ。
  - LastHitCount=0 なら無加工で返す。mismatchN>0 は戻り値に既に注記が入るため追加処理不要。
- 配線: modApp.bas:219 の `End If` 直後（両経路合流点・grounded 確定後）に
  `If grounded Then ans = modMode.AnnotateIfNeeded(ans)` を1行（B0 で確保した容量内）。
- 新テスト: (a) 実在タグ→無加工 (b) 幻覚タグ→「(出典確認できず)」付与 (c) hits0件→無加工 (d) タグ再構築が modPrompts.SourceTag と一致（本棚/パック両 origin）。
- **繋ぎ目**: SaveTurnForRestore（B0移設先）は注釈**後**の ans を保存する順序になること（modApp.bas:241 が配線行より後にあることを確認）。modPeek.RenderCitations / 信頼度バッジは ans 文字列に依存しないことを確認。

**B2: 再ランク抜粋 300→700字（凍結 modPrompts の最小手術）**
- modPrompts.bas:222 の `SafeLeft(SourceBody(hits(i)), 300)` → `700`。数値1個・文字数増減ゼロ。
- 直上に契約コメント1行（R34裁定・司令塔承認済みの旨）。これ以外は modPrompts に一切触らない。
- 検算: 候補40件×700字=28,000字 < lim（max_context_chars=60,000）。BuildRerankPrompt は lim で残量管理済みのため溢れない（modAskRetrieve.bas:206 から lim が渡ることを確認して報告）。

**B3: 🔍しっかり に前後チャンク結合**
- `modAskRetrieve.RunMultiRetrieve`（mdMode を受け取る・modAskRetrieve.bas:104）の最終 topK 確定後に、
  `mdMode` が deep のときだけ `modAskFocus.NeighborExpand hits, nHits, modConfig.GetLong("deep_neighbor", 2)` を呼ぶ（2〜3行）。
- **二重結合禁止**: thorough は modAskThorough/modAskMulti が自前で NeighborExpand を呼ぶため、deep 限定ガードを外さない。quick は対象外（GO の範囲外）。
- mdMode の実値（"deep" か定数か）は modMode/呼び出し元で確認して合わせる。
- 容量: modAskRetrieve 残1,343。+200字程度。実測報告必須。
- 検算: topK_deep=12 + 前後2×12=最大36チャンク→プロンプト側は max_context_chars=60,000 の残量管理で自然に打ち切られる（BuildDeepDraftPrompt の打ち切り経路を確認して報告）。
- 新テスト: NeighborExpand 自体は既存テスト在り。追加は「deep でだけ発火するゲート」の純部分があれば1本、無ければ記録のみ。

### 共通ルール（両波）
- 検問方式: 着手時に空コミット→項目毎に即コミット。`git add` は変更ファイルの個別指定のみ。push は司令塔が行う。コミットに index.lock 競合が出たら2秒待って再試行。
- **LOテスト（tools/run_lo_tests.py）は絶対に実行しない**（並列衝突防止。司令塔が最後に直列実行）。`python3 tools/vba_lint.py --path src` は実行可。
- 触った全モジュールの容量を python len で実測して報告（wc -m 禁止）。
- 発見したエラー・仕様との食い違いは勝手に直さず司令塔へ報告。
- 新テストは期待値を壊して落ちること（ネガティブ確認）まで実施して結果を報告。恒真アサート禁止。
- コミットメッセージにモデル名等の識別子を入れない。
