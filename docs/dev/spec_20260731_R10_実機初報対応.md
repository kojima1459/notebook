# 要件定義 R10: 実機テスト初報4件の対応(起草: Fable司令塔・調査2本の裁定済み)

実機ログ(2026-07-31 18:49～19:12, Windows Excel 32bit 管理端末):
(A) E0303 Ghostscript未検出 / (B) E0302 Word・Acrobat COM不可 /
(C) E0801 ws.Activate err91 ×4 / (D) ナレッジタブのギャラリーピル無反応。

調査で確定した事実(読取専用調査2本の報告より):
- 本コードベースに SheetActivate 系イベントは一切存在しない。err91は
  「モーダル/外部COM直後の Activate が失敗を返すが、シート切替自体は
  成功している」(ログの ActiveSheet=Nexus が根拠)。
- ShowVaultGallery は Activate 失敗で PrepareScreenView 以降を無言スキップ
  (ログ無し)。カードは描画済みなのに画面が切り替わらない=ギャラリー無反応の
  構造原因。CとDは同根。
- RestoreExcelUI(脱出路)は DisplayFullScreen を解除しないため、全画面中は
  脱出路が視覚的に効かない。
- BlockIfIngesting の実況(SetStage)はホームのセル/非表示のStatusBar/
  チャットバブルの3経路とも、マイ本棚系画面では完全不可視。
- GS解決の候補パス・案内カード表示有無が一切ログされない(観測性ゼロ)。
  カードはセッション1回きりで、消費後は完全無言。
- GsCandidatePaths は ThisWorkbook.Path が "https://..."(OneDrive)でも
  そのまま連結する(無防備)。RunGsAsync 失敗時に Err 情報をログしない。
- txtwrite救済のインフラ(Shell起動/完了待ち/タイムアウト/一時フォルダ/
  ADODB.Stream UTF-8読込)は全て既存コードにある。容量: optVision残余
  2,632字(WARNまで)、optOcrCore残余18,575字、modExtractor残余5,641字。

## R10-1【Sonnet】Activate堅牢化とギャラリー救済(C+D)

1. modUI に共通関数を新設:
   `Public Function ActivateSheetRobust(ByVal ws As Worksheet, ByVal source As String) As Boolean`
   - OERN下で Err.Clear → ws.Activate。エラー時は Err.Number/Description を
     ローカルへ控え、Err.Clear → `Application.Goto ws.Range("A1")` で1回だけ
     再試行。
   - 事後検証: `ThisWorkbook.ActiveSheet Is ws` なら **成功扱い(True)**。
     初回Activateがエラーでも切替済みなら脱出路へ落とさない(実機ログの
     4件は全てこの型)。復旧できた場合は err_log でなく usage_log に
     "activate_recovered" 1行(source と err# を含める)。
   - 検証も偽なら E0801 を err_log へ(detail に err#・Err.Description・
     ws.Visible・ActiveSheet名・AppWin/WbWin。現行書式を踏襲しつつ
     **Err.Description を必ず追加**)、False を返す。
2. GoToNexus / GoToNativeSheet は ActivateSheetRobust を使う。True なら
   現行の正常系(GoToNexusはEnsureAppView)。False のときだけ RestoreExcelUI
   +即Exit(現行の脱出路思想は維持)。
3. RestoreExcelUI に `Application.DisplayFullScreen = False`(OERN下)を追加。
   全画面のままではタブ/リボン復元が視覚的に効かない齟齬の解消。
   Auto_Close 経由でも「閉じる時にExcelを素の状態へ戻す」方向なので害なし。
4. modVault.ShowVaultGallery:
   - `ws.Activate` を `modUI.ActivateSheetRobust(ws, "modVault.ShowVaultGallery")`
     に置換。True のときは現行どおり ActiveWindow 系設定と
     modKnowledge.PrepareScreenView まで実行。False のときは両者をスキップ
     (ActiveWindow が別シートを向いたまま触らない)。
   - uiStep パターン(modUIShelf.EnsureLayout と同型)を導入し、Finish ハンドラで
     Err.Number/Description をローカルへ控え → Resume でログ用ラベルへ →
     `modLog.LogError "E0801", "modVault.ShowVaultGallery", "[" & uiStep & "] ..."`
     を必ず1行残す(現行は完全無言)。ログ後に FinishCleanup4 へ合流。
5. modUiLock.BlockIfIngesting: SetStage に加えて
   `modSkin.ShowToast "取り込み処理が終わるまでお待ちください。", "info"`
   (OERN下)。Enter() の既存トーストと同じ作法。どの画面でも見える経路を確保。
6. 制約: CP932外文字禁止/Integer禁止/宣言先頭/OERNスコープ最小。
   modUI.bas と modVault.bas の容量を lint で確認し WARN 超過なら報告して
   停止(勝手に切り出さない)。
7. 検証: `python3 tools/vba_lint.py` ERROR 0 / `python3 tools/run_lo_tests.py`
   全PASS(多重起動禁止) / `--prod`・`--publisher` 両ビルド自己検証OK。

## R10-2【Sonnet】GS解決の観測性と堅牢化(A)

1. optVision: 候補パス文字列を保持(モジュール変数 mGsLastCands 等。
   FindGsExeByCandidates で毎回更新)。
2. ExtractPdfOcrPagedText の「GS未解決」分岐(現在ログ無し)で
   `modLog.LogError "E0303", "optVision.ResolveGsExe", detail` を追加。
   detail = "GS未解決 wbPath=<ThisWorkbook.Path> cand=<mGsLastCands>
   card=<mGsCardState>"(SafeLeft 2000)。
3. 案内カードの状態をモジュール変数 mGsCardState で追跡:
   ""(未表示)/"cancel"(カードでキャンセル)/"nofind"(選択先に無し)/
   "saved"(保存成功)。OfferGsFolderPicker 内で更新し、
   `modLog.LogUsage "gs_guidance_card", <結果>` を1行残す。
4. 利用者向けE0303文言(ExtractPdfOcrPagedText 281-287)へ追記:
   「このファイルの場所: <ThisWorkbook.Path>」
   「zipの中から直接開くと動きません。zipを右クリック→[すべて展開]で
   展開し、展開先の MyBookshelf.xlsm を開いてください。」
   (CP932安全な文字のみ。矢印は「→」不可なら「-&gt;」等でなく全角「→」は
   CP932に存在するため可。em dash/絵文字は不可)
5. 案内カードの再提示: `Public Sub ResetGsGuidance()` を optVision に新設
   (mGsGuidanceShown=False にする。mGsResolved は触らない)。利用者が手動で
   「資料を追加」を実行する入口(modShelf.AddFilesResult のダイアログ確定後)
   から modFeatures.InvokeFeature("vision","ResetGsGuidance",...) 経由で呼ぶ。
   InvokeFeature の既存シグネチャに合わせること(戻り値不要なら空文字を返す
   関数扱いで可)。自動同期(modShelfSync)からは呼ばない=起動時にモーダルが
   出ない現行性質を維持。
6. optOcrCore.GsCandidatePaths: wbDir の先頭が "http"(大文字小文字無視)の
   場合は stage2(同梱)候補を組み立てない(URL連結の無意味候補を防ぐ)。
   純ロジックのため modTestsPure6 に境界テストを追加(http/HTTPS/通常パス)。
7. RunGsAsync の NoRun で Err.Number/Description をローカルへ控え、
   呼び出し元の「GS起動失敗」LogError の detail に含める(現在はパスのみで
   原因が残らない。WScript.Shell がポリシーでブロックされる端末の切り分けに
   必須)。
8. 容量: optVision は WARN まで残余2,632字。上記追加で超えそうなら実装前に
   概算を報告して指示を仰ぐこと(勝手なモジュール分割禁止)。
9. 検証は R10-1 と同じ(lint/LOテスト/両ビルド)。

## R10-3【Opus】GhostscriptによるテキストPDF抽出(COM無し救済)(B)

会社の管理端末では Word/Acrobat の CreateObject がブロックされ、テキスト
PDFが取り込めない(E0302)。同梱GSの txtwrite デバイスでCOM無し抽出を足す。

1. 純ロジック(optOcrCore へ。容量余裕あり):
   - `BuildGsTextCommand(gsExe, pdfPath, outTxt)`: 既存 BuildGsCommand/
     BuildRunCommand と同じ引用符・cmdラップ・doneフラグ作法で
     `-sDEVICE=txtwrite -o <outTxt>` のコマンドを組み立てる。
   - `GsTextVerdict(cleanLen As Long) As String`: 空白類を除いた抽出文字数で
     "ok"(採用) / "image"(ほぼ空=画像PDF疑い→E0303へ回す) を返す。
     閾値は 40 文字(全ページ合計。テキストPDFなら普通は数百字以上、
     画像PDFのtxtwriteはほぼ0字になる)。境界テストを modTestsPure6 へ。
2. 実行部(optVision へ薄く。数百字以内に抑える):
   - `Public Function ExtractPdfTextNoOcr(ByVal path As String) As String`
     ResolveGsExe → 一時フォルダ(MakeOcrFolder流用) → BuildGsTextCommand →
     RunGsAsync → WaitForDoneFlag → 出力txtを ADODB.Stream(Charset "utf-8")
     で読込(modExtractor.ExtractPlainText と同パターン) → CleanupOcrFolder。
     - GS未解決: "#ERR:E0302:GS_UNAVAILABLE" 系の内部トークンを返す
       (このとき案内カードは出してよい=ResolveGsExeの現行挙動のまま)。
     - GsTextVerdict="image": "#ERR:E0303:" 接頭辞で返す(呼び出し元が
       OCR経路へ回すための印)。
     - 成功: 抽出テキストを返し `modLog.LogUsage "pdf_text_gs", ...` 1行。
   - 既存 Private の RunGsAsync/WaitForDoneFlag/MakeOcrFolder/CleanupOcrFolder
     は Public 化してよい(モジュール内呼び出しは無変更)。optVision の容量が
     WARN(28,000字)を超える場合は、実行部一式を新モジュール
     `src/opt/optGsTxt.bas` へ置くことを**事前承認**する(その場合
     build/modules.json への登録と lint 上の扱いを既存 opt モジュールに
     合わせること。純ロジックではないので PURE_LOGIC 登録はしない)。
3. modExtractor.ExtractPdfWithFallback: Word失敗→Acrobat失敗の後に第3段として
   modFeatures.InvokeFeature("vision","ExtractPdfTextNoOcr", path) を呼ぶ。
   - テキストが返れば成功扱い(ok=True)。usage_log は optVision 側の1行で足りる。
   - "#ERR:E0303:" 接頭辞なら errCode="E0303" で返す(既存の
     modShelfVision.TryVisionFallback がそのままOCR経路へ回す。二段が自然に
     接続することを確認すること)。
   - それ以外の失敗なら現行どおり errCode="E0302"。errDetail は
     "Word: ... / Acrobat: ... / GS: ..." と3者併記(SafeLeftで長さ管理)。
   - 既存の「COM成功→文字数でE0303判定」(252-259)の順序は変えない。
4. E0302 の FriendlyMessage(modLog): 「Wordを開いたままにして再試行」の
   現行案内は残しつつ、GS救済が入った旨で矛盾しない文言に調整(過剰に
   書き換えない。1～2文の追記まで)。
5. mock_llm=TRUE のときの挙動: txtwrite はLLMを使わないため mock でも
   実行してよい(ExtractPdfOcrPagedText の mock ガードを流用しないこと)。
6. 検証: lint/LOテスト(純ロジック新テスト含む)/両ビルド。実GSはLO環境で
   動かせないため、コマンド組立てと判定の純ロジックテストで担保する。
7. 注意: この端末は CreateObject 制限が広い。WScript.Shell まで塞がれて
   いれば本救済も失敗し得るが、その場合も R10-2 の Err 記録で切り分け可能に
   なる。失敗時に握りつぶさず必ず detail に Err 情報を残すこと。
