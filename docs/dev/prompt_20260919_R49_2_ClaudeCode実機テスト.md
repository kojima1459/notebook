## 貼り付けるプロンプト（ここから下をそのままコピー）

```
あなたは Windows の実機で Excel アプリ「マイ本棚AI」を検証する担当です。
このアプリは Excel 32bit の VBA 製で、社内アドイン「AIリボンちゃん」を
通して AI を呼びます。リボンの環境はこの PC に既に入っています。

## 絶対に守ること

1. **APIキーの値を出力しないでください。** ブックの config シートに
   難読化された形（`OBF1:` で始まる）で入っています。値は伏せてください。
2. **ファイルを外部サービスへ送らないでください。**
3. **わたしの許可なく `config` シートの値を書き換えないでください。**
   書き換えを伴う確認は、先に「この値をこう変えてよいか」を聞いてください。
4. **取り込み（資料の読み込み）の途中で Excel を強制終了しないでください。**
   本棚が中途半端な状態で残ります。

## このアプリの前提（調べ直さなくてよい）

- 起動すると **Hub** という画面が最初に出る。そこから
  「💬 チャットで質問する」「📚 ナレッジと本棚」「📊 ダッシュボード」へ行く
- **起動中はシートのタブを隠している。** タブで画面を切り替えることはできない。
  画面上のボタンで移動する（閉じるときにタブは戻る）
- 回答モードは3つ: ⚡すぐ聞く / 🔍しっかり調べる / 📚入念に調べる
- **入念は1回の問い合わせが最大30分戻ってこない。** 止めたいときは ESC キー
- リボンは通信に失敗しても**例外を出さず、文字列を戻り値で返す**
  （`接続切れ` `(error:429)…` `content_filterに該当しました` など）

## やってほしいこと

### 第1部: 同梱の受入確認をそのまま実施する（これが本体）

zip の中の **`docs/09_受入確認_R46_R47.html`** をブラウザで開いてください。
**S群（6項目）と R群（4項目）を、書いてあるとおりに実施**してください。
今回いちばん見たいのは **S群**です（部内へ出る前の関所と、押し間違いの取り消し）。

各項目について、次の形で記録してください。

| 項目 | 実施した操作 | 画面に出たもの（文言はそのまま写す） | 合格/不合格 |

**注意して見てほしいこと**

- **S-1 と S-3 は、メッセージが2つ前後して出ます。**
  先に「部内に共有されます」が出て、OK を押すと打ち消しが残ります。
  これは承知のうえの暫定です。**順番が分かりにくかったかどうかも
  そのまま書いてください**（直す優先度の材料にします）
- **S-2 は「止まらないこと」を確かめる項目**です。ここで打ち消しが出たら、
  **その質問文をそのまま**記録してください。関所が効きすぎています
- **S-3 はネットワークを切る必要があります。** Wi-Fi か VPN を切って試し、
  終わったら必ず戻してください
- **S-5 は共有フォルダが設定されていないと「1票は引っ込められませんでした」
  が正しい結果になります。** 共有フォルダが設定されているかどうかを
  先に確認して、どちらの状態で試したかを明記してください

### 第2部: 30,000字の壁が実在するか（実験・この回の宿題）

このプロジェクトは「VBA の1モジュールは30,000字まで」という前提で
9か月ぶん設計してきました。**ですが、この上限が今の配布方式でも本当に
効いているのかを、実機で一度も確かめていません。**
いまの配布は「完成品の vbaProject.bin をビルドが直接書く」方式（baked）で、
上限が効く理由だった経路（VBComponents.Add / AddFromString）は配布物から
消えています。**もし効いていないなら、9か月ぶんの分割作業は不要だった
ことになります。** これを確かめてください。

この PC に開発用の一式（`MyBookshelf` のソース）があれば、次をやってください。
無ければ「ソース一式が無いので未実施」と書いて飛ばして構いません。

1. 適当なモジュールを1本コピーして、**中身を 35,000 字程度まで膨らませる**
   （コメント行を増やすだけでよい。動く必要はない）
2. `build/modules.json` にそのモジュールを足す
3. `python build\build_mybookshelf.py --dev` を実行（**baked モードのまま**。
   `--vba-mode installer` は使わないでください）
4. できた `dist\MyBookshelf_dev.xlsm` を **実機の Excel 32bit で開く**
5. VBE（Alt+F11）を開き、**そのモジュールがコンパイルできるか**を見る
   （メニューの「デバッグ」→「VBAProject のコンパイル」）

**知りたいのは次の3つだけです。**

- ビルドは通ったか
- Excel でブックが開いたか
- **コンパイルが通ったか。エラーになったなら、そのメッセージをそのまま**

### 第3部: 気づいたことを何でも

「仕様かどうか分からないけれど変だと思ったこと」を、
**遠慮せず全部**書いてください。特に:

- 押しても何も起きないボタン
- 文字が □ になっている場所
- 画面の案内どおりに操作できなかった場所
  （「タブ」と書いてあるのに画面にタブが無い、など。R49 で直したつもりです）
- 待たされて不安になった場所（何秒待ったかも）

## 報告の形

1. S群の表（6項目）
2. R群の表（4項目）
3. 第2部の3点
4. 第3部の気づき（箇条書き・いくつでも）
5. **途中で失敗して先へ進めなかったもの**があれば、どこで止まったか

**うまくいかなかったことを隠さないでください。**
「動かなかった」は失敗ではなく、こちらが知りたい情報そのものです。
推測で「たぶん大丈夫」と書かないでください。見たままを書いてください。
```

## この②で何が分かるか（司令塔メモ・Claude Code には渡さない）

- **第1部 S群**が R49 の実装（H-7 / H-H-3 / A-A-3 / G-G-2）の唯一の実機確認。
  特に **S-2（関所が効きすぎていないか）は S-1 と同じ重さ**。
  過検知は「部内ナレッジのフライホイールが静かに止まる」という、
  誰も報告できない壊れ方をする。
- **第2部 D3** はこのプロジェクトで一番大きい前提の検証。
  30,000字の壁が baked 方式で効いていないなら、§12 の分割裁定・受け皿という
  設計上の制約が丸ごと不要になる。**「最大の足かせを特定しろ」への答えが
  ここにある可能性が高い。** ソース一式が無い場合は次回へ持ち越す。
- **`--vba-mode installer` を禁じているのは意図的**。あれは1リリース限りの
  開発用フォールバックで、`--zip` との併用も禁止。installer で試すと
  上限が効いてしまい、**実験の答えが逆に出る**。
