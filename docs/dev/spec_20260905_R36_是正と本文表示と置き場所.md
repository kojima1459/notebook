## 1. 置き場所（データブック分離）— 分岐あり・GO 待ち

### 1-1. 事実（R35 §7・§10 と 09-05 実測）

- 会社PCのローカル（D:・Documents・Downloads）は日跨ぎ／シャットダウンで消える。残るのは OneDrive 同期フォルダ・部門共有サーバ・デスクトップのショートカットだけ。
- OneDrive 直接起動は避ける（`ThisWorkbook.Path` が URL になりうる。実測なし・設計で回避）。信頼できる場所の追加は組織ポリシーで不可。
- 環境変数 `%OneDrive%` は別利用者を指す（09-05 実測）→ 環境変数で置き場所を探す方式は不採用（姉妹PJも撤去中）。
- 現行（F3b）: bat が xlsm ごと `D:\MyBookshelf\` へ複製して起動し、10分ごと＋終了時に OneDrive 側へ書き戻す。データは xlsm の中。**版上げ（新 zip 配布）のたびに本棚が消える**（引き継ぎファイルを手で作る必要がある）。

### 1-2. 選択肢（タクシー原則）

| | 1-A **版上げ時の自動引き継ぎ**（推奨） | 1-B 本格的なデータブック分離 |
|---|---|---|
| 何をするか | データは xlsm の中のまま。**新しい版を初めて開いたとき、同じフォルダにある前の版（`MyBookshelf_前回.xlsm` など）を見つけて、本棚・実績・設定を自動で取り込む**（既存の `modMigrate.ImportUserData` の中身を、引き継ぎ .xlsx ではなく前版 .xlsm から直接読む形へ広げる） | エンジン（xlsm・D:）とデータ（.xlsx・OneDrive）を分け、起動時に読み込み・終了時に書き出す |
| メリット | 髙橋さんの困りごと（版上げで消える）が消える／bat・VBA の往復設計は不変／実装が小さい（modMigrate の読み取り元を広げる＋起動時の1判定） | 版上げが「xlsm を置き換えるだけ」になる／データが .xlsx なので AV・メールに通りやすい |

## 2. 是正の仕組み（❌違う → 次から必ず使われる）

### 2-1. 現状（再現済み・`modAppAct.RecordCorrection:115-143`）

1. ❌違う → `modAsk.FeedbackRed`（記録＋共有）→ InputBox「正しい内容を教えてください」
2. 本文 = `【修正ナレッジ】` + 「対象の回答(抜粋): 」回答先頭400字 + 「正しい内容: 」入力 → `modVault.RegisterKnowledgeText("修正ナレッジ", body, "修正,フィードバック")` → TEMP に `ナレッジ_修正ナレッジ_yyyymmddhhnnss.txt` → `modShelf.IngestFile` → **普通の資料**として `my_knowledge` へ
3. トースト「ありがとうございます。次に同じ質問をした人から、この内容で答えます。」

問題: **元の質問文が本文に無い**（同じ質問を再入力しても、回答抜粋に偶然含まれる語でしか当たらない）／優先度・加点が無い／誤っていた元チャンクは残る／修正のたびに別資料が増える。

### 2-2. 裁定（2-A: 修正ナレッジの強化。別テーブル＋一覧画面の 2-B は採らない）

UI は増やさない。**「質問文を一緒に保存する」＋「回答生成の直前に、質問が一致する是正を必ず先頭に差し込む」** の2点で「次から必ず使われる」を実現する。

1. **保存する本文**（modAppAct）:
   ```
   【是正メモ】この質問には、下の「正しい内容」で答えること。
   質問: <元の質問文そのまま>
   正しい内容: <入力>
   （誤りだった回答の抜粋: <回答先頭200字>）
   ```
   - 資料名（title）は `是正メモ_<質問先頭24字>`（`SanitizeFileName` 相当の置換は modVault 側の既存処理に従う）。同じ質問への2回目は**上書き**（同名の既存資料があれば `modShelf.DeleteSource` してから登録。「修正のたびに増える」を止める）。
   - `keywords` 引数は `"是正,修正,フィードバック"`。origin は `self` のまま（パック・チャンネル・引き継ぎの既存経路を壊さない）。
2. **回答時の注入**（新モジュール `modCorrect`・qa 層・凍結外）:
   - 入口は `modAskRetrieve` の各 Run*（`RunMultiRetrieve` / `RunDeepScoped` / `RunUnscoped`）が hits を返す**直前**に1行 `modCorrect.InjectHits question, hits`。modAskRetrieve は残 1,092 字なので**1行呼び出し×3 に留める**。
   - `InjectHits` の中身: `my_knowledge` から資料名が `是正メモ_` で始まる行を集め、本文の `質問: ` 行を取り出し、`modSparse.NormalizeForSearch` で正規化した質問と**完全一致**、または（完全一致が無ければ）`modSparse.KeyScore` 系の語一致が閾値以上（config `correct_key_min`、既定は実装波が Pure テストで決めて報告）の是正メモを、**hits の先頭に**差し込む（既存 hits の同一 chunk は除く。件数上限は `topk_*` を超えないよう末尾を落とす）。
   - hit の形は modAskRetrieve が返しているものと同じ（調査結果 §2-4 の型に従う）。**modAsk・modPrompts には触らない**（差し込んだ hit は普通の出典として本文へ載り、チップにも出る。本文冒頭の「【是正メモ】この質問には…で答えること」が LLM への指示として働く）。
   - 一般アシスタント（`sendMode="normal"`）では注入しない（本棚を見ないモード）。
3. **トースト文言**を実態に合わせる: 「ありがとうございます。この質問には次から、いま書いていただいた内容で答えます（是正メモとして本棚に入りました）。」
4. **記録のみ（本ラウンドでやらない）**: 誤チャンクの減点・無効化／他人の `correction` 受信箱の取り込みボタン／是正メモの一覧画面（本棚の一覧で `是正メモ_` を検索すれば見える）。

### 2-3. 契約（実装波向け・2026-09-05 調査で確定）

**事実（調査で確定・file:line）**
- hit は UDT `Hit`（`modTypes.bas:33-42`）: `chunk_id / score / source / page / preview / origin / full_text`。**1始まり配列**。modAsk は hits の中身だけを使い、my_knowledge を引き直さない（`modAsk.bas:296-297, 367-376`。プロンプトは `modPrompts.BuildSourceBlock` が `hits(i).full_text` を `[本棚:source p.N]` タグ付きで**先頭から順に**載せる `modPrompts.bas:560-617`）。→ **`Hit` を1件合成して先頭に差し込めば、凍結モジュール不触で本文にもチップにも載る。**
- modAsk が呼ぶ入口は `RunDeepScoped`（`modAsk.bas:189`）と `RunUnscoped`（`:191`）の2つだけ。戻り値 `-1`=埋め込み失敗／`0`=0件／`>0`=件数。
- 低関連警告は `hits(i).score` の最大値で判定（`modAskRetrieve.bas:509-511`）。
- `RegisterKnowledgeText(title, body, tagsText, docBase, silent)`（`modVault.bas:274-277`）: **`tagsText` は本体で未使用**（捨てられる）。`docBase` を渡すと TEMP の `SanitizeName(docBase) & ".txt"` に書き、本文先頭に `【title】` が付く。source 名は `modUtil.FileNameOf(path)`＝**拡張子込みのファイル名**（`modShelf.bas:72`）。
- 元の質問文: modAsk の `mLastQuestion` は Private で、凍結のため accessor を足せない。**`modAppState.SaveTurnForRestore(q, ans)` が ui_state `nexus_hist_u` に直近の質問（先頭300字・`;;;` 区切りで新しい順）を保存している**（`modAppState.bas:354-364`）。→ 是正メモの質問文は **`modState.LoadState("nexus_hist_u")` の先頭セグメント**から取る。実装波は「RAG 回答のあと `SaveTurnForRestore` が必ず呼ばれているか」を `modApp.OnSend` 周辺で確認し、呼ばれていない経路があれば報告（勝手に足さない）。
- 質問の正規化: `modSparse.NormalizeForSearch`（`modSparse.bas:94`）と `modInsight.NormKey`（`modInsight.bas:417`。空白・句読点・?・括弧を除去し先頭40字を小文字化＝gap 重複判定のキー）。
- 語一致: `modSparse.KeyScore` / `DistinctiveKeys`（`modSparse.bas:199, 400`）。

**契約**
- 新モジュール `src/qa/modCorrect.bas`（qa 層・UI 非依存・`modules.json` に登録・wave `R36-2`）。

## 3. スクショ本文表示（読み取り結果をその場で確かめる）

### 3-1. 裁定

- 新画面 **`text_view`**（`modDiag` の `diag_report` シートと同じ作法: 実行時に作る作業シート、テキストを行に流し込み、左上「← 戻る」）。
- 入口は2つ:
  1. マイ本棚ツールバー（一覧表モードのみ）に **`📖 本文`** ボタン（`🗑 1件` と同じ「行をクリックしてから押す」型。kind は通常）。行未選択の文言も `🗑 1件` と同型: 「本文を見たい資料の行をクリックしてから、もう一度押してください。」
  2. **📸 スクショ取込の完了直後に自動で `text_view` を開く**（髙橋さんの「放り込んだあと問題ないか確認したい」に1手で応える）。config `screenshot_show_text` = `TRUE`（`FALSE` で従来どおりトーストのみ）。
- 表示内容: 資料名／取込日時／チャンク数／`【p.N】` 区切りで **全チャンクの `full_text` をページ順に**（breadcrumb 前置 `【資料名>章>条】` は除去して表示。`modVaultGallery.MakePreviewText` と同じ剥がし方）。末尾に案内: 「内容が違うときは、この資料を 🗑 で消してから ➕登録 で正しい文章を登録し直してください（読み取った文章を直接直す機能はありません）」。
- 戻る先: 開いた元の画面（マイ本棚 or チャット）。`modUiLock`・`modViewport` の作法は modDiag と同一にする【調査】。

### 3-2. 契約（2026-09-05 調査で確定）

**事実（file:line）**
