# 要件定義 R5: 敵対的レビュー指摘への対応（実装: Opus / 裁定: Fable 司令塔）

レビュー18件に対する司令塔の裁定。番号はレビュー報告のもの。
【修正】は本タスクで直す。【受容】は直さない(理由を記す)。

## 高 – 必ず直す

### 4-D【修正・最優先】Word相乗りモードでの編集中文書の破棄
modExtractorWord.TryExtractOnce の相乗り(MODE_ATTACH)経路で、
Documents.Open が「既に開かれている文書」を返した場合、Cleanup の
doc.Close 0 が利用者の未保存編集を破棄する。
- 対策: Open の**前に** word.Documents を走査し、対象パス(FullName を
  大文字小文字無視で比較。原本パス/一時コピーパスの両方)と一致する
  既存文書があるかを調べる。
  - 既存文書がある場合: **その文書を開き直さず・閉じもしない**。
    テキスト抽出だけ既存 doc から行い、Cleanup には「doc を自分が
    開いたか(ownsDoc)」を渡して ownsDoc=False なら Close しない。
  - 無い場合: 従来どおり Open し、ownsDoc=True で Close する。
- 自前起動モード(1-3)は新規インスタンスなので既存文書は存在し得ないが、
  同じ ownsDoc 機構を通しても害はない(実装の単純さを優先してよい)。
- modExtractorWord は src/ingest だが本件はデータ喪失級のため編集許可。

### 3-A【修正】ヘッダー: トグルで崩れる/実機幅で常にアイコンのみ
- (1) モード/速度/言語の**トグル後にピルへ直接テキストを書き込む3箇所**
  (modAppState.bas:162 付近 / modApp.bas OnToggleSpeed / OnLangCycle)を、
  **DrawChatHeader の再実行(ヘッダー全体の再描画)**に置き換える。
  幅計算を通らない文字列書込みを残さないこと(これが崩れの直接原因)。
- (2) ティア方針の変更: 状態を持つ3ピル(モード/速度/言語)は
  **どのティアでも短い文字ラベルを維持**する(例: 「🏢社内」「🌐一般」/
  「⚡すぐ」「🔍調べ」「🔬徹底」/「🌐日」「🌐EN」等。実キャプションは
  実装者が決めてよいが、状態が読めること)。無状態の5ボタン
  (終了/クリア/質問例/ヘルプ/テーマ)はアイコンのみに落としてよい。
  1段に収まらない分は既存の2段目送り機構で流す(実機幅597ptで
  2段になるのは許容。重なりゼロが最優先)。
- (3) modTestsPure3 のヘッダーテストを「実キャプションから PillWidth で
  幅を作り、W=597 でティア選択+FlowRight を通して重なりゼロ」を
  検証する形に強化する(現在は固定幅配列を渡しており選択ロジックを
  通っていない)。

### 4-A【修正】E0504等のモーダルが残り二重報告
- AddFilesResult は IngestFile を **silent:=True** で呼ぶ
  (per-file モーダルを全廃)。
- 集計 MsgBox(showMsgBox:=True の経路)には、reasons に E0504 が
  含まれる場合に1行「同じ名前の資料が別の場所から登録済みのものが
  N件あります」を足す(チャット経路は既に文言あり)。

## 中 – 直す

### 1-A【修正】mMode="" の解釈不一致
IsTableMode と RefreshCurrent の両方が「空文字=一覧表」になるよう
単一の正規化関数(例 Private Function CurrentMode() As String:
"" なら "table")を作り、両者ともそれを使う。

### 1-B【修正】ギャラリー/解決事例で取込結果が画面に出ない
- modUIShelf.OnIngestScreenshot の末尾で modKnowledge.RefreshCurrent を呼ぶ。
- modUIShelf.RenderShelf の IsTableMode ガードを「no-op」から
  「modKnowledge.RefreshCurrent へ委譲して Exit」(現行モードを再描画)へ。
  再帰しないこと(RefreshCurrent の table 分岐は RenderShelf を呼ぶが、
  委譲は非 table のときだけ発生するため再帰しない — コメントで明記)。

### 1-C【修正】CloseVault の遷移
- 先に modKnowledge.RefreshCurrent で「マイ本棚」シートを表示・アクティブ化
  し(mMode 既定=table)、その後 VaultInput を veryHidden にする
  (アクティブシートは隠せず1004になる現行順序を逆転)。
- ShowVaultGallery 固定呼び出しをやめ、登録前に見ていたモードへ戻す。

### 1-D【修正】行高リセット範囲
modVault/modShared の行高リセットを 7:412 に拡大(一覧表の最終行まで)。

### 2-A【修正】初回起動でバッジ棚が出ない
modHub の DrawFirstStep 分岐でも DrawBadges を呼ぶ(welcome バッジが
初回から見える)。modHub は残り628字なので、収まらなければ呼び出し1行に
留めるか modHubStat 側へ寄せる。

### 2-C【修正】Hub描画の同期的共有I/Oがジッタ前に走る
modBoard に「BootBoard 済みフラグ」を持たせ、RefreshBoardTiles は
フラグが立つまで何もしない。これにより Boot 中の Hub 初期描画は
共有フォルダに触れず(値は0のまま=従来どおり)、LaunchNexus 後の
再描画から効き始める。StartupJitter の設計意図を尊重。

### 2-D/7-B【修正】旧Vaultシート削除の失敗時
- DisplayAlerts は変更前の値を控えて復元。
- Delete 失敗時(まだ存在する場合)は Visible を veryHidden へ戻す。

### 4-B【修正】AddFilesResult 例外時に報告が消える
modApp.OnAddDocs で res が空文字のとき、
「取込処理でエラーが発生しました。err_log をご確認ください」の
バブルを出す(キャンセル= "ok=0;ng=0;capped=0;chunks=0;reasons=" とは
区別できる)。あわせて AddFilesResult 本体に R6 準拠の
プロシージャレベルハンドラを追加し、途中失敗でもそれまでの集計を
文字列で返すようにする。

### 4-C【修正】更新取込で嘘の文面
AddDocsMessage の ok>0 かつ chunks<=0 の文言を
「✅ 取り込みました。前回から内容が変わっていない部分は増やしていません
(更新は反映されています)」の趣旨に変更(「すでに入っています」と
言い切らない)。

## 受容 – 直さない(理由)

- 2-B(既存利用者に welcome ポップアップが1回出る): 1回限りで無害。
  背景がガードシートである点は許容(次回起動以降は出ない)。
- 6-C(hub_tile_empty が到達不能): 実機写真の空表示は旧ビルドの
  現象であり、現行コードでは値が空にならないことが保証された。
  防御と観測は保険として残す(害なし)。
- 5-B / 6-B: 記録のみ(容量逼迫は次ラウンドの分割計画で対応)。
