## A. UI修復バッチ(Opus)

### A-1. ダッシュボードの共通クローム化
- modDash の画面に、他画面と同等のヘッダー帯(濃色バー+タイトル)と
  ナビピル(← Hub / 💬チャット / 📚ナレッジと本棚)を追加する。
  既存の 分析用ログ出力/チャットへ/更新 ボタンは統合・整理してよい
  (チャットへが重複するなら1つに)。
- 写真の「上部の白い帯」は、ヘッダー描画が無い+数式バー表示状態の複合。
  A-2 の EnsureAppView と、Dashboard 描画へのヘッダー追加の両方で塞ぐ。

### A-2. アプリ表示状態の自己修復(EnsureAppView)
- modUI に `Public Sub EnsureAppView()` を新設:
  DisplayFullScreen=True / 数式バー非表示 / DisplayGridlines・Headings=False /
  ScrollColumn=ScrollRow=1 / Zoom=100 を冪等に再適用(全て On Error 保護)。
  既に全画面なら何もしない(チラつき防止のため状態を見てから触る)。
- 呼び出し点: modKnowledge.PrepareScreenView / modUI.GoToNexus /
  modHub.EnsureHubLayout / modDash 表示 / modApp.OnRefreshUI。
  これにより「閉じる→キャンセル」で壊れた表示は**次にどのボタンを
  押しても自動復旧**する(現状は着せ替えだけが偶然直していた)。
- Auto_Close 側は変更しない(閉じる進行時に OnTime を仕掛けると
  閉じたブックを再オープンする事故になるため。ThisWorkbook ストリームは
  圧縮予算があるため触らない)。

### A-3. Hub右列の余白解消(タスク#27)
- modHub.DrawExtras の `4 * (NAV_H + NAV_GAP)` を実枚数3に基づく式へ。
- NAV_H 46→60 / NAV_GAP 8→10 とし、ナビ3枚が従来4枚分の縦幅を
  ほぼ埋める形にする(説明文の窮屈さも解消)。
- modHub は残り約570字。増分がこれを超える場合は定数変更+式修正のみに
  留め、追加コードは modHubStat 側へ。

### A-4. Hubタイル値の非表示(4枚)の構造的解決
- 実機で hub_tile_empty が1件も出ていない=値は空でなく、**描画段階で
  見えなくなっている**(段落2書式方式の限界)。原因の深追いより構造を変える:
  タイルを「ラベル用Shape」と「値用Shape」の**2枚構成**に分離し、
  値は独立したテキストボックスに直接書く(段落操作を全廃)。
- 描画本体は modHub の容量制約のため modHubStat(または新 modHubTiles)へ
  移設してよい(modules.json/CONTRACT/開発者ガイドの同期を忘れない)。
- 観測: 描画のたび、8タイル分の `hub_tile_drawn idx=<n> len=<値の文字数>` を
  usage_log に1行で(まとめて1行に8個分)記録。次に消えたら座標か値かを
  即断できるようにする。

### A-5. ヘッダー機能の共通化
- ナレッジ(modKnowledge クローム)とダッシュボードのヘッダーに
  🚪保存して終わる(modApp.OnSaveAndExit) と 🎨着せ替え(既存テーマ切替の
  OnAction をそのまま)を追加。Hub/チャットと同じ並び順・アイコンにし、
  「どの画面でも右上は同じ」状態にする。
- 追加はA-1/既存クロームの右端ピル列に統合(幅予算は modChrome の
  流し込みが保証)。

## B. 応答性バッチ(Sonnet)

### B-1. 埋め込み進捗の目安時間
- modEmbed.EmbedPending / modEnrich.EnrichPending の進捗 SetStage を
  「📥 ベクトル化中 12/88件・残り約3分」形式へ。
  推定は直近バッチの移動平均(1件平均×残件数、1分未満は「まもなく」)。
  最初のバッチ完了までは件数のみ表示。
- 純ロジック(残り時間の計算・文言整形)は関数に切り出し
  modTestsPure3/4 でテスト。

### B-2. 取込中の「応答なし」対策
- DoEvents を長時間ループの安全な区切りに追加:
  modExtractorWord のページ抽出ループ / modExtractorExcel のシートループ /
  modShelfSync のファイルループ(1ファイルごと)。
  ※modChunker(純ロジック)には入れない。modEmbed は既に有り。
- 再入の抑止(DoEventsで発火するクリックへの防御):
  - modShelf に `Public Function IsBusy() As Boolean`(mIngesting 公開)。
    modShelfSync にも同等(既存 mSyncRunning を公開)。
  - 画面遷移系 OnAction(modKnowledge の各ピル/ツールバー、modHub ナビ、
    modApp のナビ)は入口で IsBusy を見て、busy なら
    modUIMain.SetStage "処理中です。完了までお待ちください…" を出して
    即 Exit(モーダル禁止)。
  - IngestFile の再入ガード(E0503)は現在 ShowError(モーダル)。
    連打で連続モーダルになるため、silent でない場合も SetStage+ログのみに
    変更する(E0503 のログは維持)。
- 危険予防: DoEvents 追加箇所は「COM呼び出しの外」(ページ処理の合間)に
  限定し、1ページ内の COM シーケンス途中には入れない。
