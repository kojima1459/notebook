# 要件定義 R2: 取込コアの修正（実装: Sonnet / 起草: Fable 司令塔）

対象コミット基点: f211a74。実機ビルド 023128f のログ・写真から確定した真因に基づく。

## 背景（確定事実）

1. `modExtractor.DropGarbledPages`(modExtractor.bas:360-373) は化けページの
   `pages(i).Text` を `""` にするだけで配列を詰めない。実機ログで
   `extract_garbled N件` と `chunk_skipped_pages N件` が全6ペアで完全一致
   （1↔1, 2↔2, 2↔2, 2↔2, 6↔6, 1↔1）しており、空文字ページが後段
   （NormalizeForIngest 以降のどこか）で err#9 を出してページ単位スキップに
   化けている。
2. 1ページしかない `.doc` が化け判定されると全文が消え、`totalChars=0` →
   E0304「抽出結果が空」で取込不能（実機: 【個別特約】興行中止保険特約（関係者読替).doc）。
   さらに PDF では E0303（画像PDF）へ誤誘導される。
3. `CopyToLocalTemp` は `FileCopy`（排他オープン）を使うため、Word/Excel/
   Acrobat で開いているファイルはコピーに失敗する。実機ログ:
   `悪天候の定義.docx : localcopy=failed`（Desktopのファイル）。
   Word問題の回避策として「Wordを開いたまま使う」運用にしたため頻発する。
4. レビューH-11対応「コピー失敗時は原本フォールバックしない」は、
   危険が実在するのは **同一Excelインスタンスで開かれるxls/xlsx/xlsm** だけ
   なのに、pdf/doc/docx にまで適用している（過剰一般化）。Word COM は
   ReadOnly で開くだけで、利用者の編集セッションを壊す経路がない。
5. `modShelf.AddFilesViaDialog` は自前で MsgBox を出し、呼び出し元
   `modApp.OnAddDocs` は TotalChunks の前後差分だけでチャットバブルを出す。
   既存資料の再取込（ハッシュ重複で新規0行・status="done"）では
   「追加しました」(MsgBox) と「追加されませんでした」(チャット) が同時に出る。

## 変更要件

### A. DropGarbledPages の配列圧縮（err#9 の根絶）
- 化けページを **配列から取り除いて詰める**。残すページの `.page` 番号は
  元のページ番号を保持（出典表示のため）。
- **全ページが化け判定になる場合は除去しない**（フィルタの誤判定で文書を
  丸ごと失うより、化けた本文でも取り込む方がまし）。このとき
  `LogUsage "extract_garbled_kept"` で「全N件が化け判定のため除外せず続行」を残す。
- これにより E0304/E0303 への誤誘導も消える。

### B. チャンカーの空ページ防御（多層防御）
- `modChunker.ChunkAllPagesStructured` と legacy ループの先頭で
  `LenB(Trim$(pages(pLo+p).Text)) = 0` のページは正常スキップ
  （エラーハンドラに乗せない。mSkippedPages にも数えない）。
- 純ロジックテストを追加: (1) `NormalizeForIngest("")` がエラーを出さない、
  (2) Text="" のページを含む配列で `ChunkPagesEx` が err なく動き
  `SkippedPageCount()=0`、(3) 化けページ圧縮後の配列で総チャンク数が正しい。

### C. ロック中ファイルでも読めるローカルコピー
- `CopyToLocalTemp` の `FileCopy` を
  `Open path For Binary Access Read Shared` + `Get` → `Put` の共有読みコピーへ
  置き換える（Word/Excelが開いていても読み出しは共有可）。
- 失敗時は従来どおり空文字列を返す。0バイトファイルの扱いに注意
  （Get で LOF=0 なら空のままコピー成立とする）。

### D. コピー失敗時のフォールバックを拡張子で分ける（H-11の適正化）
- `xls/xlsx/xlsm`: 従来どおり原本フォールバック禁止（同一Excelの
  既存ブックを掴んで閉じる事故が実在するため）。
- `pdf/doc/docx`: 原本パスで続行する（Word COM は ReadOnly オープンのみで
  利用者の編集セッションに触れない）。ログは
  `localcopy=failed(原本で続行)` として次回の切り分けを可能にする。
- H-11 の本来の意図をコード内コメントで明記すること。

### E. AddFilesViaDialog の結果を呼び出し元へ返す
- `Public Function AddFilesResult(...)` 等の形で、
  ok件数 / ng件数 / capped件数 / 新規追加チャンク数 /
  代表的な失敗理由（E0504同名衝突・image_pdf・E0302等の内訳）を返す口を作る。
  既存の `Public Sub AddFilesViaDialog`(OnAction互換) は残し、内部で共通実装を
  呼ぶ。MsgBox は「呼び出し元が表示を担うときは出さない」ためのフラグを持つ。
- **modApp.OnAddDocs 側の文言変更は本タスクの範囲外**（別担当がUI改修と同時に
  実施する）。本タスクでは「結果を正しく返す口」を作るところまで。
- 戻り値の形式は modTypes に UDT を足すか、"ok=2;ng=1;dup=1;reason=E0504" の
  ような文字列でもよい（30,000字制限・モジュール契約 tools/vba_lint.py の
  CONTRACT 更新を忘れない）。

## 制約
- モジュール30,000字上限（vba_lint WARN 28,000）。
- CP932外の文字を実行文に書かない（〜 U+301C 等は禁止）。
- エラーハンドラ規約 R6（docs/60_開発者ガイド.md）: ハンドラ稼働中に
  On Error Resume Next を書かない。後始末は別Sub or Resume で抜けてから。
- 触ってよいファイル: src/ingest/modExtractor.bas, src/ingest/modChunker.bas,
  src/ingest/modShelf.bas, src/test/modTestsPure*.bas, tools/vba_lint.py(CONTRACT),
  必要なら src/core/modTypes.bas。**src/ui/ は触らない**。

## 受入条件
- `python3 tools/vba_lint.py` ERROR 0。
- `python3 tools/run_lo_tests.py` 全PASS（追加テスト含む）。
- 化けページ圧縮のテスト、空ページのテスト、共有読みコピーの純ロジック部分
  （バッファ組み立て等、切り出せる範囲）のテストがあること。
