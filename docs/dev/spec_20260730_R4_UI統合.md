# 要件定義 R4: チャットバー修正＋マイ本棚/ナレッジ統合（実装: Opus / 起草: Fable 司令塔）

前提: R2(取込コア)・R3(統計バッジ)の実装後に着手。必ず最新の HEAD を読むこと。

## 背景（調査で確定した事実の要約）

### チャットヘッダーの重なり
- 「部門: …」はボタンではなく、ヘッダー背景 `nx_top_bg` のテキストの一部
  (modUINexusDraw.bas:56-68、MarginLeft=82 から幅無検証で伸びる)。
- 右端ピル8個の固定予約幅の合計は 606pt（右から exit30/clear62/sq74/help30/
  theme26/lang92/mode118/speed124 + gap6×7 + 右余白8）。
  Nexusシートのヘッダー実幅 W(A1:M1) は約597pt。**予約が実幅を超えており、
  最内側に積まれる nx_top_speed(⚡すぐ聞く)が必然的にタイトルへ被る**。

### 本棚/ナレッジのボタン見切れ
- 共通クローム modKnowledge.DrawToolbar の折り返しは `rowIdx = 0` のときだけ
  発火し(modKnowledge.bas:174)、2段目で maxX を超えた分は画面外へ描かれる。
  同じ欠陥パターンが発行者ボタン(211)/利用状況(241)/スクショ取込(276)にもある。
  全ボタンが有効な端末の合計幅は約1,068pt。
- modUIShelf は K・L列の幅を設定しておらず(modUIShelf.bas:88-93)、
  DrawChrome の W=Range("A1:N1").Width が機種・履歴依存でぶれる。
- Nexus 以外の画面には ParkFocus(スクロール復帰)が無く、
  水平スクロールバーも Nexus 起動時に消されたまま
  (modUI.bas:67-74, 355-359)。一度右へスクロールした状態が持ち越され、
  利用者に戻す手段が無い。「🗑削除が『除』しか見えない」の主因。

### 統合の材料（そのまま使える事実）
- ギャラリー(modVault)/一覧表(modUIShelf)/みんなの解決事例(modShared)は
  既に modKnowledge.DrawChrome の3モードピルで繋がっており、
  データ源も modShelf.SourceList で100%同一。
  違いは**描画先シートだけ**（一覧=「マイ本棚」シート、
  ギャラリーと解決事例=実行時生成の「Vault」シート）。
- Vault/VaultInput はビルド時 EXPECTED_SHEETS に無い実行時生成シート。
- 参照点の完全リスト（すべて更新対象）:
  modVault.bas:25(GALLERY_SHEET)/723/733(GetGallerySheet系)/795(CloseVault)、
  modShared.bas:26(SHEET_NAME="Vault")、
  modHub.bas:400,411,624-627(OnGoVault)、
  modKnowledge.bas:420-443(OnGoGallery/OnGoTable)/628(RefreshCurrent)、
  modApp.bas:600-608(OnRefreshUI の Case Else)。
- modVault は tools/vba_lint.py の CONTRACT に未登録(変更自由)。
  modUIShelf は required: EnsureLayout, RenderShelf, OnAddFiles, OnSyncNow,
  OnPickFolder, OnExportPack, OnImportPack, OnDeleteSource(維持必須)。

## 変更要件

### A. 統合: 描画先を「マイ本棚」シート1枚に集約(最重要)
1. modVault のギャラリーと modShared の解決事例を、
   **「マイ本棚」シート(modAppDef.SH_SHELF)上に描画する**よう変更する。
   Vault シート(GALLERY_SHEET="Vault")は今後一切作らない。
2. 既存ブックからの移行: マイ本棚系画面の表示時に、旧 "Vault" シートが
   存在すれば On Error 保護付きで削除する(Application.DisplayAlerts 制御込み)。
   VaultInput(登録フォーム)は現状維持(閉じたら veryHidden なのでタブに出ない)。
3. モード切替(ギャラリー/一覧/みんなの解決事例)は既存の modKnowledge ピルを
   そのまま使い、切替時に同一シートを describe→全消し→再描画する。
   各モードの描画冒頭で **A:N の全列幅をそのモードの前提値に明示設定**する
   (現状の「一覧」はK/L未設定、という穴を塞ぐ)。
4. シートタブとして利用者に見えるのは従来どおり
   Nexus/使い方/ホーム/マイ本棚(+ログ類)。**Vault タブは消滅**する。
5. モジュール構成は変えない(modVault/modShared は「マイ本棚シートに描く
   ギャラリー描画エンジン」として存続)。モジュール名変更・統廃合はしない。

### B. 画面表示の共通儀式(見切れの恒久対策)
「マイ本棚」「Hub」を表示・再描画する入口
(modUIShelf.EnsureLayout / modVault.ShowVaultGallery / modShared.Show /
 modHub.EnsureHubLayout の activate 経路)で、以下を必ず行う共通ヘルパを
modUI(または modKnowledge)に1つ作って全入口から呼ぶ:
- ActiveWindow.ScrollColumn = 1 / ScrollRow = 1(On Error 保護)
- ActiveWindow.Zoom = 100
- DisplayGridlines/Headings の既存制御は維持

### C. ツールバーの完全折り返し(modKnowledge)
- DrawToolbar と後続の発行者/利用状況/スクショ取込ボタンの配置を、
  **1本の流し込みレイアウト**に統一する: 「次のボタン幅が maxX を超えるなら
  行を1つ増やして x=L+8 に戻す」を段数無制限で行う共通ロジック。
  `rowIdx = 0` 限定のガードは全廃(4箇所)。
- 行数が増えた場合にカード領域の開始行が重ならないよう、ツールバーの
  実使用高さを返し、下の描画開始位置がそれを使うこと。

### D. チャットヘッダーの予算内配置(modUINexusDraw)
- 右端ピル群を「幅予算」を持つ配置に変える。要件:
  1. タイトル(💬 チャット + 部門ラベル)のために **最低280ptを確保**する。
  2. 残り幅に右端ピルが収まらない場合、あらかじめ定義した
     コンパクト表記(例: lang「🌐」30 / mode「🔎」30 / speed「⚡すぐ」56 等)へ
     自動的に切り替えて必ず収める。どうしても収まらない分は
     ヘッダー直下の2段目(同じ濃色帯を1行分追加)へ右詰めで流す。
     どちらの方式を採るかは実装者が選んでよいが、
     **「W がいくつでも重ならない」ことをコードで保証**すること
     (固定幅の合計と W の比較がコード上に存在すること)。
  3. 部門ラベルは利用可能幅に収まるよう文字数で切り詰め(超過時は「…」)。
- ボタンの機能・OnAction は一切変えない。

### E. チャット取込結果の正直な報告(modApp.OnAddDocs)
- R2 で modShelf に追加された「結果を返す口」(AddFilesViaDialog の
  Function 版。R2実装の報告と最新コードを確認して正確な名前を使う)を使い、
  TotalChunks 差分判定をやめる。
- チャットバブルの文言を結果別に:
  - 新規追加あり: 現行の成功文言を維持
  - 全件が既存と同一内容(重複0追加): 「その資料はすでに本棚に入っています」
  - 同名衝突(E0504): 別の場所から同名資料が登録済みである旨と対処
  - 画像PDF(image_pdf): スクショ取込への誘導
  - その他失敗: 「N件取り込めませんでした。マイ本棚の状態欄をご確認ください」
- MsgBox とチャットバブルの二重報告をやめる(チャット経由では MsgBox を
  出さない。R2 が用意したフラグを使う)。

### F. 導線の整合
- modHub.OnGoVault(ナレッジ倉庫)はマイ本棚シート上のギャラリーモードを開く。
  Hub のナビカード文言に「ナレッジ倉庫」と「マイ本棚」が併存して
  紛らわしければ、「📚 ナレッジと本棚」等の1枚に統合してよい
  (ボタン数が減る分は縦積みなので崩れない)。
- modApp.OnRefreshUI の Case Else / modKnowledge.RefreshCurrent の
  フォールバック先をマイ本棚シートの現行モード再描画に変更。
- 起動時(modBoot)の EnsureLayout 群は現状維持(マイ本棚は既に起動時構築)。
