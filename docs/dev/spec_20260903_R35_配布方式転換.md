## 2. 裁定の各論

### 2-1. `--vba-mode`（既定 `baked`）

- `build_mybookshelf.py --dev/--prod` に `--vba-mode {baked,installer}` を足し、**既定を `baked`** にする。
- `installer` は**1リリースだけ**残す開発用フォールバック。`--zip` との併用は BuildError（AMSI 検知済みの形を配布経路に乗せない）。次ラウンドで削除。
- **波1 の報告で判明した退行（波2 で直す）**: `modInstallCheck.VI` を削除したため、`_INSTALLER_SRC_TEXT` の `f = f + Application.Run("modInstallCheck.VI")` と直後の `If Err.Number <> 0 Then f = f + 1` が実機で常に失敗し、installer モードは「Setup NG」に落ちる。この2行を削る（`f>0` の Add 失敗検出は残る）。圧縮後サイズが縮むので `pad_to_exact` の到達不能差分 {1,2,4,7} に当たったら、インストーラ内の文言を1〜2バイト調整して合わせる（既存の作法）。
- 出力ファイル名は変えない（`dist/MyBookshelf.xlsm` 等）。`dist/` 配下のコミット禁止は不変。

### 2-2. ThisWorkbook（document module）の中身

```vba
Option Explicit
Private Sub Workbook_Open()
    modBoot.Boot
End Sub
Private Sub Workbook_WindowResize(ByVal Wn As Window)
    On Error Resume Next
    modViewport.OnWindowResized
End Sub
```

- `modBoot.Boot` を**直接呼ぶ**（`Application.Run` ではない）。理由: 全モジュールが最初から入っているので遅延結合の必要が無く、コンパイル不能なら `Workbook_Open` の時点で見える方が良い。`src/ui/ThisWorkbook.cls` と同じ形で LO コンパイル検査を毎回通っている。
- **`Workbook_BeforeClose` は入れない。** 現行本番の ThisWorkbook にも無く、終了処理は Excel が自動で呼ぶ `modBoot.Auto_Close`（標準モジュールの Auto_Close）が担っている。BeforeClose から `Auto_Close` を呼ぶと**二重実行**（テレメトリ送信・OnKey 解除が2回）の縫い目を作る。取込中の×確認（`ConfirmCloseDuringIngest`）が本番で効かないのは現行と同じ＝**今回は変えない**（記録のみ §7）。
- `Application.OnTime` 経由をやめる副作用: 名前入力の `InputBox` が `Workbook_Open` の同期文脈で出る。これは `RunFirstRunPromptEarly` が狙っていた状態そのもの（`modBoot.bas:577-590` のコメント）。`RunFirstRunPromptEarly` は未使用になるが**凍結 modBoot には触らない**。

### 2-3. `vba_src` シートの廃止

- `EXPECTED_SHEETS` から `vba_src` を外す（`installer` モードのときだけ足す）。`_make_vba_src` は installer モード専用として残す。
- `vba_src` を実行時に読む箇所は src 全体で3つ。**いずれも `On Error Resume Next` 下でシート不在を無害に通す**（本日確認済み）ので、凍結 modBoot に手を入れない:
  - `modBoot.CancelPendingInstallerBoot`（`modBoot.bas:94-97`）: `Set w = Worksheets("vba_src")` が失敗→`w Is Nothing`→Exit

  - `modInstallCheck.VI`: 方式Bでは誰も呼ばない（2-4 で削除）

### 2-5. CP932 に無い文字（riskconsulting と方針が違う点。理由を明記）

- 実測: src に341箇所（`—` U+2014 が41、以下絵文字）。**全部コメント内で、実行文には0。**
- 裁定: **コード行は lint ERROR（既存 `check_cp932_safe`）、コメントはビルド時に `?` へ置換**（`errors="replace"`）。
- riskconsulting は「コメント含め lint ERROR・一括置換してから焼く」を採っている。MyBookshelf で同じ道を採らない理由:
  1. 凍結5本（modAsk/modBoot/modShelf/modRetrieve/modPrompts）のコメントも触ることになる
  2. 容量逼迫モジュール（modBoard 残19字 等）で1文字→複数文字の置換は上限を割る
  3. 現行の VBE（`AddFromString` 経由）も CP932 外の文字を `?` に落としており、**配布物の中身は今と同一**
- 自己検証は「置換した文字数」を報告する。**初期値は 330**（波1 完了時のビルド実測。09-03 午前の「341」は modInstallCheck 手術前かつ「行×文字種」の数え方だったので不一致は当然。以後は 330 を基準にする）。lint ERROR 0 が前提なので、置換は構造的にコメントにしか起きない。

## 9. `Documents` が消えない場所かを1分で確かめる手順（ユーザー向け）

1. エクスプローラーで左の「ドキュメント」を開く
2. 上のアドレス欄をクリックして、出てくるパスを見る
   - `C:\Users\<番号>\OneDrive - <会社名>\ドキュメント` のように **OneDrive を含む** → 同期あり。**シャットダウンしても残る**（ファイルに雲や緑チェックの印も付く）
   - `C:\Users\<番号>\Documents` で OneDrive を含まない → 同期なし。D: と同じで消える可能性があるので、空のテキストファイルを1つ置いてシャットダウン→翌朝確認
3. パスをそのまま（番号は伏せて）司令塔へ
