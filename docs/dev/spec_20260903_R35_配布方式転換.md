## 2. 裁定の各論

### 2-1. `--vba-mode`（既定 `baked`）

- `build_mybookshelf.py --dev/--prod` に `--vba-mode {baked,installer}` を足し、**既定を `baked`** にする。
- `installer` は**1リリースだけ**残す開発用フォールバック。`--zip` との併用は BuildError（AMSI 検知済みの形を配布経路に乗せない）。次ラウンドで削除。
- **波1 の報告で判明した退行（波2 で直す）**: `modInstallCheck.VI` を削除したため、`_INSTALLER_SRC_TEXT` の `f = f + Application.Run("modInstallCheck.VI")` と直後の `If Err.Number <> 0 Then f = f + 1` が実機で常に失敗し、installer モードは「Setup NG」に落ちる。この2行を削る（`f>0` の Add 失敗検出は残る）。圧縮後サイズが縮むので `pad_to_exact` の到達不能差分 {1,2,4,7} に当たったら、インストーラ内の文言を1〜2バイト調整して合わせる（既存の作法）。
- 出力ファイル名は変えない（`dist/MyBookshelf.xlsm` 等）。`dist/` 配下のコミット禁止は不変。

### 2-2. ThisWorkbook（document module）の中身

```vba
Option Explicit
Private Sub Workbook_WindowResize(ByVal Wn As Window)
    On Error Resume Next
    modViewport.OnWindowResized
End Sub
```

- **`Workbook_Open` は持たない（09-03 レビュー班B MAJOR-2 で裁定変更）。** 起動は旧方式と同じく Excel が自動実行する **`modBoot.Auto_Open`**（`modBoot.bas:75`）が担う。旧方式でも実際の起動経路は Auto_Open で、インストーラの OnTime 予約は Auto_Open→Boot の `CancelPendingInstallerBoot` が取り消していた。09-03 午前の案（`Workbook_Open → modBoot.Boot`）は Auto_Open と合わせて **Boot が2回走り**（2周目は `gBootDone` 分岐で3画面を再描画し、共有フォルダへ実I/Oを打つ）、R8 F3 の「起動中に共有I/Oを走らせない」設計を破る。
- Auto_Open は VBA からの `Workbooks.Open` では走らないが、利用者経路（ランチャー bat／ダブルクリック）では必ず走る。旧方式と同じ前提であり、新しい前提ではない。
- **`Workbook_BeforeClose` は入れない。** 現行本番の ThisWorkbook にも無く、終了処理は Excel が自動で呼ぶ `modBoot.Auto_Close`（標準モジュールの Auto_Close）が担っている。BeforeClose から `Auto_Close` を呼ぶと**二重実行**（テレメトリ送信・OnKey 解除が2回）の縫い目を作る。取込中の×確認（`ConfirmCloseDuringIngest`）が本番で効かないのは現行と同じ＝**今回は変えない**（記録のみ §7）。
- `Application.OnTime` 経由をやめる副作用: 名前入力の `InputBox` が Auto_Open→Boot の同期文脈で出る（旧方式でも Auto_Open→Boot が本経路だったので同じ）。`RunFirstRunPromptEarly` は未使用になるが**凍結 modBoot には触らない**。
- **初回の名前が保存されない退行（レビュー班B MAJOR-3・裁定）**: 旧方式は Install が `ThisWorkbook.Save` していたので `pack_author` はその場でディスクに残った。方式Bでは Boot は保存しないため、初回に名前を入れて「保存しない」で閉じると次回また聞かれる。→ **`modSetupWizard.RunFirstRunWizard` の末尾（`SaveState WIZARD_DONE_KEY` の直後）で1回だけ `ThisWorkbook.Save`**（`On Error Resume Next` 下・ウィザードが実際に走った回だけ）。名前・部門・共有パス・ウィザード済み印が同時に残る。凍結 modBoot には触らない。読み取り専用で開かれた場合は Save が失敗して従来どおり（無言）。

### 2-5. CP932 に無い文字（riskconsulting と方針が違う点。理由を明記）

- 実測: src に341箇所（`—` U+2014 が41、以下絵文字）。**全部コメント内で、実行文には0。**

- 自己検証は「置換した文字数」を報告する。**初期値は 330**（波1 完了時のビルド実測。09-03 午前の「341」は modInstallCheck 手術前かつ「行×文字種」の数え方だったので不一致は当然。以後は 330 を基準にする）。lint ERROR 0 が前提なので、置換は構造的にコメントにしか起きない。

### 10-1. F3a: パック取込・引き継ぎ読み込みの Open 失敗（層2・原因一意）

**原因**: この端末は「`Workbooks.Open` に `Password:=` 引数を付けると、**保護されていないファイルでも Open が失敗する**」型（2026-07-29 実機事故と同型。`spec_20260815_R33_全体監査.md:214`・`audit_20260815:2577` が「引き継ぎ読み込みも同じ端末で必ず失敗する」と予告済み）。`modExtractorExcel`（Excel資料の取込）には「引数なしで再試行」の保険があるが、`modPack.ImportPackFile`（R27波3-3）と `modMigrate.ImportUserData` は**ダミー Password 付きの1回だけ**で開いており、この端末では必ず失敗する。**部門正典の自動受け取り（`modChannel:302`）も同じ関数を通るので、部門ナレッジ配信がまるごと届かない。**

**裁定**: 「保護ファイルで入力ダイアログを出さない」目的は **Open の前に先頭4バイトで判別する**ことで達成し、Password 引数は使わない。
1. `kind = modShelfScan.EncryptedFileKind(path)`（既存・R33 W3-11・純ロジック `EncryptedByHeader` はテスト済み。modPack は既に ingest 層の `modShelf`/`modShelfStore` を参照しているので層規約に反しない）
2. `kind = "enc"` → **開かずに** E0701。文言「このファイルはパスワードで保護されています。保護を外したものを受け取ってください」

### 10-2. F3b: ランチャー往復（R36(a) を前倒し・層1・ユーザー要望「書き戻しを忘れる余地を無くしたい」）

**前提（09-03/04 確定）**: D: は信頼できる場所だがシャットダウンで消える／OneDrive 同期フォルダは消えないが信頼できる場所ではなく、Excel が開くと `ThisWorkbook.Path` が `https://…` の URL になりうる（Ghostscript の隣探し・`Dir()` 走査が静かに空振りする）／OneDrive を信頼できる場所に追加するのは組織ポリシーで不可。
**裁定**: 「動かす場所は D:、消えない置き場は OneDrive」。複製と書き戻しは **bat が自動で行い、利用者は OneDrive にある bat を押すだけ**。VBA は1行も変えない。

`build/build_mybookshelf.py` の `_launcher_bat_text` を次の設計に置き換える（CP932・CRLF・`chcp` 無し・`setlocal`）:
1. `SRC=%~dp0`（bat の場所＝OneDrive 側の原本フォルダ）、`DST=D:\MyBookshelf\`。**`SRC` と `DST` が同じなら複製も書き戻しもせず従来どおり起動だけ**（D: に全部置く運用も壊さない）。`D:` が無い端末は従来どおり `SRC` から起動（メッセージは出さない）。
2. `DST` を作り、`xcopy "%SRC%MyBookshelf.xlsm" "%DST%" /D /Y /Q`（**新しい方を採る**: 前回書き戻せなかった D: 側が新しければ上書きしない）。`Ghostscript\gswin32c.exe` が `DST` に無ければ `Ghostscript` フォルダを複製。
3. 起動は別 cmd で `start "" /wait excel.exe /x "%DST%MyBookshelf.xlsm"` を走らせ、終了で `%DST%.closed` の印を置く（他の Excel が開いていても自分の Excel だけを待てる。プロセス名では見分けられない）。
4. 本体は 10分ごとに `copy /Y "%DST%MyBookshelf.xlsm" "%SRC%MyBookshelf.xlsm"`（Excel が開いていても読み取りコピーは通る。Excel は保存を一時ファイル→リネームで行うので途中状態を掴みにくい）。印が現れたら**最終書き戻し**: 先に `SRC` の現行を `MyBookshelf_前回.xlsm` へ退避してからコピー。失敗したら 3回リトライ→それでも失敗なら「OneDrive へ書き戻せませんでした。D:\MyBookshelf\MyBookshelf.xlsm を手で OneDrive へコピーしてください」と表示して `pause`。
5. `%~dp0` に空白・日本語を含む（OneDrive - 会社名）ので全パスを引用符で囲む。
- **繋ぎ目**: (a) 10分コピーが OneDrive の同期と競合して `MyBookshelf-<PC名>.xlsm` の競合コピーができうる → 記録のみ（書き戻し先は同じファイル名1本・OneDrive 側は誰も開かない前提）。(b) 開いたままシャットダウンした場合、最後の10分コピー以降が消える（許容・README に明記）。(c) `xcopy /D` は秒単位の比較＝同時刻なら上書きしない。(d) README 【1. 開き方】を「OneDrive のフォルダに展開し、その中の bat を押す。D: は自動で使われる」に書き換え、docs/00・20・70 も追随。(e) 当環境では bat を実行できないので、**実機で1往復（複製→起動→取込→閉じる→OneDrive の xlsm が更新され `_前回` ができる）を確認するまで配布しない**。
- **F3b 実装後の司令塔差し戻し（09-04）**: (1) 黒い画面がカウントダウン表示のまま開きっぱなし→入口プロセスは `start /min` で最小化した別プロセスに全工程を渡して即終了・待機プロセスも最小化・タイトルに「閉じないでください」 (2) `timeout 600` のループでは閉じてから最大10分待たされる→30秒監視・20回に1回書き戻し (3) `if not exist "D:\"` → `if not exist D:\nul`。
- **記録のみ（R36）**: D: はあるが書き込み権限が無い端末では `mkdir`/`xcopy` が黙って失敗する（今は未規定）／複製先が固定名 `D:\MyBookshelf\` なので、同一端末で dev 版と本番版を同時に置くと取り合う（1端末1バリアントの通常配布では問題なし）／利用者が最小化された黒い画面を閉じると書き戻しが止まる（次回起動時に D: 側が新しければ `xcopy /D` が上書きしないので、次に正しく閉じた回で追いつく）。
- **`ghostscript_path` は使わない**（OneDrive からの exe 実行は Files On-Demand・AppLocker で不安定。D: に複製する方が確実。14MB の複製は初回だけ）。
- **環境変数で OneDrive を指す案は不採用（09-05 実機実測・Windows 11 24H2 build 26100.3194）**: `echo %OneDriveCommercial%` → **未定義**（打った文字がそのまま返る）／`echo %OneDrive%` → **`C:\Users\win11admin\OneDrive`＝ログオン利用者（`C:\Users\2104520`）とは別の利用者のフォルダ**（端末のマスターイメージ作成時の値が全体に焼き付いていると推定）。したがって `%OneDrive%` を bat の書き戻し先に使うと**他人のフォルダへ書きに行く**。bat が「bat を置いた場所（`%~dp0`）」を原本とする現行設計は正しく、環境変数へは切り替えない。R36 のデータブック分離でも同じ（置き場所は利用者が bat を置いた場所で決める）。姉妹PJ riskconsulting へも共有。
