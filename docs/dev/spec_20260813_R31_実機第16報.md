## 確定した事実(調査で裁定)

### F-A: ツールチップクリック不能の機構(確定)
- modKnowledgeBar.ToolButton L360-367 の `ws.Hyperlinks.Add Anchor:=btn, Address:="", SubAddress:=自セル, ScreenTip:=tipText` が原因。
- **ExcelのShapeではHyperlinkがOnActionに優先し、クリックはリンク追随(自セル選択)に食われてマクロ不発**。L311-313のコメント「OnActionが優先」は実機で反証された誤記。
- ScreenTipが出る=Hyperlinkが生きている、クリック無反応=OnActionに届かない、で症状と完全一致。
- 掃除波不要: HyperlinkのAnchorはShape本体で、modKnowledge.RemoveChrome(L485-509)が毎描画で nxk_ Shapeを全削除→再描画のため、コードからHyperlinks.Addを消せば次の1回で残留も消滅。
- 技術的回避(Hyperlink維持+クリック共存)は**無い**と断定(FollowHyperlinkイベントはシートモジュール必要=配布形態と不整合、透明Shape重ねはホバーとクリックを分離できない)。
- **LO死角の新種**: Hyperlink付きShapeのOnAction死はLOで検出不能。CLAUDE.mdの死角リストへ追記する。

### F-B: 余白3画面の機構(前提転換・2回ルール適用)
- Hub(ホーム)/Dashboard/マイ本棚とも**FreezePanes無し・ScrollArea設定経路は全遷移で必ず通る・解除経路ゼロ**。にもかかわらず余白がある。
- **最有力(d)説: R29の「ScrollAreaはホイールを止める」が誤帰属。ホイールの実際の停止線は焼き付いたUsedRange末尾**。
  - Hub: modHub.bas L90 `Rows("1:40").RowHeight=15`(毎描画600pt≒1画面弱)
  - Dash: modDash.bas L269 同型40行
  - 本棚: mShelfRowHighがセッション毎に0リセット→ShelfRowHighフォールバック SHELF_MAX_ROW=412 → NormalizeShelfRows/ClearCardAreaが**毎セッション初回に7:412(約6,090pt≒8画面)を焼き付け**
  - ResetRowsBelow(UseStandardHeight)は焼き付きを**解放していない**(R30確定法則: Rows.Deleteが唯一の即時解放。UseStandardHeight解放主張=modViewport.bas L369-371は未実証でR30法則と矛盾)
  - 症状の規模感(Hub/Dash=小さい余白、本棚=大きい余白)と焼き付け深度が整合。R30のNexus根治がScrollAreaでなくRows.Deleteで効いた事実とも整合。
- 修正はどのみち安全側: 焼き付きを削除すれば、ScrollAreaがホイールを止めていようがいまいが停止線=コンテンツ末尾+αになる。

### F-C: 配置ズレの機構(確定)+管理者ページ材料
- ツールバー=固定幅左詰め(ComputeToolbarLayout→FlowLeft(L+8, L+W-8, gap5))、ヘッダーピル=FlowRightでL+W-8右端密着。構造非対称でΔ=13〜360pt超が構成・窓幅で変動。
- 発行者構成でW=1000のときスクショ取込だけ2段目に孤立(右に約900pt空白)する折り返しも「中途半端な余白」の一因。
- 管理者ページ: build_mybookshelf.py `_make_howto`(L859-1195)と同型でVBA容量ゼロ。EXPECTED_SHEETS/TAB_COLORS追加必須(忘れるとビルド自己検証が停止)。一次資料=docs/70_データ管理者向け_置き場所と運用.md §B + modPublish/modChannel設計コメント。
