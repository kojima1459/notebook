## Fix-A(重大・先行)

FA-1【A-H1/B-H1 確認ダイアログが全経路で死んでいる】
  modShelf.IngestFile に Optional ByVal interactive As Boolean = False を追加し、
  modShelfBatch.AddFilesResult(:409)からのみ True を渡す。TryVisionFallback へ伝播し、
  :128 の条件を interactive 基準に(silent はモーダル抑止の意味のまま温存)。同期経路は
  従来どおり無確認。MsgBox に vbMsgBoxSetForeground(&H10000)を追加。確認文言末尾に
  「(完了後に検索用の準備が続きます)」を追記(B-M: 埋め込み時間の正直さ)。

FA-2【A-H2/B-H2 チェックポイントが途中でディスクに落ちない】
  optOcrCache.SaveRange の書込み成功直後に modShelfBatch.SaveCheckpoint を呼ぶ。
  SaveCheckpoint に Optional throttleSec(既定0)を追加し、この経路は120秒スロットル
  (前回保存から120秒未満なら黙って戻る)でEDR負荷を抑える。

FA-3【A-H3/A-M3 同期×中断で残資料のmanifestが恒久汚染】
  modShelfSync: (i)ファイルループ先頭で modShelfBatch.CancelRequested()→Exit For
  (残りは manifest に触れず見送り。同期サマリへ「中断のためN件を見送りました」)。
  (ii)Finish: で ResetCancel。(iii)silent 時の見送り判定に modShelf.IsBusy() を追加
  (取込中の入れ子自動同期を止める=バナー削除・フラグ消去の事故も同時に閉じる)。
  (iv)入口の ResetCancel は modShelf.IsBusy()=False のときのみ。
  ※modShelfSync の変更許可を本件に拡大。28,000字未満はコメント同量圧縮で維持。

FA-4【A-H4/B-M メモ合成の契約一本化】
  optOcrEta に純関数 ComposeOcrMemo(resumeHead, partialBody, capBody) を新設し、
  「resume冒頭文は前置・置換禁止」「partial(全N頁中M頁…totalKnown引数化)とcap(上限…)は
  連結」を1箇所で保証。optOcrPage:405/optVision.OcrCapMemo の置換ロジックを廃止して
  これに寄せる。復元のみで完了(fresh=0, truncated=False)でもカードへ届くよう
  modShelfVision:153 を「truncated Or メモ非空」に。0頁中断の文言は
  OcrAbortMemoFor(0,"cancel",optOcrCache.HasSaved()) を使用(「最初から」と断言しない)。
  ゴールデンテスト追加(復元+cap打切り/復元のみ完了/部分失敗+capの3連結)。

FA-5【B-H3 画像化・ベクトル化フェーズで中断が効かない】
  (i)optGsTxt.WaitForDoneFlag ループに CancelRequested 確認+毎秒 StageBanner
  「画像化中… バッチb/B (全N頁) 経過s秒」。中断時は早期 False 復帰し、呼び出し側
  (OcrPdfByBatch)は RenderBatch 戻り直後に CancelRequested を先に確認して
  abortReason="cancel" に倒す(timeout と混同しない)。
  (ii)modEmbed のチャンクループ先頭に CancelRequested→Exit For(既存ESC中断と同じ
  後始末=abortReason 経由の partial・embedded=0 再開に乗せる)。
  (iii)optOcrEta.GsBudgetSec に1バッチ上限 max(120, BATCH_PAGES*16) 秒を追加。

FA-6【A-M4/B-H4 中断ボタンが無関係バナー全部に生える】
  modSkin.PaintProgress に Optional cancellable As Boolean = False を追加し、
  取込経路(modShelfBatch.StageBanner / AddFilesResult / SyncNow ループ)のみ True。
  modShelf.IngestFile 入口(ガード判定直後)に ResetCancel(modVault/modUIShelf 直接経路の
  幽霊中断対策)。

FA-7【A-M5/B-H5 1件だけ中断で「完了しました」】
  modShelfBatch: cancelHit を別変数で保持(ループ後にも CancelRequested を確認)し、
  中断があれば「中断しました(成功N件/失敗M件/見送りK件)」のトースト/モーダルへ。

FA-8【B-M 中断フィードバック不可視+ビート整理】
  OnCancelIngest: SetStage→ShowProgress へ(全画面で見える)。文言は「中断しています…
  現在の処理が終わり次第停止します」(「頁」と言わない)。TouchBusy 呼び出しを削除
  (ビートは実作業由来に統一)。CancelRequested 中は optOcrPage の頁バナー上書きを
  スキップ(中断実況を消さない)。

FA-9【A-M2 絶対上限480分が8時間超の正当バッチで二重取込を開く】
  FA-8 により全ビート源が実作業となるため、GuardExpiredNow は absLimitMin:=0
  (ビート基準のみ)へ変更。GuardExpired の引数・純テストは維持(真理表は0=無効を含む形へ)。

## 記録のみ(採用せず・理由つき)
- 複数の大型PDFで確認が複数回出る: N は抽出(GS分類)後にしか判明せず事前一括確認は構造上
  不可。頻度が低く、1回ごとの確認が正。
- 手動同期は確認なしで長時間OCRが走り得る: silent 設計(R11-A C4)に従う。自動同期は既定
  OFF、チェックポイントで被害限定済み。HANDOFFに記載。
- 確認ダイアログ表示中は他ファイルの取込も停止する: モーダルの性質上不可避。
  vbMsgBoxSetForeground で放置リスクを低減。
