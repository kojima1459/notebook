### R33-02 [MAJOR] ✅裏取済 modPii: 全角数字の電話番号を検知できず、部内共有へ素通りする
- 場所: `src/pack/modPii.bas:82` / 発見班: LH1-core古参
- 機構: HasLongDigitRun の数字判定は `If ch >= "0" And ch <= "9"` という文字列比較で、modPii.bas には Option Compare 文が無いため既定の Binary（文字コード比較）になる。全角数字０-９は U+FF10〜U+FF19（65296〜65305）で "9"(57) より大きいので `ch <= "9"` が False になり、Else 節へ落ちてランが【リセット】される。さらに区切り文字として認めているのは半角"-"・半角スペース・U+2010 の3つだけで、日本語IMEが実際に出す全角ハイフンは U+FF0D（全角ハイフンマイナス）・U+2212・U+30FC であり、どれも一覧に無い。コメントは「全角相当のハイフン(U+2010)」と書いているが U+2010 は日本語入力ではまず生成されない文字。加えて HasEmailPattern も `s Like "*[A-Za-z0-9.]@[A-Za-z0-9.]*"` で半角ASCIIの@と前後半角英数を要求するため全角＠のアドレスも通らない。src配下151本を grep したが StrConv/vbNarrow による半角正規化は【1箇所も存在しない】ので、走査前に半角へ均される経路も無い。
- 再現: 日本語IMEを全角のまま（Japanese Windowsの既定状態の一つ）質問を打つ。例:「田中様の携帯　０９０－１２３４－５６７８ に折り返す手順は?」と入力し、この語彙が本棚に無くて検索0件になる。0件は modInsightIo.EmitGap(bas:92) を【利用者の操作を介さず自動で】発火させ、唯一の関門が modInsightGate.PiiBlocked→modPii.ScanText。全角数字は1桁も数えられずランは常に0のまま、全角－も区切りに該当しないので HasLongDigitRun=False、＠も無いので HasEmailPattern=False → ScanText は空文字を返し PiiBlocked=False。

### R33-04 [MAJOR] ✅裏取済 modConfig.GetBool だけが既定値へ落ちず、読めない値を常に False にする
- 場所: `src/core/modConfig.bas:109` / 発見班: LH1-core古参
- 機構: 同じファイルのヘッダ(39-45行)が「『既定値へ落ちる』という契約を、どんな入力でも守り切る」と宣言し、GetString/GetLong/GetDouble は実際にその分岐を持つ（GetLong:66-67 の `ElseIf Not IsNumeric(v) Then GetLong = defaultValue`）。しかし GetBool にだけ相当する分岐が無い。Empty/エラー値は既定値へ落ちるのに、【非空で解釈不能な文字列】は最後の Else に落ち、"true"/"1"/"yes"/"on" のどれにも一致しないので defaultValue を無視して無条件に False を返す。LCase$ は Unicode の大小変換しかしないので全角ＴＲＵＥは "ｔｒｕｅ" にしかならず "true" と一致しない。呼び出し側は Boolean 1個しか受け取らないため「明示的に FALSE だった」のか「読めなかった」のかを区別できず、事後に補正することが原理的に不可能。
