# Nexus Agent — 実装の時系列(フェーズ別サマリー)

全128コミットの詳細は `git log --oneline` を参照。ここでは開発の流れを
フェーズ単位で要約し、「今のアーキテクチャがどう出来上がったか」を
追える形にする。

## フェーズ0: 前史(V1試作・現在は破棄)

初期のプロトタイプ(UserForm UI、Gemini/Azure OpenAI直叩き、vbaProject.bin
の手動バイナリパッチによる自己インストーラ実験)。ここで確立された
「自己インストーラ方式(ThisWorkbookが`vba_src`シートからモジュールを
動的注入)」は現在も中核技術として継続している。

## フェーズ1: V2チャットボット(現在は別リポジトリ`notebook`のmainブランチへ分離)

社内AIリボン経由のRAGチャットボット第2弾。ルーティング・引用フィルタ・
続けて質問等を実装。**このプロダクト(Nexus Agent)とはコードを共有せず、
設計の教訓のみを引き継いでいる**別プロダクト。

## フェーズ2: マイ本棚AI(Wave0〜Wave5) — 本プロダクトの起点

`docs/dev/MASTER_SPEC.md`(実装契約書v1.0)を起点に、複数エージェントの
並列実装(Wave1: 基盤8モジュール → Wave2: 機能24モジュール → Wave3: 整合
修正+テスト → Wave4: 敵対的レビュー15件修正 → Wave5: ドキュメント+初回
ビルド)で3画面UI(ホーム/マイ本棚/ダッシュボード)版を完成させた。
`vba_lint.py`(静的解析)と`run_lo_tests.py`(LibreOffice構文コンパイル)の
2層テストハーネスもこのフェーズで確立。

## フェーズ3: 実機報告への追従修正

Windows実機での初回テストで見つかった不具合(`ReDim(0 To -1)`の実行時
エラー、モジュール名衝突、ネットワーク共有ファイル取込失敗、画面描画
失敗が起動全体を巻き込む問題等)を修正。**この時期に「1画面の描画失敗が
アプリ全体を止めない」という設計原則が確立**され、以降の全機能が
`On Error Resume Next`によるブロック単位の障害隔離を踏襲している。

## フェーズ4: RAG全面再設計 + Nexus Agent(SPA UI)始動

- RAGパイプラインをPlan B(768次元埋め込み+direct Azure API経路)へ全面
  再設計、NotebookLM級の多段パイプライン(拡張→マルチクエリ→再ランク)を導入。
- 「Nexus Agent」= Shape描画によるSPA風チャットUIへの刷新を開始
  (`modUI.bas`新設)。3画面UIから段階的に移行(`nexus_ui`configで切替可能。
  現在は既定TRUE)。

## フェーズ5: ゲーミフィケーション基盤

EXP/レベル、Vaultナレッジ倉庫ギャラリー、Nexusダッシュボード(KPI/バッジ)、
K-Meansナレッジ地図(`modCluster`)、ガバナンス分析CSV(`modAnalytics`)を
順次実装。

## フェーズ6: Phase4 P2P基盤

AD連携ユーザーID、パック出所タグ付け(`origin=pack:<作者>`)、感謝状の
発行・受領によるEXP交換(自己申告不可の設計)、共有フォルダI/Oのリトライ
耐性(エラー70対策)とGC、ナレッジ自浄(ノイズ論理除外)エンジン、固定UIの
Z-Order維持、状態永続化(記憶喪失対策)、P2Pノイズ集計(組織的グローバル
除外)+管理者による透明性確保・復帰UI。**この時期にP2Pのファイルベース
協調パターン(collect-then-process/1ファイル1権利)が確立**された。

## フェーズ7: セキュリティ・堅牢性の連続監査

3回の独立監査を実施し、それぞれ修正コミットを積んだ:

1. **Red Team自己監査(Phase1/Phase2)**: 数式インジェクション二重封鎖、
   noise台帳GC、4つの盲点封鎖。
2. **UI/UX 7大穴監査**: 連打・多重発火・グローバルロック・クリップボード
   実機耐性。
3. **SRE/カオスエンジニアリング監査**: MAX_PATH制限・AVロック耐性・
   沈黙欠損の可観測化(環境依存バグ)。
4. **Endgameバグバウンティ監査**: 画面暗転ロックアウト・別ブック誤爆・
   並行GC競合の封鎖。

これらの発見事項は `docs/dev/EDGE_CASES.md` に集約・体系化されている。

## フェーズ8: デザインシステム刷新

MS&ADグリーン基調・Yu Gothic UI・柔らかいドロップシャドウ・Toast通知
(MsgBoxのハイブリッド代替)・Empty Stateへの刷新。「Excel感・Windows95感」
の払拭を目的とした一連の視覚ポリッシュ。

## フェーズ9: 検索の高速化(狂気案Lv.1)

バイナリ量子化(符号ビット)+XORハミング距離による粗選別を、既存のFloat
コサイン検索を1バイトも変えずに追加(`modBitwiseOpt`、完全独立モジュール)。
大規模ナレッジ(数万〜10万件)でも高速な検索を実現するオプトイン機能。

## フェーズ10: 出典照合・専門家紐付け(Peek View / Mentor)

- **Peek View**: 出典チップのワンクリックで元チャンク本文をポップアップ
  表示。ハルシネーションの人間による即検知を可能にする。
- **Mentor**: 回答の出所タグから専門家を自動特定し、質問を直接送れる
  ボタンを表示。送信→受信→返信の往復ループまで実装。

いずれも「新規モジュール+1行フック+サーキットブレーカー」という
疎結合プラグイン方式で実装され、これが以降の全機能追加の標準パターンに
なった(`docs/dev/ARCHITECTURE.md` §4参照)。

## フェーズ11: 組織エコシステム化

オンボーディングツアー(`modTour`)、ヘルプ(`modHelp`)、チーム連帯ボード
(`modBoard`: 個人+組織全体の節約時間、感謝受領数ベースの称号)、Mentor
返信機能、会話の記憶(次回起動時の復元)を実装。

## フェーズ12: 回答品質のNotebookLM化

VBAの通信ロジックを一切変えず、LLMへのシステムプロンプトのみを改修
(`modPrompts.StyleInstruction`)。ペルソナ定義・意図の深読み・結論先行
(BLUF)・プレーンテキストでの視覚的整理(Shape描画はMarkdownを装飾
しないための独自記法)・One-Shot模範解答を導入。

## フェーズ13: UX最終改修 + 依存性を生む仕組み

ホットキー召喚(Ctrl+Shift+Q)・Ctrl+Enter送信・考え中バブル・
フレンドリーエラー文言・ご意見箱(EXP付きバグバウンティ)・P2P接続設定UI・
遊び心(時間帯挨拶・関西弁の隠し味)を実装。続けて、称号連動の解放スキン
(サクラ/オーシャン/ゴールド)・質問テンプレチップ・連続起動ストリーク
表示・ナレッジガチャを追加し、「きっかけ→行動→報酬→再投資」の習慣
ループを完成させた。

## フェーズ14: リポジトリ分離(本ドキュメント作成時点)

`notebook`リポジトリの`mybookshelf/`サブディレクトリから、独立ブランチ
`product/nexus-agent`(将来的に独立リポジトリへ移行想定)へ切り出し。
仕様書・設計書・ER図・エッジケースカタログ・開発者向けドキュメント一式を
新規作成。

## フェーズ15: ユーザー体験と診断機能の拡張(2026-07-20)

**新UI・ログ機能:**
- チャット履歴シート(`modChatLog`): 質問・回答・日時・モードが自動記録される見える化。最新が上、100件で自動削除。`chat_log_enabled=FALSE`で無効化可能
- 質問テンプレチップ穴埋め化: テンプレをクリック→「【知りたい改定】: (記入)」の穴埋めフォームが入力欄に自動挿入
- 低関連度警告(`modAsk`): 関連度が低い検索ヒット(既定0.3未満)時、回答冒頭に「⚠️ 手元の資料との関連が薄い可能性があります」と警告表示

**診断・エラー処理:**
- 診断の設定サマリー(`modDiag`): 「❓ ガイド」→「🩺 診断を開く」レポート冒頭にモデル名・自動同期間隔・本棚フォルダ等の現在値を表示
- エラーダイアログの直近エラーコピー(`modLog`): ダイアログ末尾に案内。「❓ ガイド」→「🩺 診断を開く」→📋ボタンで、err_logの直近5件(コード・箇所・HTTP通信情報)をクリップボードへコピー

**同期UX:**
- 同期完了表示(`modShelfSync`): 手動同期が正常完了時、ダイアログを出さずステータスバーに「✅ 同期が完了しました」と表示のみ(上限見送りがあった場合のみダイアログ出力)

**内部拡張:**
- `err_log`に`err_number`(生エラー番号)・`http_status`(HTTPステータスコード)列を追加
- Azure OpenAI APIキー・エンドポイントを環境変数化(`AZURE_OPENAI_KEY`, `AZURE_OPENAI_ENDPOINT`)
