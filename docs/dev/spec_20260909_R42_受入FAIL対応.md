## §1 A1／A2 設計（`modChunkPage`・新規・src/ingest）

### 1-1 データの持ち回り
- `ChunkAllPagesStructured` の `blockBuf()`（行）に並走する **`blockPg()`（行ごとの物理ページ・Long）** を持つ。`blockPage` 変数と :452/:461 の代入は削除。
- 行の追加 3箇所（:451 見出し行・:462 本文行）→ `modChunkPage.BlockAddPg blockBuf, blockPg, blockN, 行, pageNo`（`BlockAdd` と同じ伸長規則で両配列を揃える）。
- ブロック確定 2箇所（:444 見出し境界・:486 末尾）→ `modChunkPage.FlushPaged blockBuf, blockPg, blockN, chapter, section, tgt, ov, mx, outArr, outCount`（呼び出し後 `blockN = 0`）。SkipPage の `blockN = 0` はそのまま（両配列とも捨てる）。
- `ChunkOnePageStructured`（1ページ経路）と `FlushBlock` は**不変**（単一ページなので従来どおり）。

### 1-2 `modChunkPage` の関数（契約）
- `Public Sub BlockAddPg(ByRef buf() As String, ByRef pg() As Long, ByRef n As Long, ByVal s As String, ByVal page As Long)`: 空文字は積まない。`n = 0` で `ReDim buf(1 To 64): ReDim pg(1 To 64)`、超過で両方 `ReDim Preserve` ×2。
- `Public Function LineStarts(ByRef buf() As String, ByVal n As Long) As String`: 内部用ではなく**純関数の検証口**。`Join(buf(1..n), vbLf)` における各行の開始位置（1始まり）を `"1,12,30"` の形で返す（行 i の開始 = 前行の開始 + Len(前行) + 1）。
- `Public Function PageAtPos(ByRef starts() As Long, ByRef pg() As Long, ByVal n As Long, ByVal pos As Long) As Long`: `starts(i) <= pos` を満たす最大の i の `pg(i)`。`pos < starts(1)` は `pg(1)`。n=0 は 0。
- `Public Function FirstInkPos(ByVal body As String, ByVal startPos As Long) As Long`: `startPos` 以降で空白類（半角/全角スペース・vbLf・vbCr・vbTab）でない最初の位置。無ければ `startPos`。
- `Public Function PlanWindows(ByVal total As Long, ByVal tgt As Long, ByVal ov As Long, ByVal room As Long, ByVal body As String) As String`: `FlushBlock`:582-600 のスライディング規則**そのまま**（`FindSentenceBoundary` を使うため `modChunker.FindSentenceBoundary` を Public 化）。各窓を `"s-e|s-e|…"` で返す。**規則を1文字も変えない**（本文の粒度は R42 で変えない＝受入報告 §3 の前提）。
- `Public Sub FlushPaged(ByRef buf() As String, ByRef pg() As Long, ByRef n As Long, chapter, section, tgt, ov, mx, ByRef outArr() As ShelfChunk, ByRef outCount As Long)`:
  1. `n < 1` なら Exit。`raw = Join(buf(1..n), vbLf)`（`ReDim Preserve buf(1 To n)` して Join・`BlockTake` と同じ）。`lead = Len(raw) - Len(LTrim$(raw))`、`body = Trim$(raw)`。空なら `n = 0` して Exit。
  2. `starts()` を `LineStarts` と同じ規則で Long 配列に作る（文字列を経由しない）。
  3. `crumb`/`room`/`atomicLimit` は `FlushBlock`:568-574 と同一（`modChunker.BuildBreadcrumb` は Public 済み・`CRUMB_PLACEHOLDER`/`MAX_CHUNK_CHARS` は Public 化）。
  4. `Len(body) <= atomicLimit` → 1かけら。page = `PageAtPos(starts, pg, n, FirstInkPos(body, 1) + lead)`。
  5. 超過 → `PlanWindows` の各窓 `s-e` について page = `PageAtPos(starts, pg, n, FirstInkPos(body, s) + lead)`、本文 `Mid$(body, s, e - s + 1)`。
  6. かけらの追加は `modChunker.AppendStructChunk` を Public 化して呼ぶ（`room` 切詰めと `crumb` 前置は不変）。
  7. 末尾で `n = 0`。
- `Public Function PhysicalKeep(ByVal firstIdx As Long, ByVal keptN As Long, ByVal maxPages As Long, ByRef truncated As Boolean) As Long`: `maxPages <= 0` → keptN（truncated=False）。`firstIdx + keptN > maxPages` → `truncated = True`、戻り `maxPages - firstIdx`（負は 0）。それ以外 keptN。
- `modExtractor.BuildPagesFromGsText`:673-676 → `keptN = modChunkPage.PhysicalKeep(firstIdx, keptN, maxPages, truncated): If keptN < 1 Then Exit Function`（False＝本文なし。呼び出し元は従来どおり Word→Acrobat の連鎖へ落ちる）。

### 1-3 出典契約（既存列のまま）
- `ShelfChunk.page`／my_knowledge の page／`Hit.page` は**そのかけら本文の開始物理ページ**。p4 末尾から p5 にまたがるかけらは p4。ページ範囲の表示（page_end）は導入しない。
- 見出し行から始まるかけらは見出し行のページ。オーバーラップで前ページの末尾から始まるかけらは前ページ。
- chunk_id は `bs::hash::pN::cN`（modShelf:210-226）なので、同じ PDF を再取込すると後半の id が変わる。既存の「新行を書いてから旧同名行を消す」順は不変。**取込済みの PDF は再取込しないと直らない**（利用者向け文言は §4-9）。
- 目次ページ（`isToc`）・SkipPage・NormalizeForIngest の挙動は不変。

### 1-4 modChunker の容量（残61字）
- 削除: `Dim blockPage As Long`（:416）・`blockPage = pageNo`（:452）・`If blockN = 0 Then blockPage = pageNo`（:461）。

### 1-5 テスト（`modTestsPure45`・新規。LO で走る純関数中心）
- `LineStarts`: 3行（"abc","de","f"）→ "1,5,8"。1行→"1"。
- `PageAtPos`: starts=(1,5,8) pg=(1,2,5): pos1→1・pos4→1・pos5→2・pos7→2・pos8→5・pos100→5・pos0→1。n=0→0。
- `FirstInkPos`: `"  x"`→3・`vbLf & "x"`→2・`"x"`→1・末尾空白のみ→startPos。全角空白。
- `PlanWindows`: 本文 "あ…" 30字・tgt=10・ov=3・room=100 → 期待は `FlushBlock` 規則の手計算値を固定（文境界なし＝`1-10|8-17|15-24|22-30`。`FindSentenceBoundary` の slack は tgt\4。句点入りは境界で切れる例を1つ）。

  ```
  move /Y "%DST%%XLSM%" "%DST%<upgrade_name>" >nul

  :COPY_NEW
  copy /Y "%SRC%%XLSM%" "%DST%%XLSM%" >nul
  if errorlevel 1 goto :COPY_FAIL
  copy /Y "%SRC%%BUILD%" "%DST%%BUILD%" >nul
  goto :COPY_DONE
  :COPY_LEGACY
  xcopy "%SRC%%XLSM%" "%DST%" /D /Y /Q
  if errorlevel 2 goto :COPY_FAIL
  if exist "%SRC%%BUILD%" copy /Y "%SRC%%BUILD%" "%DST%%BUILD%" >nul
  :COPY_DONE
  ```
  - `:COPY_LEGACY` は「同じ版」の経路＝従来の `/D`（D: 側が新しければ上書きしない＝未書き戻しデータの保護）。
  - SRC に印が無い（古い zip・手作業配置）→ 従来どおり。
  - `_旧版` の複製（:550）は `:COPY_DONE` の後に従来どおり残す（`/D`）。ただし **`:RETIRE` で D: に作った `_旧版` を SRC の古い `_旧版` で上書きしない**よう、`if exist "%DST%<upgrade_name>"` のときは複製しない。
  - 引継ぎの条件（modMigrateFrom.OfferImportIfFirstRun）は不変: 新版本体は zip 由来で本棚空・未質問。`FindPreviousBook` は `ThisWorkbook.Path`（＝D:）を見るので `_旧版` が見つかる。
- `:COPY_FAIL`: 既存の「複製失敗」窓（:556）の文言を「D: へ複製できませんでした（元のファイルか D: の空きを確認）」に。`goto :EOF`。

### 2-2 起動番号（B2）
- `:LOOP` 冒頭で `set "SID=%RANDOM%%RANDOM%"`。印は `%DST%.closed.%SID%`。`__wait__` へ `"%~f0" __wait__ %SID%` で渡し、`:WAIT_AND_MARK` は `type nul > "%DST%.closed.%~2"`。監視は自分の印だけ見る。起動前の削除（:568）は自分の印（実質無い）だけ。`:FINAL_COPY` の最後で自分の印を消す。古い `.closed`（旧 bat）は無視。

### 2-3 成否の検知（B3）
- 退避（:594）: `copy /Y ... >nul` の直後 `if errorlevel 1 goto :BACKUP_FAIL`。`:BACKUP_FAIL` は窓「退避に失敗したため書き戻しを中止しました。D:\MyBookshelf\%XLSM% が最新です。手で OneDrive へコピーしてください」→ `goto :EOF`。SRC に本体が無い場合は退避不要（従来の `if exist` のまま）。
- 定期書き戻し（:588）: 直後に
  ```
  if not errorlevel 1 goto :COPY_LOOP
  if defined WB_WARNED goto :COPY_LOOP
  set "WB_WARNED=1"
  start "MyBookshelf 書き戻し失敗" cmd /c "echo OneDriveへの定期書き戻しに失敗しています。& echo 作業は D:\MyBookshelf\%XLSM% に残っています。閉じるときにもう一度試します。& pause"
  goto :COPY_LOOP
  ```
  （goto 形で書く。括弧ブロック内の `&`・`%` 展開の罠を踏まない。`if defined` は遅延展開不要）。
- 最終書き戻しの再試行（:597-603）は不変。

### 2-4 Ghostscript（B4）
- `if not exist "%DST%Ghostscript\gswin32c.exe" goto :GS_COPY` / `if not exist "%DST%Ghostscript\gsdll32.dll" goto :GS_COPY` / `goto :GS_DONE` / `:GS_COPY` xcopy 一式 / `:GS_DONE`。注記の「約14MB」→「約22MB」。

### 2-5 検証
- python: `_launcher_bat_text` は純関数。`tools/` に bat 生成の検査が無ければ **`tools/check_launcher.py`（新規・小）** で (1) CP932 エンコード可 (2) ラベル `:RETIRE/:COPY_NEW/:COPY_LEGACY/:COPY_DONE/:COPY_FAIL/:BACKUP_FAIL/:GS_COPY/:GS_DONE/:FINAL_COPY/:WAIT_AND_MARK` が各1回 (3) `goto :X` の X が全て定義済み (4) `.closed.%SID%`／`%~2` の対応 (5) `xcopy ... /D` が `:COPY_LEGACY` にだけ残る、を検査。final-gates の一環で走らせる。
- 実機（Windows のみ）: §5-B。
