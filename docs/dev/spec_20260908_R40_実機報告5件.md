## §1 F1 の設計（Fable 自身）

**変更前**: `optGsProc.RunGsAsync` = WMI `Win32_Process.Create(cmd)`（失敗時 `WScript.Shell.Run`）／`KillGsTree` = WMI で名前照合 → `WScript.Shell.Run "taskkill /T /F"`／`optOcrCore.BuildRunCommand` = `cmd.exe /s /c "(gs…) 1>log 2>&1 & (if errorlevel …) >flag"`。

**変更後**:
- `optOcrCore.BuildRunCommand(gsCommand, doneFlagPath, logPath)`: **cmd ラップ無し**。GS 本体のコマンドの実行ファイル直後（入力 PDF より前）に ` -sstdout="<log>"` を挿す（GS 自身の機能で標準出力をファイルへ。stderr は落ちないが PostScript 系エラーは stdout に出る）。`doneFlagPath` は未使用（契約維持で引数は残す）。
- `optGsProc.RunGsAsync`: VBA の `Shell(runCmd, 0)` で `gswin32c.exe` を直接・非表示起動。戻りの PID で `OpenProcess(QUERY_LIMITED_INFORMATION|TERMINATE)` のハンドルを保持（→ PID 再利用が起きない＝R13-F2 の名前照合が不要）。`Shell` の失敗（実行ファイル無し・AppLocker）は Err → `errNum/errDesc` へ写して False（呼び出し元の E0302 記録は不変）。
- **新規** `optGsProc.SyncDoneFlag(flagPath)`: `GetExitCodeProcess` が `STILL_ACTIVE(259)` 以外を返したら、その終了コードを `done.flag` に書いて（`Print #`・既存なら上書きしない）、**書けたときだけ**ハンドルを閉じ True。**退路（レビュー1周目 B1 の Fix）**: 完了フラグの書き手がこのモジュールだけになった（cmd 時代の「`&` で無条件に作る」保証が消えた）ので、(1) 起動直後に `OpenProcess` が失敗しても呼ばれるたびに取り直す、(2) 終了コードを読む権限が無くても `SYNCHRONIZE` だけで開ければ `WaitForSingleObject(h,0)` で「終わった」ことだけを見て `"?"`（`GsExitCodeFromFlag` → −1＝失敗と決めつけない側）を書く、(3) それでも開けず `Err.LastDllError`=87（無効な PID＝起動直後に終了）なら `"?"`。**それ以外（例: EDR が 5=ACCESS_DENIED を返し続ける端末）では終了を知る手段が無く、従来どおりアイドル上限（`vision_pdf_timeout_sec`）で見切って E0302 になる**（usage_log `gs_kill_unavailable` に err 番号が残る。実機で起きたらこの番号を見る）。`optGsTxt.WaitGsTextDone`／`WaitForDoneFlag` の各ループ先頭で呼ぶ（既存のフラグ待ち・`GsExitCodeFromFlag`・`GsFailureDetail` は不変。負の終了コード＝クラッシュ系は従来どおり 255 に畳む）。
- `optGsProc.KillGsTree(pid)`: 保持ハンドルが同じ PID なら `TerminateProcess`。既に終了していれば True（R33H F20 の意味を維持）。ハンドル無し・別 PID は False（作業フォルダを残す側）。WMI・taskkill・cmd は使わない。
- Declare は `#If Win64` で `PtrSafe/LongPtr`、それ以外は `Long`（32bit Excel が前提。LO は `#Else` 側でコンパイル）。ハンドルは `Long` で保持（Win64 でもカーネルハンドルは下位 32bit）。
- ログ: `gs_kill_unavailable`（ハンドル未取得）／`gs_kill_not_needed`／`gs_killed_on_hang`／`gs_kill_failed`／`gs_kill_skipped` の usage_log キーは不変。
- `optGsTxt.GsOutHasPages`: `gs_out.log` に総頁が無くても `gstext_%04d.txt` が1つでも在れば「ページを処理した」とみなす（レビュー M2。`-sstdout` が空でもスキャン PDF が OCR へ回り、総頁の分母も失わない）。
- lint CONTRACT `optGsProc` に `SyncDoneFlag` 追加。Pure4 `TestBuildRunCommandGolden`・Pure6 `TestGsRunCommandObservability` をゴールデン更新（「cmd・>・&・%・echo・errorlevel を含まない」「done.flag のパスを含まない」「-sstdout が実行ファイル直後」を固定）。

**残る WScript.Shell／WMI**（GS 経路外・今回不触）: `modWorkExcel`／`modBoard`／`modVault`／`modVaultGallery`／`modHubStat`／`modBoot`／`modAnalytics`／`modCluster`／`modClip` 等。PDF 取込では通らない。AMSI が別の操作で反応したら次ラウンドで同じ型（直接起動・API）へ寄せる。

**確認できないこと**（この環境に Windows／Defender／GS が無い）: (a) 直起動で AMSI が反応しなくなること自体。(b) `-sstdout` で `gs_out.log` に "Processing pages 1 through N"／"Page N" が出ること（GS 公式の機能。バッファリングで遅れる可能性は cmd 時代と同じ。進捗の主信号はページファイルの LOF）。(c) `Shell` が返す ID が PID であること（Windows の公式仕様。ハンドルが取れなければ `gs_kill_unavailable` が1回記録され、取込自体は進む）。

## §2 F2〜F5 の設計

- **F2** `modLive.CiteTagSpans(s, starts(), lens())`（純関数）: `[本棚:` / `[パック(` から同一段落内の最初の `]` まで（段落を跨ぐ・閉じ無しは除外）。`modLive.StyleAnswerParas`（AI バブルだけ・生成時と復元時の両方から呼ばれる）の末尾で `TextRange.Characters(start,len).Font` を **8pt・primary 色**に。本文の文字列は 1 字も変えない。
- **F3** `modExtractorExcel.AppendBlockLines` に絶対番地（`used.Row/Column` 基準）を渡し、各行の先頭に `RowPrefix(col,row)` = `"[A6] "`（`CellAddressOf` は 1→A・27→AA の純関数）。1セル範囲（スカラー）も同様。`[シート: 名前]` 行は不変。**既に取り込んだ Excel は再取込するまで番地が付かない**（本文とハッシュが変わるので、再取込は「削除→取込」。記録）。表示: `modLive.PageLabel(src, page)` が `.xlsx/.xlsm/.xls/.xlsb` なら「 シートN」、他は「 p.N」、0 は空。`modPeek.DrawChip` と `modLive.BuildSourceBlock` が使う（旧ホーム画面の `modUIMain.JoinSourceLabels` は不触）。プロンプト: `modAskOnePass.BuildOnePassPrompt` と `modAskGlobal` の出力規則に「Excel の資料では p. はシートの通し番号。抜粋の行頭にある [A6] のようなセル番地を根拠の文に添える」1行（凍結 `modPrompts` は不触＝すぐ聞く／しっかりの通常経路では番地の指示は無いが、本文に番地が載るので自然に引かれる）。
- **F4** `modPackExport.ExportPackToFile`／`modPack.ImportPackFile` の `Bump` 直後に `modStats.EvaluateBadges`（`On Error Resume Next` 包み）。起動中（`BeginDeferredBadges`）は従来どおりキューに積む。
- **F5** `onepass_max_chars` 既定 450000（build config・`modAskOnePass` の既定・管理者ガイド kv・docs/10）。章数 8・seed 6 は据え置き（章あたりの予算が 1.5 倍になる）。JSON エスケープ（`EscapeJsonStr`）は配列＋Join の O(n) で 45 万字も問題無い。**遅くなったら 300000 に戻す**（管理者ガイドに記載）。

## §4 実機での確認方法（ユーザー）

1. **F1**: 同じ PDF を取り込む → 強制終了せず本棚に入る／ページ番号が付く。**必須で見るもの**: `%TEMP%\nxocr_*`（取込中に開く。終わると消える）の `gs_out.log` に "Processing pages 1 through N" が入っているか（空なら `-sstdout` が効いていない＝スキャン PDF の分類が弱くなる。取込自体は動く）／`done.flag` の中身（0 などの数字。`?` なら終了コードが読めない端末）／usage_log に `gs_kill_unavailable` が出ていないか（出ていれば err 番号を教えてほしい）。usage_log に `pdf_text_gs` が出る。もし再び強制終了したら、Windows セキュリティ → 保護の履歴 → 該当項目の**脅威名**を教えてほしい（AMSI 以外の原因の切り分けに要る）。
2. **F2**: 質問して回答内の `[本棚:…]` が本文より小さく青系の色になっている。出典チップ・本文ボタン・Word で開くは従来どおり。
3. **F3**: Excel を（一度削除して）取り込み直し → 本文ボタンで各行の頭に `[A6]` 形式の番地／出典チップが「シート1」／回答文に「(C12 付近)」のような位置が添えられる（入念・広域で確実。すぐ聞くは本文に番地があるので出やすいが指示は無し）。
4. **F4**: 初回のパック出力・取込の直後にバッジのトーストが出る（他の操作を挟まずに）。2回目以降は出ない（取得済み）。
5. **F5**: 入念に調べるの体感（従来 20 万→30 万トークン相当）。著しく遅い／エラーなら config `onepass_max_chars` を 300000 に戻す。

## §5 記録のみ（R41 候補）

- 終了コード 259 と `STILL_ACTIVE` の衝突（GS は 0/1/負しか返さないので実害無し）。
- `SyncDoneFlag`/`RunGsAsync`/`KillGsTree` は副作用ありで LO テスト不能＝**F1 の中核は自動検査ゼロ。実機報告だけが検証手段**。
- サロゲートペア（絵文字）を含む回答で `Characters(start,len)` の位置がずれる可能性（推測・実機で絵文字入り回答を1本見れば判定できる）。

- GS 経路以外の WScript.Shell／WMI（§1 末尾）。
- `gs_out.log` の stderr（`-sstdout` は stdout のみ）。
- Excel の番地を出典タグ自体（`p.N`）へ載せる案は `Hit.page` の型変更＝パック形式の版跨ぎになるため見送り。
- Word を開いたままの取込で応答なし（R39 から継続・原因未特定）。
