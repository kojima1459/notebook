## 実機プローブで確定した事実（余白の真因・7ラウンド来の決着）

- `modUI.bas:104` の `ws.Rows("1:400").RowHeight = 18` が**起動のたびに1〜400行へ行高を明示設定**し、Excelの内部使用範囲（xlCellTypeLastCell）を毎回400行に焼き付けていた。実機の `Worksheets("Nexus").UsedRange.Address` = **$A$1:$M$400** がこの定数と一致。
- FreezePanes併用のNexusはホイールがScrollAreaを素通り（R29確定）するため、素通り先の停止線=使用範囲末尾=400行目。400行×18pt≈画面10枚分 →「無限に転がる」体感。
- **`ClearFormats` では直らない**（行高はClearFormatsの対象外・実機で `A28:M2000`/`A33:M2000` とも無効を確認）。保存でも直らない（次回起動で再設定されるため）。
- **`Rows("28:400").Delete` で即時に直ることを実機で確認**（保存不要・セッション中に有効。バブルShapeはPlacement=3のため無影響）。削除後のホイール停止はコンテンツ末尾行が画面上端に来る位置（実機では31行目が上端・46行目まで表示）＝**Excelの仕様上の理論限界**。残る余白は最大約1画面分（従来の約10画面分から縮小）。これ以上の削減はFreezePanes廃止（入力欄固定の喪失）でしか得られない → 採らない。
- 分割ウィンドウ（Window.Split）方式は実機で**両ペイン独立スクロール・入力欄が流れる**ことを確認 → 恒久候補から除外。
- 「使うほど伸びる」はR18以来の錯覚で、初回起動時から400行あった。歴代の塗り/ScrollArea系修正が効かなかったのはこのため。

## 波1（Opus）: 余白の根治 — 「400行焼き付け」の廃止と行の解放

**設計方針**: 行高18ptの明示設定を「実際に使う範囲だけ」に限定し、不要になった行は `Rows.Delete` で解放する（実機実証済みの唯一の解放手段）。R28のNormalスタイル地色（`ApplyNormalStyleBg`）により、削除後の標準高行も地色で表示されるため白帯は出ない。

1. **W1-0（着手前監査・報告義務）**: `modViewport.RowAt` / `BoundBottomY` / `BoundAddr` / `RowAtFloor` と `modUINexusDraw.NexusBound` / `ChatBottomFor` が「全行=18pt」を前提にした割り算をしていないか監査。行Top走査ベースなら無修正でよい。18pt割り算前提が見つかった場合は**修正せず司令塔へ報告**（バンド内は全行18ptが維持されるため、バンド内限定の前提なら適法）。
2. **W1-1** `modUI.InitUI:104` の `ws.Rows("1:400").RowHeight = 18` を廃止し、**初期表示に必要な範囲（初期バンド下端行+余裕3行）のみ**へ18ptを設定する。範囲の行番号はFitBandToViewport後に確定する既存の幾何（NexusBound系）から導出し、導出前に必要なら暫定40行→確定後に不足分を追加設定する二段構えも可（実装裁量。ただし最終的に18pt行が存在するのはバンド下端+3行までであること）。
3. **W1-2（移行掃除・冪等）**: InitUI の骨格構築時（`ws.Cells.Clear` 直後）に、旧版が焼き付けた行を解放する: バンド確定後 `ws.Rows(bound+1 & ":2000").Delete` → 直後に `ws.UsedRange` を1回参照（再計算トリガ）。2000は `NEXUS_MAX_ROW`（ExtendChatBand旧塗りの上限）。毎起動実行で冪等。行1〜4（固定領域）とバンド内には触れない。
4. **W1-3（成長経路）**: `modSkin.ExtendChatBand` の**拡大分岐**で、新たにバンドへ入る行（旧mChatBandRow+1〜新lastRow）へ `RowHeight = 18` を設定してから塗る（会話の成長に行高が追随。バンド内全行18pt不変式の維持）。
5. **W1-4（縮小・クリア経路）**: ExtendChatBand の**縮小分岐**と `modUI.ClearChat` 後処理で、新バンド下端より下を解放: 実体関数 `ReleaseRowsBelow(ws, boundRow)`（`If lastUsed > boundRow Then Rows(boundRow+1:max(lastUsed,2000)).Delete` + UsedRange参照）を**容量に余裕のあるモジュールへ新設**し、呼び出しは1行。縮小分岐の既存再塗り（Interior.Color）はバンド内のみに縮小（バンド外は削除で消えるため塗り不要）。
6. **容量制約**: modSkin残163字 → ExtendChatBandへの追記は**正味増分ほぼゼロ**に抑える（旧縮小塗りロジックの置換で相殺）。実体は modChrome（残7,298）または modViewport2 へ（着手前に実測・lint CONTRACT登録要否を確認）。modUI残716字 → ClearChat/InitUIの呼び出し追加は1行ずつ。全モジュール容量実測を報告。
7. **繋ぎ目（レビュー観点として明記）**: (a) FreezePanes行1-4は削除範囲外であること（bound≥5保証） (b) バブルShape=Placement=3で行削除の影響なし（起動直後・クリア直後・長会話後の3状態で確認） (c) `DisableUndoRedo` 済みのためUndoスタック問題なし (d) Rows.Delete は modUiLock.AlertsOff/On 保護不要（モーダルを出さない）が、描画中の再入に注意 (e) ScrollArea・FreezePanes設定順序は不変 (f) チャット履歴等の他シートに触れない。
8. **テスト**: 純関数化できる部分（解放範囲の行番号計算等）は modTestsPure29 へ純関数テスト+ネガティブ確認。Excelオブジェクト操作部はLO compile+実機確認項目として明記。
9. **文書**: CLAUDE.md VBA落とし穴へ「行高の明示設定はUsedRangeを焼き付ける（ClearFormats/保存では消えない・`Rows.Delete`が唯一の即時解放。R30実機実証）」を追記。HANDOFFの余白記述を「R30根治」へ更新（ラウンドクローズ時に司令塔が実施）。

**実機確認方法（第16報の観点）**: 起動→チャットでホイール最下部→最後の吹き出けのすぐ下（+最大1画面弱）で止まる／会話5往復→クリア→再度ホイールで同様／再起動後も同様。
