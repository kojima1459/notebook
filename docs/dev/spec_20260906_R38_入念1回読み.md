# R38 仕様: 「入念に調べる」の1回読み（章丸ごと・メガコンテキスト）（2026-09-06）

裁定者: Fable。起点: 外部レビュー（Gemini）裏どり `review_20260905_外部レビュー裏どり_R37.md` §4 ＋ 髙橋情報「リボン経由で 20 万トークンまで通る（本人検証済・OpenAI 公開上限まで）。50 万超で精度が落ちる情報があるので 20 万を安牌にしている」＋ ユーザー GO「A を挟まず一気に B」。

## §0 結論と守るもの

- **入念に調べる＝精度**、しっかり調べる＝中間、すぐ聞く＝速度。R38 は**入念だけ**を変える。しっかり・すぐ聞くは1文字も変えない。
- 入念の「単発経路」（`modAskMulti.TryDecomposed` が False を返し `modAskThorough.RunThoroughFlow` に来る回）を、**章丸ごと読み＋1回呼び出し**に置き換える。分解経路（複合質問）・俯瞰経路（全体像の質問）は従来どおり。
- **戻し方は config 1行**: `thorough_onepass=off` で従来の4段（要点整理→下書き→自己点検→検証）に戻る。遅さだけが問題なら `onepass_max_chars` を下げる。
- 1回読みが**材料を組めなかったら黙って従来の4段へ落ちる**（章も近傍も引けない・例外。答えが出ない状態を作らない。`modAskGlobal.TryGlobal` と同じ思想）。**ただし LLM 呼び出し自体の失敗（ESC 中断・NW 断・上限）は4段へ落とさず、4段と同じくエラー文をそのまま返す**（レビュー A-M3 裁定: 止めたい利用者を4段でさらに数分待たせない。`modGateway.CallLLM` は Err 18 も `#ERR` 文字列に変えて正常戻りするため、経路はここで見分ける）。
- 凍結（modAsk / modPrompts / modRetrieve / modShelf / modBoot）は不触。プロンプト文は新モジュール内に持つ（`modAskGlobal.BuildGlobalPrompt` と同じ理由）。出典タグの書式は `modPrompts.SourceTag` だけを通す。

## §1 検算（前提）

| 項目 | 値 |
|---|---|
| 20 万トークン ≒ 日本語 | 約 30 万字 → `onepass_max_chars` 既定 **300,000** |
| 現行の入念（4段）の本文上限 | 60,000 字（`max_context_chars`。触らない） |
| 200 頁級の規程1冊 | 約 45 万字 ＝ 1冊丸ごとは入らない。**章**が単位 |
| 往復回数（入念・単発） | 現行 expand + rerank + decompose判定 + 4段 ＝ 7 → **4**（expand + rerank + decompose判定 + 1回読み） |
| 呼び出し中の見え方 | 同期呼び出しで Excel は応答なし表示（現行と同じ。実況に「※応答なし表示でも処理中」を出す） |

**確定（2026-09-06 ユーザー報告）**: 髙橋さんのサイバー保険 RAG も**同じ社内リボン経由**で 20 万トークンを1回で渡している＝リボンの入力上限はうちの経路でも問題にならない。未確認は**1回の秒数と精度だけ**（§5 の受入で測る）。

## §2 新モジュール `modAskOnePass`（src/qa・受け皿・Gemini 3.8 flash が起草）

### 2-1 公開 API

```vb
Public Function Enabled() As Boolean
'  config thorough_onepass（既定 "on"）。IsOn(値) を通す。

Public Function TryOnePass(ByVal q As String, ByRef hits() As Hit, ByVal nHits As Long, _
                           ByVal history As String, ByVal prevU As String, ByVal prevA As String, _
                           ByRef outBody As String) As Boolean
'  True = 回答本文を outBody に入れた（出典突合済み。F3 以降は LLM エラーの "#ERR…" 文字列もここ＝呼び出し元は ok=Not IsErrorResponse）。False = 何もしていない（章も近傍も引けない・例外。呼び出し元が4段を実行）。
'  hits は【必ずローカルへ複製してから】使う（opHits = hits）。呼び出し元の hits/nHits は書き換えない
'  （出典チップ・信頼度バッジは検索結果そのものを見せる。近傍・章本文は「根拠であってヒットではない」= modAskThorough の既存判断）。
```

### 2-2 TryOnePass の手順

1. `nHits < 1` → False。`On Error GoTo Quiet`（想定外は False・`onepass_fallback why=err` を usage_log）。
2. **章の解決**: `modChunkMetaStore.ReadAllMeta(mIds, mPaths, mRefs)` → `metaN`。`metaN < 1` なら 4 へ（近傍経路）。
   上位 `onepass_seed_hits`（既定 6・nHits を超えない）件について `modXDoc.ChapterOfChunk(hits(i).chunk_id, mIds, mPaths, metaN)`（R38 で Public 化）で章キーを取り、`Trim$(hits(i).source) & "::" & 章キー` を vbLf 区切りで積む → `DedupeKeys(box, onepass_max_chapters 既定 8)` で**順位順・重複なし**の picks を得る。0 件なら 4 へ。
3. **章丸ごと読み**: picks を**1章ずつ順位順に** `modAskGlobal.CollectChapterHits(pick1件, 1, chHits, capPer, 300)`（R38 で Public 化＋Optional 引数）で読む。`capPer = PerChapterCap(onepass_max_chars, nPick, 2000)`。章ごとの結果を ctxHits の末尾へ連結（章の順＝順位順、章の中＝文書順）。合計 0 件なら 4 へ。`mode="chapter"`。
4. **近傍経路（章が引けないときの代替）**: `opHits = hits`、`nUse = nHits`、`modAskFocus.NeighborExpand opHits, nUse, onepass_neighbor（既定 6）`、`modAskFocus.RefsExpand opHits, nUse, 0`。ctxHits = opHits(1..nUse)。`mode="neighbor"`。
5. **本文ブロック**: `SourceBlockOf(ctxHits, ctxN, onepass_max_chars)`＝各件 `modPrompts.SourceTag(h) & vbLf & full_text & vbLf & vbLf`、上限は `modOutlineBuild.BudgetTake` で残量管理、切れたら末尾に `(一部省略)`。
   **重点抜粋（Lost-in-the-middle 対策）**: 元の hits の上位 `min(3, nHits)` 件を同じ書式で `focusBlock` に組む（本文ブロックと重複してよい。質問の直前に置く）。
6. **実況**: `modUIMain.SetStage "🔎 入念(1回読み): " & 章数 & "章・" & ctxN & "箇所を読んで回答を作成中… ※応答なし表示でも処理中"`（On Error Resume Next で囲む。絵文字は ChrW で書く）。
7. **呼び出し**: `modGateway.CallLLM(BuildOnePassPrompt(...), "thorough_onepass", config thorough_onepass_effort（既定 "high"）, config thorough_draft_verbosity（既定 "high"）, config recommended_model（既定 "gpt-5.5"）, lat, prevU, prevA)`。`modRagParse.IsErrorResponse` なら `onepass_llm_err`（`why=llm_err`）を記録し、**outBody にそのエラー文字列を入れて True**（F3。4段へは落とさない）。
8. **後処理**: `body = modAsk.ApplyAnswerTags(ans)`。出典突合は `modAskThorough.AnnotateAgainstHits(body, allHits, allN)`。`allHits` は ctxHits の後ろに元の hits(1..nHits) を連結した配列（重点抜粋の出典が「確認できず」にならないため）。`outBody` に入れて True。
9. **記録**: `modLog.LogUsage "thorough_onepass", "thorough", "mode=" & mode & " chapters=" & nPick & " chunks=" & ctxN & " chars=" & Len(prompt) & " extra=" & extra, 0, ctxN`（F6: chars はプロンプト全長。F1: extra は章に無かった元 hits を末尾へ足した**件数**で、載った件数ではない。Fix2 で章の予算を8割にし、残り2割を extra 用に空ける）。

### 2-3 プロンプト `BuildOnePassPrompt`（純関数・Pure43 で固定）

```vb
Public Function BuildOnePassPrompt(ByVal q As String, ByVal ctxBlock As String, ByVal focusBlock As String, _
                                   ByVal history As String, ByVal lang As String, _
                                   ByVal ansTags As Boolean, ByVal strictG As Boolean) As String
```
並び（この順で固定）:
1. 役割: 「あなたは社内資料の調査アシスタントです。『入念に調べる』モードです。下の本棚抜粋（関連する章の本文・文書順）だけを根拠に、質問へ<lang>で丁寧に、根拠を示しながら回答してください。」
2. 手順（ansTags のときだけ）: 「出力は<thinking>に検討、<answer>に利用者へ見せる回答、の構造にすること。<thinking>では次の順で検討する: (1)質問の前提と論点を分解する (2)本文から関連する記述を漏れなく抜き出す（章をまたぐもの・表の見出しと値・但し書きを含む） (3)抜き出した記述同士の矛盾・例外・免責を確認する (4)本文に書かれていない推測を削る (5)各主張に出典を付けられるか確認する。[[FOLLOWUP:...]]の行は</answer>を閉じた後（タグの外）に置くこと。」
3. 出力規則: 「・根拠にした箇所には必ず出典タグを文の直後に付ける（本棚の資料は [本棚:ファイル名 p.ページ番号]、受け取ったパック由来は [パック(作成者名):ファイル名]）。」「・■見出しで構造化し、各主張の直後に出典を明記。必要なら600〜900字まで許容。断定できない点は「資料からは確認できません」と明示すること。」（F7: `"・" & modAskThorough.ThoroughStyleAddendum()`＝単一情報源。**■ は落とさない**＝表示側が行頭 ■ を見出しにする。Fix2 で Pure43 が固定）「・支払う場合だけでなく、支払わない場合(免責事由・除外・適用除外)も対象に含め、資料にあれば必ず言及すること。」「・Markdown記号(#、**、表)は使わない(この画面では崩れて見える)。」
   strictG のときだけ: 「【厳守】本棚抜粋に書かれた情報のみで回答し、外部知識や推測での補完は禁止。出典を付けられない主張は書かない。抜粋から判断できない場合は「資料からは判断できません」とだけ述べ、どんな資料を追加すれば答えられるかを1行添えること。」
4. history が空でなければ「## これまでの会話(参考。続きの質問なら踏まえて回答する)」＋ history。
5. 「## 本棚抜粋(関連する章の本文・文書順)」＋ ctxBlock。
6. focusBlock が空でなければ「## 重点抜粋(検索で最も近かった箇所。上の本文と重複あり)」＋ focusBlock。
7. 「## 質問」＋ q。
8. 深掘り候補: 「最後に、この回答をさらに深掘りするための質問候補を2つ考え、回答本文の一番最後に次の1行だけを追加してください(この行は利用者向け表示からは自動的に取り除かれます。良い候補が無ければ [[FOLLOWUP: なし]] と書く):」＋ vbLf ＋ 「[[FOLLOWUP: 候補1 | 候補2]]」

### 2-4 純関数（Pure43 で固定・Hit 型を跨がない）

- `IsOn(s As String) As Boolean` … 空・"on"・"true"・"1"・"yes"（大小・前後空白無視）= True。"off"・"false"・"0"・"no" = False。それ以外は True（既定側へ倒す）。
- `DedupeKeys(boxLf As String, maxN As Long) As String` … vbLf 区切りの文字列から、空行を捨て、**初出順**で重複を除き、先頭 maxN 件だけを vbLf 区切りで返す（先頭・末尾に vbLf を付けない）。maxN<1 は空。比較は大小無視・前後空白無視。
- `PerChapterCap(total As Long, nChap As Long, minCap As Long) As Long` … `total \ nChap`。minCap 未満なら minCap。nChap<1 は total。total<1 は minCap。
- `BuildOnePassPrompt` … §2-3。
- `CountLines(boxLf)`（DedupeKeys の結果の件数。空なら 0）。

## §4 作法（CLAUDE.md §10/§11 のうち、この波で踏みやすいもの）

- `Optional ByVal x As Object = Nothing` 禁止／`InStrRev` は2引数／大小違いの同名変数禁止／`And`/`Or` は短絡しない／`On Error` と `Exit` は Err を消すので**ログの前に退避**／1行 1023 字まで／非BMP絵文字は識別子・Const 不可（ChrW で組む）／配列の `ReDim Preserve` は無条件に1回通す／モジュール容量 30,000 字以内（python len）。
- Hit 型（Public Type）は LO でモジュール間の配列受け渡しができない → **Pure テストは文字列・数値だけの純関数に限る**（Hit を跨ぐ関数はテストを書かない。書くと SKIP 上限 14 を押し上げる）。
- 恒真アサート禁止。期待値は定数で書く（実装を呼び直して比較しない）。

## §5 実機受入（出戻り判定・ユーザー向け）

1. 入念で1問聞く → 実況に「🔎 入念(1回読み)」が出る／`usage_log` に `thorough_onepass`（`mode=chapter` か `neighbor`・`chars=`）と `ask_steps` の `thorough_onepass=<ms>` が残る。**秒数**を従来（3分10秒級）と比べる。
2. **リボンの上限**: `chars=` が 20 万字以上の質問で `#ERR` にならず答えが返る。返らない場合は `err_log` に E0202/E0204 が残り、同じ質問が4段で答えられる（自動で落ちる）。→ `onepass_max_chars` を 150000 へ。
3. **精度**: 同じ質問を `thorough_onepass=on/off` で1回ずつ聞き、✅/❌ を付ける（`ask_sources` と `feedback` が材料）。表の値・但し書き・章をまたぐ質問を各1問含める。
4. 章に割れていない本棚（⚡仕上げ未実施・パック由来）で `mode=neighbor` になり答えが出る。
5. 続けて質問（履歴あり）でも1回読みで答え、深掘り候補が付く。
6. **著しく遅い／精度が落ちた**: config `thorough_onepass=off` → 4段へ戻る（ブック開き直し）。

### §5-2 テスター向けの手順（髙橋さんに渡す文面・Gemini 3.8 flash 下書き→司令塔が典拠照合）

**事前準備**: 画面下のシート一覧で「config」の隣に「usage_log」があるか確認。無ければシート見出しを右クリック→「再表示」→ usage_log。

**① 1問聞いて動作と表示を確認する**
- やること: 聞き方を「🔬 入念に調べる」にして1問送る。回答後、usage_log の最新行を見る。
- 期待: 処理中に「🔎 入念(1回読み): N章・M箇所を読んで回答を作成中… ※応答なし表示でも処理中」と出る。usage_log に `thorough_onepass`（詳細に `mode=chapter` か `neighbor`・`chars=`）と、`ask_steps` の中に `thorough_onepass=<ミリ秒>` が残る。従来の入念（3分10秒級）より短いか、秒数をメモ。
- NG: 表示が出ない／usage_log に `onepass_fallback`（材料が組めず4段へ落ちた）か `onepass_llm_err`（AI 呼び出し自体の失敗。回答欄に `#ERR` が出る）がある → `why=` の後ろをそのまま共有。

**② 長い本文（20万字超）でエラーにならないか**
- やること: usage_log の `chars=` が 200000 以上になる質問（大きい規程で章をまたぐ質問）を1問。
- 期待: 回答欄に `#ERR` が出ず答えが返る。
- NG: 答えが返らない／err_log に E0202・E0204 → config の `onepass_max_chars` を 300000→150000 にして保存し開き直して再試行（それでも駄目なら `thorough_onepass=off`）。

**③ 新旧で精度を比べる**
- やること: 「表の値を聞く」「但し書き・例外を聞く」「複数の章にまたがる」の3問を、config の `thorough_onepass` を `on` と `off` で1回ずつ（変更のたびにブックを開き直す）。それぞれ ✅/❌ を押す。**質問は1文で書く**（「？」や句点で2つに割れる質問は入念だと自動で「論点の分解」へ行き、1回読みを通らない）。採点の前に usage_log の最新行が `thorough_onepass` であることを確かめる（`global_answer` や `decompose` なら別経路）。
- 期待: どちらでも答えと根拠が正しい。
- NG: `on` のときだけ抜ける・間違える → 質問文と on/off それぞれの回答を共有。

**④ 章に割れていない本棚で**
- やること: ⚡仕上げをしていない本棚、またはパックから取り込んだ資料に対して入念で1問。
- 期待: エラーにならず答えが返り、usage_log に `mode=neighbor`。
- NG: `why=` を共有。

**⑤ 続けて質問で**
- やること: 回答のあと「続けて質問」で追加の質問。
- 期待: 続きでも1回読みで答え、末尾に深掘り候補が付く。
- NG: 文脈が切れる／候補が出ない → 共有。

**戻し方**: 著しく遅い・精度が落ちた → config `thorough_onepass=off` → 保存 → 開き直し。
