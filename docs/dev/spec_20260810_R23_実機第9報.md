## R23-1 自己インストーラの無言失敗根治【最優先・配布ブロッカー】

### 根本原因（班1調査で確定）

配布 xlsm はモジュール0本の骨格で、起動時に `vba_src` シートから全135本を VBE 注入する設計。インストーラ実体は `build/build_mybookshelf.py:1199-1267` の `_INSTALLER_SRC_TEXT`（ThisWorkbook ストリームへ外科パッチ、**src/ 配下に VBA ソースは存在しない**。凍結モジュール modBoot は不触で完結）。

現行コードの穴（`:1225-1236`）: `On Error Resume Next` 下で失敗カウンタ `f` が増えるのは **`VBComponents.Add` が Nothing を返した場合だけ**。`c.Name = n` の失敗も `AddFromString s` の失敗も握り潰され、「名前だけ付いた空モジュール」でも `f=0` のまま `:1244` の Setup incomplete ガードを素通りし、`:1248 ThisWorkbook.Save` で**破損状態がファイルに焼き付く**。R12 未踏観点監査・指摘5（`docs/dev/audit_20260801_R12_未踏観点監査_生報告.md:79-85`）が同じ穴を指摘済みだが未実装だった。

R21 でプロジェクトは 135本/258万字まで単調増大しており、32bit Excel の VBE へ Workbook_Open 中に一括注入する以上、資源起因の単発失敗は今後も起こり得る。**方針: 失敗をゼロにするのではなく、失敗を必ず検出して「壊れた状態の Save」を絶対に通さない**（検問方式と同じ思想）。

### FA-R23-1a インストーラの失敗検出強化

`_INSTALLER_SRC_TEXT` のモジュール注入部を以下の意味へ改める（文言は容量に応じ最適化してよいが意味は厳守）:

```vb
If c Is Nothing Then
  f = f + 1
Else
  Err.Clear
  c.Name = n
  If c.CodeModule.CountOfLines > 0 Then c.CodeModule.DeleteLines 1, c.CodeModule.CountOfLines
  If LenB(s) > 0 Then c.CodeModule.AddFromString s
  If Err.Number <> 0 Then f = f + 1 _
  ElseIf LenB(s) > 0 And c.CodeModule.CountOfLines < 1 Then f = f + 1
End If
```

要件:
1. `c.Name` / `DeleteLines` / `AddFromString` いずれかの失敗（Err.Number≠0）を `f` に計上。
2. **実測検証**: 本文があるはずのモジュール（LenB(s)>0）で注入後 `CountOfLines < 1` なら失敗扱い（Err が立たない无言破損への防御。今回の実機がまさにこれ）。
3. `f > 0` のとき Save しない現行ガードは維持。MsgBox 文言を「保存せずに閉じて開き直せば再試行される」ことが伝わる内容へ変更（ASCII のみ、例: `"Setup incomplete (N modules). Close WITHOUT saving, then reopen this file to retry."` — N は f の値を連結）。ファイル上のペイロードは無傷なので、開き直し＝全量再試行が成立する。

### FA-R23-1b 容量制約下での実装手順【厳守】

- ThisWorkbook ストリームは**元と同じバイト数でしか差し替え不可**。現況実測: 圧縮後 1,096B / 上限 1,148B（**余裕52B**）。
- 追加コードの圧縮後増分がこれを超える場合の削減順序: (i) 既存 MsgBox 文言の短縮 → (ii) 変数名・空白の切り詰め → (iii) それでも不足なら Trust ラベルの文言短縮。**機能の削減は不可**。
- `pad_to_exact` は差分 1/2/4/7B で原理的に到達不能（`:1285-1294`）。ビルドが該当エラーで落ちたら文言を1〜2B増減して再試行。
- ASCII のみ（`build_installer_src` が強制）。VBA 構文は Excel 実機でしか最終確認できないため、**行継続 `_` の直後コメント禁止・1行 If の Else 混在などVBA落とし穴を避けた保守的な構文**で書くこと。
- 検証: `--dev`/`--prod` 両ビルドが通ること（パッチ超過は BuildError で検出される）。さらに注入後の `_INSTALLER_SRC_TEXT` を一時 .bas に書き出し `tools/vba_lint.py` 相当の構文チェックが可能なら通すこと（不可能なら目視2回＋レビュー面で必ず読む）。

### FA-R23-1c verify_build のペイロード本文一致検査【再発防止】

`verify_build()`（`:1461-1508`）は現在「モジュール名の集合」しか照合しておらず、本文の欠落・化けを検出できない。以下を追加:

- ビルド成果物の `vba_src` シート各行の C列文字列が、`src/` の対応ファイルへビルド規則（Attribute 行除去・`_clean()`）を適用した文字列と**完全一致**することを全135本で検査。不一致は BuildError（モジュール名と先頭差分位置を出す）。
- Python 側なので容量制約なし。dev/prod 両方に適用。

### 記録のみ（R23-1 関連・実装しない）

- インストーラ内 `Application.Run "modViewport.OnWindowResized"` 等3箇所のブック名無修飾（他ブック同居時の誤解決リスク。今回の原因ではない。直すなら容量と合わせ次期一括）。
- 失敗モジュールのみの部分リトライ（開き直し全量再試行で代替。52Bに収まらない）。

## R23-2 ヘッダー帯上のボタン視認性【全4画面・全テーマ】

### 対象（班2調査で確定）

`sidebar` 帯 + `ApplyHeaderDepth` グラデ + `sidebarActive` ボタンの同一パターン4箇所:

| 画面 | ファイル:行 | ボタン形状 |
|---|---|---|
| Hub | src/ui/modHub.bas:260-264 | 円形 26×26pt、Line.Visible=0 |
| ダッシュ | src/ui/modDash.bas:401-407 | 角丸ピル HeaderPill |

| チャット | src/ui/modUINexusDraw.bas:338-349, 363-371 | HeaderButton / HeaderTheme |

### FA-R23-2a 白枠線の追加（主対策）

上記4箇所すべてのボタン/ピルへ `Line.Visible = -1`（msoTrue）、`Line.ForeColor.RGB = RGB(255,255,255)`、`Line.Weight = 0.75` を設定。全テーマの帯は暗色（最明でも #0B7D6E）のため、白枠線は常時コントラスト比 3.5:1 以上を確保できる（テーマ分岐不要）。

### FA-R23-2b sidebarActive の明度引き上げ（副対策）

`src/ui/modSkin.bas` の `ResolveColor` で各テーマの `sidebarActive` を以下へ変更（帯との明度差を確保しつつ、ボタン内の白文字が読める暗さ＝白文字コントラスト4.5:1以上を維持）:

| テーマ | 現行 | 新値 |
|---|---|---|
| msad | RGB(1,103,91) | RGB(14,138,123) |
| light | RGB(31,41,55) | RGB(55,65,81) |
| dark | RGB(30,41,59) | RGB(51,65,85) |
| sakura | RGB(112,46,72) | RGB(143,61,94) |
| ocean | RGB(20,56,96) | RGB(29,79,133) |
| gold | RGB(38,34,24) | RGB(61,54,38) |

値の置換のみ（キー追加なし）なので modSkin の容量増はほぼゼロ。`sidebarActive` の他用途（ナビのアクティブ表示等）があれば全 grep で洗い出し、明度引き上げで害が出る箇所が1つでもあれば**変更せず司令塔へ報告**（勝手に判断しない）。

### 容量の取り扱い【厳守】

- modHub.bas 残364字。枠線3プロパティの追加（約90字）は入るが、超える場合は**同モジュール内の既存コメントの等量圧縮のみ許可**（コード削除・意味の変わる圧縮は不可）。作業後に必ず `python3 tools/vba_lint.py --path src` で容量再測定。

### テスト

- modSkin の色値変更は既存ゴールデン（色値 assert があれば）を新値へ追随。無ければ `sidebarActive ≠ sidebar` かつ「msad の sidebarActive = RGB(14,138,123)」を固定する純関数テストを modTestsPure23（余裕があるモジュール）へ追加。
