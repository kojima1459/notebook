# 裁定書 R8: P2P/共有系レビュー14件への対応（裁定: Fable司令塔 / 実装: Opus）

敵対的レビュー(2026-07-31・読取専用)の発見に対する裁定。
実装は R7 完了後に着手(modHub/modBoot が R7 と重なるため直列)。
実装者は【修正】のみ行い、要件外の発見は報告に留めること。

## 最高・高 —【修正】必須

### F1【最高】感謝状がチャンネル経由で構造的に一度も出ない
origin="channel:<部門名>" に対し modP2P.AuthorOfSource が "pack:" しか
解決せず即Exit。C-1(名前空間分離)の副作用リグレッション。
- 裁定: チャンネル取込時(modChannel.SyncChannel→ImportPackFile)に、
  パックのメタデータから発行者IDを取得し `chauth:<チャンネル名>` として
  my_stats へ保存する(H-5 の pkauth と同じ作法)。
  AuthorOfSource は "channel:" 接頭辞のとき chauth から解決する。
  発行者IDが取れない旧パックは従来どおり感謝なし(静かにExit)でよい。
- modP2P 冒頭の設計コメント(pack:前提)も現実に合わせて更新。
- 純ロジックに切り出せる解決関数はテストを書く。

### F4【高・データ喪失】失効タイマーがダミー共有パスでも進行し30日で全消去
- 裁定(2段構え):
  a) modGuard.EnforceExpiry に「一度も共有へ到達した記録が無い端末は
     絶対に消さない」を追加(guard_last_reach が空なら警告もスキップし、
     usage_log に1行だけ残す)。消してよいのは「かつて届いていたのに
     30日届かない」端末だけ、が本来の設計意図。
  b) build_config_rows に `knowledge_expire_days`(既定30、説明に
     「0で無効。PoC中は0推奨」)を追加し、管理者が画面から制御可能にする。
- docs/30_運用保守ガイド と 43系に注意書きを追記。

### F5【高】modShare.ResetProbe が未配線(設定し直しても復活しない)
- 裁定: modHelp.OnShareSetup で SetValue 直後に modShare.ResetProbe を
  呼ぶ。トースト文言は Reachable() を再評価してから出す(嘘をつかない)。

### F6【高】到達性プローブが「存在」でなく「中身1件以上」を見ている
空の健全な共有ルートで share_unreachable になり、フォルダを作る側が
全員 modShare 経由のため誰も初期化できないデッドロック。
- 裁定: プローブを GetAttr(パス末尾の\を除去した形) And vbDirectory の
  判定へ変更(空フォルダでも真。エラーはトラップ)。
  modP2P.CollectNoiseVotes 内の独自プローブ(末尾\無しのDir)は廃止し
  modShare.Reachable()/SubDir に一本化。
- 初回OK時に modShare 側で標準サブフォルダ(thanks/noise/insight/
  telemetry/board/channels)を EnsureDir する「初期化の入口」を1箇所作る。

### F2【高】modBoard/modPublish/modMentor が modShare の関所をバイパス
- 裁定: 3モジュールのパス組み立てを modShare.SubDir / Reachable ガード
  経由に統一。BootBoard は Reachable() が偽なら即Exit。
  (modShare が唯一の到達判定・唯一のルート解決である状態に戻す)

### F3【高】起動ジッタ前に最重量の共有I/Oが走る
- 裁定: (1) modBoot の StartupJitter を、共有I/Oを伴う最初の処理より
  前へ移動。(2) modHub.DrawInbox の PendingUpdates は起動時は
  実行せず「押して確認」のプレースホルダ表示とし、mBooted 後の再描画
  でのみ実クエリ(結果は10分TTLでキャッシュ)。
  (3) modChannel の RemoteVersion 2回読みを1回に(変数へ受ける)。

### F11【高相当・信頼性】取込失敗を「すべて最新です」と報告する
- 裁定: SyncAll系で失敗件数(failN)を数え、
  okN=0 かつ failN>0 なら「N部門を読み込めませんでした(発行中の
  可能性。少し待って再実行してください)」と正直に表示。R4方針の徹底。

## 中 —【修正】(同バッチで実施)

### F12 同時発行の版ズレ+共有への直接SaveAs
- 裁定: (1) 発行はローカル%TEMP%へSaveAs→共有へFileCopy→version.txt、
  の順に変更(書込み窓を短縮)。(2) `publish.lock`(作者ID+時刻)を
  発行開始時に作成・終了時に削除。存在し10分未満なら発行を拒否して
  案内。10分超は残骸とみなし上書き続行。
### F8 「みんなの節約(今日)」が構造的にほぼ0
- 裁定: PublishBeacon を Public 化し、FeedbackGreen(自己解決加算)後に
  Reachable ガード+10分スロットル付きで再発信。
### F9 ビーコン読みが人数線形×Hub再描画のたび
- 裁定: RefreshBoard に10分TTLキャッシュ(前回集計時刻を持ち、
  TTL内は再読しない)。強制更新はダッシュボードの「更新」だけ許す。
  (集約スナップショット方式はPoC後の課題としてコメントに明記)
### F10 modInsight にGCが無く my_stats も無限成長
- 裁定: GcOldThanks と同作法の GcOldInsights(30日超のqa/gapファイル削除)
  + ins: nonce の GcOldNonces 適用 + CollectFrom は my_stats の ins: を
  1回の一括読みで既読集合(Dictionary)化してから照合する。
### F13 MAX_CHANNELS=40超が無警告で消える
- 裁定: 41件目を検出したら err_log に1行 + Hub の受信箱に注意表示。
### F14 GcOldThanks が未受領の長期不在者宛も30日で削除
- 裁定: 保持を60日へ延長し、コメントの誤った前提を修正。

## 受容(今回直さない・理由)
- 12,000人規模のビーコン集約スナップショット化: PoC規模(数十人)では
  TTLキャッシュで十分。本格展開の設計課題として記録。
- OK→NG動的降格(F7): セッション途中のVPN切断は、リトライ回数の上限が
  各所3回で有限であり、F9のTTLと F3 の遅延化で頻度が大きく下がる。
  完全な降格機構は状態管理が複雑になるため次期。ただし modShare に
  ReportFailure(失敗記録の受け口)だけ用意し、連続5回で NG へ倒す
  最小実装は許可(実装者判断で入れてよい)。
