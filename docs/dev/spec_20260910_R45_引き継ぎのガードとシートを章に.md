| 問い | ユーザーの裁定 |

## §1. 一般モードへ引き継いだ文脈のガード（R45-A）

### 何が起きていたか

一般モード（壁打ち）の指示文には**事実面のガードが1本も入らない**
（`modApp.bas:191` が `extraRules` に空文字を渡し、`modAppState.bas:268` の
`If LenB(extraRules) > 0` で何も足されない）。`modLive.EmptyShelfGuard` は
**本棚が空のときにしか**届かない。

そこへモード切替の橋渡し（`modConvBridge`）が
**【直前の社内ナレッジ検索での文脈】として社内資料由来の回答本文**を流し込む。
運ばれるのは `modAsk` が控えた `mLastCleanAnswer` で、
**R44 の常設ガード「※…」も低関連度の ⚠ も含まれない**
（どちらも `modAsk.bas:283` で**その後に**足す表示専用の飾りだから）。
つまり画面には「社内資料は未使用」と出ているのに、中身は社内回答を引き継いでいる。
しかも `TrimPairs` により**最大 `followup_max_pairs` 往復ぶん再送**される。

### 裁定

`modGenPipe.CarryRules()`（純関数）を新設し、
**橋渡しヘッダーがあるターンだけ** `modAppState` から1行で足す。

```
・直前の会話に「【直前の社内ナレッジ検索での文脈】」が含まれる場合、
  そこに出てくる会社固有の条件・金額・期限・条文番号・様式は、
  自分の知識で断定し直さず「社内ナレッジ検索で確認した内容です。
  原文は出典でお確かめください」と一言を添える。
・会話に出ている情報を根拠として使うこと自体は問題ない。
```

**文言の要件は反証班の指摘をそのまま守った**:

- **「社内資料は一切使えない」とは書かない。** `conv_bridge` は既定 TRUE なので、
  そう書くと**直前に出典付きで確定した数字まで撤回**させる
  （R29 W1-2 で潰した文脈断線と同型の事故）。
- **「会話に出ている情報を根拠として使うこと自体は問題ない」を明示**する。
- 止めるのは**断定して言い直すこと**だけ。壁打ち（下書き作成・言い回しの相談）は潰さない。

**無条件には入れない。** 存在しない会話を指す指示だけが残ると、
モデルがその会話について語り出す（`modGenPipe.bas:409-415` に同型の実害記録）。

判定は `modConvBridge.HasBridgeHeader`（純関数・新設）。
**`Left$` ではなく `InStr` で見る**——一般モードで1往復進むと新しい回答が
先頭へ積まれ（`modAppState.bas:321` の `;;;` 連結）、ヘッダーは途中へ移るため。
前後2つの印（`HEADER_PREFIX` と `HEADER_TAIL`）を**両方**見るので、
本文に「【直前の…」が偶然現れても誤検知しない。
ヘッダーの後半は `HEADER_TAIL` として**単一情報源化**した
（`WithBridgeHeader` が組み立て、`HasBridgeHeader` が探す。片方だけ変えると検出が静かに外れる）。

**凍結モジュールは不触**（`modApp` は残245字なので触らず、`modAppState` 側へ1行）。

## §2. Excel の「シート＝章」（R45-B）

### 何が起きていたか

`modChunker.ClassifyLine` は、Excel の行を**章にも節にも一度も分類しない**。

- 2セル以上の行 → タブがあるので **4（表行）**
- 値1個の行 → R43 のセル番地前置 `[A5]` があるので `Left$` 判定が全滅して **0（本文）**

結果 `ChunkAllPagesStructured` は**ブック全体を1ブロック**として扱い、
`chapter`/`section` に一度も代入されず、breadcrumb は `【〔資料〕】` だけ、
`modChunkMeta.ExtractSectionPath` は必ず空を返す。
**structure モードの構造化が Excel 資料に対して何もしていなかった。**

その結果、`section_path` に依存する層が Excel では全滅していた:
章要約 `doc_outline`／俯瞰質問（`modAskGlobal`）／`doc_links`・`doc_centroids`／
参照展開 `RefsExpand`／条番号の直接ヒット保証。

### 裁定

シート本文の1行目を **`# シート: 名前`** にする（`modExtractorExcel.SheetHeadingLine`・純関数）。
`ClassifyLine` の「`#` 1個＋空白」で**章**に分類され、シートごとにブロックが割れる。

**`【…】` を選ばない理由**: `ClassifyLine` は60字以内の `【…】` も章と見なすが、
`StripHeadingMark` が外すのは `#` だけなので、chapter が `【シート: 名前】` のまま
breadcrumb に入り `【〔資料〕 > 【シート: 名前】】` と**二重括弧**になる。

表記を変えるときは `ClassifyLine` の条件と `StripHeadingMark` の**両方**を見ること
（`modTestsPure48` の G7 が、抽出側の実物を分類器に食わせて固定する）。

### 効果の実測（正直に）

教えてBOX ナレッジ5ファイル（43シート・10,996かけら）で、旧挙動と新挙動を比べた。

| 測ったこと | 旧（ブック全体が1ブロック） | 新（シート＝章） |
|---|---|---|
| かけら数 | 10,987 | 10,996（+9） |
| 伏せた実データ300件・上位5件 | 66.0% | **66.0%（変化なし）** |
| 口語の言い換え32件・上位5件 | 62.5% | **62.5%（変化なし）** |

**点で当てる検索の精度は動かない。** これは正直に書いておく。
効くのは別のところ:

1. **俯瞰質問が Excel でも成立する**（章要約が作られるようになるため）。
   「この分野の全体像は」「最近よく聞かれることは」に答えられる。
2. **かけらがシートをまたがなくなる。** 旧挙動ではシート境界を跨いだかけらが
   ファイルあたり数個でき、その尾部の内容が**別シートの番号で出典表示**されていた
   （出典のシート番号が実際と違う。全体の 0.4% 程度）。
3. breadcrumb にシート名（＝分野名）が入り、埋め込みの手がかりが1つ増える。

### 代償（開示）

- **取り込み時に「章の仕上げ」が走る。シート1つにつきAIを1回呼ぶ**
  （5ファイル計43回。上限は1資料60章）。**取り込みが長くなる。**
- **配布済みの部門ナレッジは入れ直しが必要**（取り込み結果が変わるため）。
- プレビューと本文ビューに `# シート: 名前` の `#` が見える（軽微）。
