# R14 要件定義: 実機テスト第3報への対応(2026-08-03)

基点: b53d1d8(R13完了)。裁定者: Fable。実装: Opus/Sonnet。判定基準: docs/dev/00_プロダクト憲章.md。
調査8班の根本原因(全てfile:line証拠つき)を前提とする。

## 根本原因(確定)

RC1. 質問カウンタ欠落: ask_quick_total+ask_deep_total の2キー決め打ちが3箇所
     (modHubStat.AskTotal:171-173 / modTelemetry:62-63 / modPrompts:415)。
     ask_thorough_total が全箇所で漏れ。実機の「質問1(実際3)」と厳密一致。
RC2. 一般モードの解決ボタン拒否: mLastQuestion は modAsk.AnswerWithContext:281 でのみ
     設定され、modAppState.AskGeneral は独立経路。さらに単純解禁すると
     EmitThanksForLastAnswer が残留 mLastHits から過去RAG出典へ誤感謝状、
     EmitVerifiedQA が残留 mLastCleanAnswer で誤共有の危険(調査で確定)。
RC3. 0バイトコピー: CopySharedRead はコピー元をクラシック Open(ANSI/CP932)で開く。
     NFD名は Open For Binary の「無ければ作る」挙動で0バイト実体を掴み、LOF=0 →
     「0バイトは空のままコピー成立」仕様で dest 0バイト+True。GSは空PSとして
     rc=0/バナーのみで即終了(実機ログと完全一致)。localcopy=ok と嘘の記録。
RC4. OCR上限20頁: vision_pdf_max_pages 既定20。超過分は永久欠落なのに partial メモは
     「同期を押すと続きから再開します」(嘘、再開ロジックなし)。Visionループ
     (optVision:447-492)は DoEvents ゼロ+ChatGPTV にタイムアウト無し=フリーズ主因。
     画像後始末は最後に一括のみ。
RC5. 着せ替え: (A)Knowledge/Dash の🎨→modHub.OnThemeToggle は Nexus+Hub しか再彩色せず
     押した画面が変わらない(「わからない」の実体)。(B)太陽/月トグルが解放済み
     sakura/ocean/gold を無警告で dark 上書き。(C)ToggleTheme が BeautifyAll を呼ばず
     グラデ退行。(D)nx_fchip/nx_help_* が ApplyTheme 対象外。(E)ApplyTheme系に
     OERN欠落+Repaint の ScreenUpdating 復旧漏れ経路。
RC6. 質問例: 実行時生成コードが存在しない(ビルド時 make_seed_pack.py 専用)。
     全取込経路(チャット/ナレッジ/同期)で生成されないのは仕様ではなく未実装。
RC7. チャンク粗さ: FlushBlock の atomic-keep 閾値 chunk_max_chars=1800 が支配的。
     Excel の細かさは行長とスライディング分割境界の偶然の一致。拡張子別設定なし。
RC8. deep/thorough 無差別: 生成側(draft/verify の effort/verbosity/model)完全共有。
     検証は1発生成で、機械的な出典タグ突合は皆無。
RC9. 回答描画は完全プレーンテキスト(.TextRange.Text)。段落書式は vbCr 区切りでのみ
     可能(modLive.StyleFooter が前例)。optMarkdown はチャット表示に無関係。
RC10. ヘッダー右ズレ: ピルは FlowRight(右端密着)、ツールバーは FlowLeft(左詰め)の
     非対称。ギャラリー無反応: ws Is Nothing 無言Exit(modVaultGallery:49-50) +
     既にギャラリー表示中の再押下はフィードバック皆無。

## 実装項目

### R14-1 カウンタと一般モードfeedback [P0]
1a. modStats に Public Function AskTotalAll() As Long (quick+deep+thorough) を新設し、
    modHubStat.AskTotal / modTelemetry(3行目としてask_thorough出力も追加) /
    modPrompts.UserContextBlock の3箇所を置換。
1b. 一般モード回答後の「解決した」を有効化:
    - modAsk に Public Sub NoteGeneralAnswered(ByVal q As String) 新設:
      mLastQuestion=q / mLastMode="general" / mLastCleanAnswer="" / mLastNHits=0 /
      mFeedbackDone=False。modAppState.AskGeneral 成功時に1行呼ぶ。
    - FeedbackGreen 内: EmitVerifiedQA と EmitThanksForLastAnswer は
      mLastMode<>"general" かつ mLastNHits>0 のときのみ(残留誤爆の恒久防止)。
      selfsolve_total / sv:キー / feedback_green(mode="general") は一般モードでも加算。
    - 純テスト: ガード条件の真理表(モード×NHits)。

### R14-2 ナレッジ画面ヘッダー整列+ギャラリー [P1]
2a. modKnowledgeBar.ToolbarContentRight(純関数)新設、modKnowledge.DrawChrome の
    FlowRight アンカーを「ツールバー実右端(異常値はL+W-8へフォールバック)」に変更。
2b. modVaultGallery.ShowVaultGallery:49-50 の無言Exitに E0801 LogError+トースト追加
    (RedrawGallery:141-145と同型)。既にギャラリー表示中の再押下は
    「表示を更新しました」トースト(押下が効いた実感)。

### R14-3 コピーの根治 [P0]
3a. CopySharedRead を ADODB.Stream Type=1(binary) LoadFromFile/SaveToFile へ置換
    (modUtilText の10箇所実績パターン踏襲、FSO等の新規依存なし)。
    st.Size(元サイズ)と FileLen(dest ASCII安全名)の突合を必須化。不一致/元非ゼロで
    dest=0 は失敗: dest Kill+空文字返し+outReason="size_mismatch"。
3b. 失敗時のユーザー文言「共有のファイルを読み取れませんでした(ファイル名の特殊文字が
    原因の可能性)。ファイル名を変えてから再度お試しください」を modExtractor /
    modShelfVision の失敗メモへ配線。copyNote は検証済みかどうかで ok/failed を出す。
3c. optOcrCore.ClassifyGsTextResult に Optional gsInputBytes(=-1): 0 なら "emptyinput"。
    optGsTxt 側は FileLen 1行+引数追加のみ。真理表テスト追随。

### R14-4 OCR全量取込 [P0]
4a. 新モジュール src/opt/optOcrPage.bas: バッチ制御(GSを20頁ずつ FirstPage/LastPage で
    複数回起動)、バッチ完了ごとに該当jpgを逐次Kill、各頁の TryRibbonRun 前後に
    DoEvents、頁ごとに経過ms を計測し usage_log "vision_page_ms" をバッチ単位で集約
    記録。OcrRenderedPages 本体ロジックを optVision から移設(optVision は呼び出しへ)。
    注: 同期 Application.Run 中のハード中断は不可能(制約として記録)。DoEvents と
    頁間チェックで「1頁分以上は固まらない」構造にする。
4b. vision_pdf_max_pages 既定 20→100(build config、PAGES_MAX=200内)。
    進捗バナー「OCR中… p/N頁 (バッチ b/B) 残り約s秒」(頁レートからETA)。
    画像化待ちにも「画像化中… バッチb/B」。
4c. 正直なメモ: optOcrCore.OcrCapMemoFor 新設。「上限Nページのためx/y頁のみ取り込み
    ました(設定 vision_pdf_max_pages で変更可)」。modUIShelf.BuildMemo の partial 分岐が
    errorNote を実際に使う形へ修正(「同期で続きから再開」の嘘文言廃止)。

### R14-5 チャンク粒度(PDF/Word) [P1]
5a. modShelf に拡張子別2段フォールバックヘルパー(ChunkParamFor(key, ext)):
    "chunk_target_chars_" & ext → グローバル → 既定。modChunker は触らない(残38字)。
5b. build config 追加: chunk_max_chars_pdf=900 / chunk_target_chars_pdf=450 /
    chunk_overlap_chars_pdf=100、docx/doc 同値。xlsx/グローバル既定は不変。
5c. 新テスト(modTestsPure11 新設): ヘルパーのフォールバック表。
    註: 既存資料は再取込しない限り不変。同一資料の再取込は旧チャンク残置+新チャンク
    追加になるため、報告書で「入れ直す場合は先に削除」を案内(コード変更なし)。

### R14-6 着せ替えの信頼回復 [P1]
6a. modHub.OnThemeToggle: ActiveSheet で分岐し、Knowledge なら RefreshCurrent、
    Dash なら ShowDashboard を追加で呼ぶ(押した画面が必ず変わる)。
6b. modUI.ToggleTheme: 現テーマが light/dark 以外(解放スキン)のときは上書きせず
    トースト「特別スキン使用中です。🎨着せ替えで変更できます」。light/dark 間のみ
    トグル。ApplyTheme 直後に BeautifyAll を追加(グラデ退行解消)。
6c. modSkin.ApplyTheme: nx_fchip / nx_help_* の分岐追加。ループ本体と
    PaintBubble/PaintActionButton の Fill/Line 代入を OERN 保護。modUI.Repaint は
    エラー時も ScreenUpdating=True へ必ず到達する構造へ。
6d. 報告書に「何が変わるか」の確認手順を記載(テーマごとの目視ポイント)。

### R14-7 質問例のオンデマンド生成 [P1]
7a. modStarter.OnShowList: シード0でも my_knowledge に実データがあれば生成経路へ。
    キャッシュ(modState キー my_questions_cache / my_questions_srcsig=資料数+最新日)が
    有効ならそれを表示。無効なら modGateway.CallLLM 1回(modPrompts.BuildQuestionsPrompt
    新設: 直近ソースの要約/norm_text 断片から質問5件生成)→キャッシュ保存→表示。
    生成中は StageBanner/SetStage「質問例を作成中…」。失敗時は従来文言+E系ログ。
7b. 取込完了(非silent)で srcsig が変わりキャッシュ自然失効(取込側の変更は不要)。

### R14-8 入念モードの本格強化+回答可読性 [P1]
8a. 新モジュール src/qa/modAskThorough.bas: thorough 専用6段:
    (1)再ランク(rerank_effort_thorough=medium 新config) → (2)ソースバッチ要約
    (BuildEnrichPrompt 同型の新 BuildSourceDigestPrompt、1呼び出し、下書きへは
    「要約+原文抜粋」ハイブリッド) → (3)下書き(thorough_draft_effort=high/verbosity=high
    新config) → (4)自己批判(BuildCritiquePrompt 新設: 未検証断定・出典不備・論点漏れ
    の指摘のみ、1呼び出し) → (5)検証(BuildDeepVerifyPrompt に批判文を渡す拡張) →
    (6)機械的出典突合(VBA純ロジック: 回答中の[本棚:名 p.N]タグを抽出し hits() と照合、
    不一致タグは「(出典確認できず)」を付記+usage_log "cite_mismatch")。
    deep/quick は不変。段階実況は AskStage 機構を6段に拡張。ask_steps 集約は継続。
8b. モード説明更新: すぐ聞く=速さ優先 / 深掘り=会話の流れを深く / 入念=時間をかけて
    多段検証(2〜4分)。
8c. 可読性: (i)modLive(余裕あり)に純関数 NormalizeAnswerText: markdown混入の保険変換
    (行頭"# "→■ / **x**→【x】 / 行頭"- "→・)+ブロック間空行正規化。
    (ii)バブル本文を vbCr 段落へ(フッター機構と整合、modLive.StyleFooter 前例)。
    (iii)StyleAnswerParas 新設: ■始まり段落を Font.Bold=True(Paragraphs(n).Font 方式、
    全体OERN)。modUI 側は呼び出し行のみ。
    (iv)8a(6)の突合と合わせ、引用タグの表示形は現行維持。
