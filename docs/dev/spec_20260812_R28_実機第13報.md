## 前提となる調査確定事項

- R27までの余白修正は「塗りを内容下端で打ち止め」する設計であり、ホイール素通り(実機実証済み)の下では原理的に無力。R27の「塗り継続」実体はdash限定の埋め草13ptのみ。
- hub は paintAddr(切り上げ)未使用で常時10pt未塗り帯。shelf-table は paintBg=False で地色ゼロ塗り(darkテーマで全面白のはず)。chat は Rows("1:400").RowHeight=18 で約14画面分がスクロール域。
- 逆質問断線: (1) modClarify.PickSource/PickIntent が半角数字しか照合しない(modClarify.bas:398-421)一方、IsNumberChoiceOnly は全角・丸数字を受理する(同351-387)ため、全角回答で資料選択だけが消失。(2) 「対象の資料:」はクエリ文字列ヒントに過ぎず、検索は scopeSources 無しの本棚全体(modAskRetrieve.bas:423-427)。(3) 深掘りボタンは無条件描画だが逆質問ターンは履歴に積まれず必ず断られる(modAppAct.bas:149-153)。
- 橋渡し(modConvBridge)は OnToggleMode 発火・1往復固定。モード内会話は followup_max_pairs 既定3。一般→RAG方向は modAsk.mPrevU が非空だと state を再読込せず、切替前の古いRAG会話が深掘りに使われる実害を確認。OnClearChat は state のみ消し mPrevU 亡霊が残る(HANDOFF M-4)。
- Hub幽霊文字: modUIMain.SetStage/RenderSourcesPreview/ShowTip(modUIMain.bas:333-580)が画面状態を見ずに SH_HOME の固定セル(A12/A14:H25/A26:H27/A33:H34)へ書く。Hub は同じ物理シート。入念モードのDoEvents中に画面遷移すると再入で発症。
- ギャラリー: CARDS_PER_PAGE=9 固定(modVaultGallery.bas:24)。R21裁定は縦充足のみ根拠で、5列×2段=10枠と不整合。
- トースト: modSkin.ShowToast は高さ34pt固定(modSkin.bas:380)。入念モードのDescription約130字が1行で切れる=「社内ナ」。
- 「AI要約中x/30」「章の要約1/1」は仕様どおり(R17小口バッチ/俯瞰索引)。修正は文言明示のみ。
- activate_recovered err#91 は R10 で原因確定済みの自己回復ログ。対応不要。

## 波1(Opus): ①下余白の根治 — Normalスタイル方式

**設計思想の反転**: 「背景を内容に合わせて塗る」を廃し「背景は無限に存在し、その上に内容を載せる」へ。既存の塗り・境界・埋め草は**一切削除しない**(二重防御として残す。剥がす作業はリスクなのでしない)。

1. **W1-1** `modChrome` に `Public Sub ApplyNormalStyleBg()` を新設: `ThisWorkbook.Styles("Normal").Interior.Color = modUI.UiColor("bg")`。冪等ガード(現在色と同じならスキップ)+`On Error Resume Nextで包み、失敗時は無害に既存塗りへフォールバック(Err退避・リセット作法遵守)。
2. **W1-2** 呼び口: `modChrome.SetupHubColumns/SetupDashColumns/SetupShelfColumns/SetupChatColumns` の4関数冒頭に1行ずつ(=6描画経路すべてを被覆。modBoot凍結のため起動時フックはここで代替する)。テーマ切替は `modSkin.ApplyTheme` 内に1行(modSkin残676字に収まる約40字。入らなければ modViewport2 経由に変更し司令塔へ報告)。
3. **W1-3** `modSkin.ExtendChatBand` の縮小分岐(xlNone当て、modSkin.bas:481-495)は **変更しない**。xlNone=Normal継承=bg色となり整合するはず。ただしレビュー観点として明記。
4. **W1-4** shelf-table の paintBg=False(modUIShelf.bas:390)も**変更しない**(Normalで自動解決。modUIShelf残464字のため不触)。
5. **W1-5** LO制約: Styles("Normal")はLO実行時に差異がありうるため、W1-1のOn Error保護を必須とする。LO compile/pure が通ること。純関数テスト対象なし(描画のみ)のため、ネガティブ確認は「UiColor("bg")の値検証」既存テストで代替し、実機確認観点を配布報告に記載。

**繋ぎ目**: UsedRange依存の座標計算は無し(調査確定)。modIntegrity膨張警告はスタイル変更では発火しない(UsedRange不変)。veryHiddenデータシートにも色が付くが表示されないため実害なし。

## 波2(Opus): ②逆質問の根治

1. **W2-1 番号パーサ統一**: `modClarify` に Public純関数 `ParseClarifyReply(reply, nSrc, ByRef srcIdx, ByRef intentIdx)` を新設し、`modRagParse.ParseChoiceNumbers` と同じ正規化(全角０-９→半角、①-⑳→数値)で読む。規則: 抽出した数列の1個目=資料番号(1..nSrc内のみ採用、0=選択なし)、丸数字または2個目の数=意図番号(1..5)。`PickSource`/`PickIntent` を本関数経由に置換。LOテスト(新設 modTestsPure28 か余裕のある既存): 「2-②」「１－①」「①」「0」「3」半角/全角の全組合せ+ネガティブ確認。
2. **W2-2 検索スコープ配線**: `MergeAnswer` で資料確定時に ui_state キー `clarify_pick_src` へ資料名を保存(0選択時は立てない)。`modAskRetrieve.RunUnscoped` 入口で読み、非空なら `modFollowup.ScopeDictFrom` 相当で scopeSources を構築して `modRetrieve.Search/RunMultiRetrieve` の既存 scope 引数へ渡し、**読んだ直後に必ず消す**(1ターン限り)。スコープ内ヒット不足時は本棚全体へ広げ直し `usage_log` に `clarify_scope_widen` を記録(RunDeepScoped の既存作法 modAskRetrieve.bas:345-355 と同型)。実体関数は modClarify か modFollowup に置き、modAskRetrieve への追記は呼び出し2〜3行以内(残2,024字厳守・WARN帯に入れない)。
3. **W2-3 ボタン導線**: `modAppAct.OnActDrill` 冒頭に `modClarify.HasPending()` 分岐: トースト「逆質問にお答えください。下の入力欄に番号(例: 1-①)を入れて送信してください」+`modUI.ParkFocus`。既存ガードより前に置く。
4. **W2-4 逆質問文面**: `BuildClarifyPrompt` の末尾文言を「下の入力欄に『2-②』のように番号だけ入れて送信してください」へ(「どこに入力するか」を明示)。
5. **W2-5 入力欄Text書式**: `modUINexusDraw.DrawInputArea` に `.NumberFormat = "@"` を1行(残900字内・約30字)。半角「1-3」の日付化を根絶。
6. **記録のみ(次期)**: 逆質問バブルに👍💾等が作用する件/合成後クエリが画面に出ない件/clarify合成followupでのDemoteUsed降格(W2-3のガードで入口は塞がる)。

**繋ぎ目**: 通常質問(clarify_pick_src無し)の検索経路が1バイトも変わらないこと(スコープキー不在時は既存コードパスへ素通し)をレビュー最重点とする。
