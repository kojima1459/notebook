# Security

## APIキー秘匿の限界 (Mode B = MVP)

Mode B (難読化埋め込み) はAPIキーを **XOR + Base64** で xlsm に埋め込み、VBAプロジェクトをパスワード保護する方式である。

### 何を防ぐか

- **一般ユーザーが xlsm を開いて中身を見る** → 防げる。シートには何も書かない。
- **VBAエディタを開いてコードを覗く** → 防げる (VBAプロジェクトパスワード)。
- **手元の Excel から `Environ$`/シートに出力させて取り出す** → コードがパスワード保護されていれば呼べない。

### 何を防げないか

- **xlsm をバイナリ解析する** (zipとして展開し vbaProject.bin を抽出) → 防げない。
  VBAプロジェクトパスワードは古い 32bit/40bit のハッシュで、無料ツールで突破可能。
- **メモリダンプ** → 防げない。
- **同じビルドの xlsm を複製して pad を再現する** → 防げない (pad はビルド定数)。

### 結論

Mode B は「営業担当者が普段使う範囲で見えないようにする」 obfuscation であり、**暗号化ではない**。情シスや本気の攻撃者には通用しない。

## 推奨される将来移行先 (Mode A)

クライアントには API キーを置かない構成:

```
[Chatbot.xlsm] --HTTPS--> [Azure Functions (relay)] --api-key--> [Azure OpenAI]
                              |
                              +-- Entra ID で利用者を認証
                              +-- レート制限 / コスト集計
                              +-- 監査ログ (immutable)
```

- クライアントは Entra ID トークンを `Authorization: Bearer` で送るだけ。
- 真のキーは Azure Functions の Key Vault 参照に閉じ込められる。
- 退職者・離任者は Entra ID の所属変更だけで即時遮断できる。

`modApiGateway` は `Mode A` を想定して 初日から抽象化済み。Phase 2 でルーティング先を変えるだけで切替可能。

## 利用ログの取り扱い

- 既定では **質問本文は記録しない** (`has_question_text=0`)。
- ユーザーが UI 上の「ナレッジ改善に質問本文を提供する」チェックを ON にした時のみ記録。
- メタデータ (タイムスタンプ・ユーザー・部署・トークン数・遅延・PIIフラグ) は常に記録 (利用管理目的)。
- ログは SharePoint 上の **個人別 CSV** に保存し、管理者だけが束ねて閲覧。

## PII対策

- `modPiiGuard` で電話/メール/マイナンバー/契約番号らしきパターンを検知し、送信前に警告。
- システムプロンプトでも「個人情報を含む質問には回答しない」と指示。
- 検知時はログのフラグ列に記録し、運用で監視可能にする。

## レート制限

- クライアント側の rate limit (1日100質問 / 1時間30質問) は **コスト暴走の最終防衛線**。
- 本物の上限はサーバー側 (Mode A 移行時) で持つべき。
- 値は `config.ini` で運用調整可能。
