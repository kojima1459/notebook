> **この文書は誰向けか**: 配布後の「マイ本棚AI」を保守する**非エンジニアの保守担当**向けです。
> **何が分かるか**: エラーコードの意味と対処、🩺診断レポートの読み方、ログの見方、
> 月次集計のやり方、困ったときの切り分け手順、既知の制限が分かります。

## 1. エラーコード表(E0101〜E0901)

利用者が「使い方」で困ったとき、画面には必ず「何が起きたか」+「どうすればよいか」の
2文と、末尾に `(コード: Exxxx)` が表示されます。このコードで下表を引いてください。
「ユーザーに見える文言」列は、実装(`src/core/modLog.bas` の `FriendlyMessage`)から
そのまま転記したものです(言い回しを変えたい場合は必ずコードを直してから再ビルドしてください)。

### 1-1. 基盤・AI呼び出し系

| コード | 意味 | ユーザーに見える文言 | よくある原因 | 保守者の対処 |
|---|---|---|---|---|
| E0101 | `config`シートに必要な項目が無い | 設定ファイル(configシート)に必要な項目が見つかりません。配布元にこのファイルの再入手を依頼してください。 | 古いバージョンのファイルを使い続けている/configシートを誤って編集・削除した | 最新の配布物(`--prod`でビルドし直したもの)を渡し直す。configシートを直接編集しないよう案内する |
| E0102 | Windows Script Runtime不可 | この端末では検索機能に必要な部品(Windows Script Runtime)が利用できません。管理者へご連絡ください。 | 端末ポリシー(AppLocker等)で Scripting.Dictionary がブロック | 管理者へ連絡して端末ポリシーの例外追加を依頼 |
| E0201 | AIリボン(`ChatGPT`関数)が見つからない | AIリボンが見つからず、AIに問い合わせできませんでした。AIリボン入りのExcelで開き直すか、🩺診断ボタンで状態を確認してください。 | 社内AIリボンが入っていないExcelで開いている/リボンのアドインが無効化されている | 🩺診断の「AIリボン」欄を確認。リボン入りのExcel環境で開き直してもらう。mock_llmで運用する暫定案内も検討 |
| E0202 | AIからの応答がエラー/空 | AIからの応答がエラーになったか、空でした。時間を置いてからもう一度お試しください。続くようなら診断結果を管理者へ連絡してください。 | AI側の一時的な不調/ネットワーク不安定 | 数分待って再試行してもらう。頻発する場合はerr_logのdetail列(応答内容)を確認し、リボン提供元へ連絡 |
| E0203 | 埋め込み取得(文章をAIが読める形に変換する処理)に失敗 | 文章をAIが読める形に変換する処理(埋め込み取得)に失敗しました。時間を置いてからもう一度お試しください。続くようなら診断結果を管理者へ連絡してください。 | AI側の一時的な不調/取込中にネットワークが切れた | 再試行を案内。「マイ本棚」の🔄同期を押すと未変換分だけ再開できる |
| E0204 | 本日のAI利用上限に達した可能性 | 本日のAI利用上限に達した可能性があります。今日はここまでにして、明日「🔄同期」を押せば続きから再開できます。 | 1日あたりの利用上限(社内AIリボン側の制限)に到達 | 翌日以降に🔄同期で再開してもらう。頻発する部署は上限緩和をリボン管理者へ相談 |

## 2. 🩺診断レポートの読み方

「ホーム」タブの「🩺 診断」ボタンを押すと、`diag_report` シートが作り直されて
表示されます。実装(`src/core/modDiag.bas`)は次の順に項目を並べます。
各行の先頭が **✅=問題なし** / **⚠️=要確認**、⚠️の行には「→ 対処」が付きます。

| 見出し | 何を見ているか | ⚠️が出たら |
|---|---|---|
| `[バージョン]` | アプリ名・バージョン番号 | 配布物が最新版かどうかの確認材料(常に✅) |
| `[AIリボン]` | `mock_llm`の状態、リボン(`ChatGPT`関数)が見つかるか | ⚠️ならE0201欄を参照。`mock_llm=TRUE`のときはこの項目は✅扱い(意図的な状態なので注意喚起のみ) |
| `[シート]` | 使い方/ホーム/マイ本棚/ダッシュボード/config/my_knowledge/my_vectors/my_manifest/my_stats/usage_log/err_log/ui_stateの12シートの存在+行数 | シートが1つでも無ければE0101欄を参照。配布物の破損を疑う |
| `[設定(config)]` | mock_llm/recommended_model/quick_model/embed_dim/shelf_max_chunks/topk_quick/topk_deep/answer_language/pack_authorの必須キー9個 | キー欠落ならE0101欄を参照 |
| `[本棚の状態]` | 登録資料数(manifest行数)/チャンク数(my_knowledge行数)/AIが読める形にまだ変換していないチャンク数 | 「変換していないチャンク」が0でなければ、🔄同期を押すよう案内(自動で続きから変換される) |
| `[追加機能(opt)]` | tts/vision/markdown/diffdocそれぞれの「モジュールあり/なし」「設定有効/無効」 | 常時参考情報(✅/⚠️の判定はしていない)。有効化したいのに反映されない場合はconfigの`feature_<id>`を確認 |
| `[直近のエラー(最大5件)]` | err_logの末尾から新しい順に最大5件(日時/コード/どこで発生したか) | エラーが1件でもあれば内容を確認し、§1の表と突き合わせる |

画面の指示どおり、内容がよく分からない場合は **この画面をスクリーンショットして
管理者(保守担当)に送ってもらう** のが一番早い一次切り分けです。

## 3. ログシートの見方

`err_log`と`usage_log`は既定で「非表示(hidden)」シートです。見るには:

1. どこかのシートタブを右クリック → **「再表示」** をクリック
2. 一覧から `err_log` または `usage_log` を選んでOK

(`my_knowledge`/`my_vectors`/`ui_state`/`vba_src`は「完全に隠す(veryHidden)」設定の
ため、この方法では出てきません。中身を直接見る必要は通常ありません。)

**見終わったら必ず再度「非表示」に戻してください**(右クリック→非表示)。利用者が
誤って内部シートに触れて壊すことを防ぐためです。値を直接編集しないでください。

### 3-1. err_log の列

| 列 | 内容 |
|---|---|
| timestamp | 発生日時(`yyyy-mm-dd hh:nn:ss`) |
| code | エラーコード(§1の表と対応) |
| context | どのモジュール・どの処理で発生したか(保守者向けの手がかり) |
| detail | エラーの詳細(`Err.Description`等。最大2000字) |
| version | 発生時のアプリバージョン |

### 3-2. usage_log の列

| 列 | 内容 |
|---|---|
| timestamp | 発生日時 |
| event | イベント種別(下表) |
| mode | 質問モード(`quick`/`deep`)等。関係ないイベントは空 |
| detail | イベントの詳細(質問文の先頭200字、件数など) |
| latency_ms | 所要時間(ミリ秒)。関係ないイベントは0 |
| hit_count | 検索ヒット件数。関係ないイベントは0 |

`event`列に実際に記録される値(実装から確認済み):

| event | いつ記録されるか |
|---|---|
| `ask` | 質問が実行されたとき |
| `feedback_green` | 🟢「解決した!」が押されたとき |
| `feedback_yellow` | 🟡「ヒントになった」が押されたとき |
| `feedback_red` | 🔴「だめだった」が押されたとき |
| `ingest` | 資料が1件、取込(または置換)されたとき |
| `sync` | 🔄フォルダと同期が実行されたとき |
| `pack_export` | 📦パックにして渡すが実行されたとき |
| `pack_import` | 📥パックを取り込むが実行されたとき |
| `diff`(opt機能) | 約款差分比較が実行されたとき |
| `pdf_text_gs`(R10) | PDF テキスト抽出で Ghostscript が成功したとき |
| `gs_guidance_card`(R10) | Ghostscript 案内カード(フォルダ選択)の結果が記録されたとき(accepted/canceled/nofind/saved 等) |
| `activate_recovered`(R10) | シート切替時の Activate エラーを自動復旧したとき(初回エラーでも切替済みなら成功扱い) |
| `word_attach_existing`(R11) | Word既存インスタンスに相乗りしたとき |
| `word_quit_skipped`(R11) | Word Quit を見送ったとき(利用者ファイル保護) |
| `word_open_count_unknown`(R11) | Word.Documents.Count 取得失敗のとき |
| `word_reuse_open_doc`(R11) | Word既存ドキュメントを再利用したとき |
| `word_doc_count_unknown`(R11) | 加算前後のドキュメント件数が不明なとき |
| `caller_mismatch`(R11) | OnAction の Caller が期待値と不一致だったとき |
| `p2p_userid_fallback`(R11) | P2P ユーザーID取得で ribbon→fallback 経路に落ちたとき |
| `p2p_userid_slow`(R11) | P2P ユーザーID取得が遅延したとき |
| `gs_*_rc_nonzero`(R11) | Ghostscript 実行で rc(リターンコード)が 0 以外だったとき |
| `guard_material_fail`(R11) | 統計バッジ算出で素材取得失敗のとき |
| `guard_wipe_incomplete`(R11) | ナレッジ消去で一部消去できなかったとき |
| `insight_gc`(R11) | 共有フォルダの感謝状・ギャップファイルを片付けたとき |

## 4. 月次の部集計方法

「マイ本棚AI」は1人1ファイルの個人利用ツールです。usage_logは**そのファイルを
使っている本人だけの記録**しか持っていないため、部署単位の集計をするには
**メンバー各自のファイルからusage_logを集めて手元で合算**する必要があります。

1. 集計対象のメンバーに、各自のファイルの `usage_log` シートを§3の手順で表示してもらう
2. `timestamp`〜`hit_count`のデータ範囲を選択してコピーしてもらう
   (見出し行は最初の1人分だけでよい)
3. 集計用に新しく作った空のExcelブック(集計専用ファイル)に、全員分を1つのシートへ
   縦に貼り付けていく
4. 貼り付けたデータを選択し、`[挿入]→[ピボットテーブル]` で集計する
   - 行: `event`
   - 列: `timestamp`の月部分(先頭7文字 `yyyy-mm`。列を追加して`=LEFT(A2,7)`等で
     切り出しておくと集計しやすい)
   - 値: 件数(`event`の個数)
5. 「今月の質問数」は`event="ask"`の件数、「自己解決数」は`event="feedback_green"`の
   件数、というように§3-2の対応表で読み替える

- なぜこの手順か: usage_logに部署名・氏名の列が無く、ファイル自体が個人単位で
  分かれているため、自動で全社集計する仕組みは現状ありません(ダッシュボードの
  「今月の質問数」もこのusage_logを**その人の分だけ**その場で数えているだけです)。
- 個人情報(detail列に質問文の先頭200字が入る)を含むため、集計用ファイルの
  共有範囲には注意してください。

## 5. FAQ(動かないときの切り分けフロー)

「動かない」という相談を受けたら、この順に確認してください。

```
① マクロは有効になっているか?
   └ 「使い方」タブしか見えない/黄色い警告バーが出ている
     → docs/20_セットアップと配布.md §2-3 の手順でマクロを有効化
       (「VBAプロジェクトオブジェクトモデルへのアクセスを信頼する」設定を含む)

② リボン(操作ボタン)のあるはずの画面が出ているか?
   └ 「ホーム」タブを開いて、質問入力欄や「💬 質問する」ボタンが見えるか確認
     → 見えない場合はブックを閉じて開き直す(EnsureLayoutが再構築する)
       それでも直らなければE0801として扱いerr_logを確認

③ 🩺診断ボタンを押した結果はどうか?
   └ §2の読み方に従い、⚠️の付いた行を上から順に確認
     → ⚠️の内容が§1のエラーコード表のどれかに対応するので、その対処を行う
```

上記で切り分けられない場合は、診断画面(`diag_report`シート)のスクリーンショットと
`err_log`の直近数行を合わせて確認すると、原因の特定が早くなります。

## 7. 共有ナレッジの自動消去(knowledge_expire_days)

配布端末を紛失・退職者が持ち出した場合の保険として、`config` の `knowledge_expire_days`
(既定30)で「共有フォルダに最後に到達できた日から何日で知識を自動消去するか」を設定できます。

- **一度も共有フォルダへ到達したことが無い端末は、この設定に関わらず決して消しません**
  (2026-07-31 R8で修正: 従来は未到達端末まで30日で全消去する不具合があった)。
  オフライン専用・キッティング直後などで共有へまだ一度も届いていない端末が
  誤って知識を失うことはありません。
- `0` で無効化できます。**PoC(実機テスト・試験導入)期間中は `0` を推奨**します
  (`docs/42_実機テスト依頼メール文面.md`のチェックリストにも同じ案内があります)。
- 実装は `src/stats/modGuard.bas`(`EnforceExpiry`)、判定式の純ロジックは
  `src/core/modShareRule.bas`(境界値テストは `src/test/modTestsPure5.bas`)。

## 8. Ghostscript(画像PDFのOCR取込)の配布・運用

画像PDFのOCR取込(`docs/43_画像PDFのOCR取込設定.md`)に使うGhostscriptは、
`dist/Ghostscript/` に常置でコミット済みです。通常の配布(リポジトリZIPのDL→解凍)では
利用者側の追加作業は不要ですが、保守担当が次の2点を運用することがあります。

### 8-1. IT側で標準配置先を焼き込む(ghostscript_search_dirs)

社内に既に別のGhostscript配置規約がある場合、`config` の `ghostscript_search_dirs`
(既定は空)に、セミコロン区切りで探索させたいフォルダを書いておけます。

```
（configシートの値の例。1セルにそのまま入力する)
C:\Tools\Ghostscript;\\fileserver\share\tools\gs
```

各フォルダについて「直下」と「`bin\`直下」の両方に `gswin32c.exe` が無いか探します。
`config` `ghostscript_path`(明示フルパス)→同梱→この`ghostscript_search_dirs`→
案内カード、の順で解決されます(詳細は`docs/43_画像PDFのOCR取込設定.md`§5)。
配布ビルドを作る前に、このconfig値だけを書き換えて再ビルドすれば全利用者に配れます。

### 8-2. 大規模配布用のzip梱包(--zip)

```
python3 build/build_mybookshelf.py --prod --zip
```

通常の本番ビルド(`dist/MyBookshelf.xlsm`)に加えて、`dist/MyBookshelf_配布.zip`
(`.xlsm` + `Ghostscript/`一式)がワンコマンドで作られます。`--publisher`と併用すると
`dist/MyBookshelf_発行者用_配布.zip`になります。この配布zipは`.gitignore`対象
(`dist/*_配布.zip`)なので、リポジトリ本体を肥大させずに配布物だけを作れます。
既定ビルド(`--zip`を付けない`--prod`/`--dev`)の挙動は変わりません。

## 9. R8/R8b における共有GCと発行ロック運用

### 9-1. 共有フォルダ上のQ&A/ギャップの自動整理(GC)

共有フォルダ上に蓄積した Q&A ファイル(`qa_*.txt`)と
ギャップファイル(`gap_*.txt`)の自動削除(GC: Garbage Collection)は、
**発行者用ブック(`--publisher`でビルド)の端末だけが実行します。**

一般ユーザー端末では GC が走らないため、
発行者用ブックを **月1回以上起動** する運用を確保してください。

**注意: 部門に発行者用ブックの端末が1台も無い場合、共有フォルダの
qa/gap ファイルは誰にも掃除されず増え続けます**(警告は出ません)。
その場合は起動が遅くなる前に、部門に発行者を1人立てるか、
共有フォルダの `insight` 配下を手動で整理してください。

実装: `src/pack/modInsight.bas` の `GcOldInsights`
(保持日数 `thanks_gc_days`(既定60日)を超えた qa/gap ファイルを削除し、
削除件数を `usage_log` に1行記録)。
自端末ローカルの nonce/既読印の GC は全端末で実行されます。

### 9-2. publish.lock の残骸対処

同時発行を制御するため、発行開始時に `publish.lock`(作者ID+時刻) が
共有フォルダに作成されます。通常は発行完了時に自動削除されますが、
実機クラッシュなどで残る場合があります。

**状況別の対処:**

| 状況 | 対処 |
|---|---|
| `publish.lock` が 10分未満 | 他の発行が進行中。完了を待つ |
| `publish.lock` が 10分超（残骸） | 手で削除 → 「📦パックにして渡す」を再実行。E0807がerr_logに記録される |
| 手動削除手順 | 共有フォルダを開き、`publish.lock` ファイルを Shift+Delete で完全削除 |

**時計ズレへの対応:**
実機のシステムクロック(時計)が遅れている場合、lock の年齢判定が`ageMin<0`になります。
この場合、残骸扱い(stale)として扱われ、err_log に E0807 を記録したうえで
上書き続行されます。(時計が遅れた端末が永久に発行不能になるより、
同時発行の窓が開く方が害が小さい)

## 10. 既知の制限

| 制限 | 内容 |
|---|---|
| Mac不可 | ファイル抽出(Word/Excel/PDF読み取り)がWindows Excel専用の仕組みに依存しているため、コア動作はWindows前提です。Macで開くとE0302系のエラーになります |
| リアルタイム監視なし | 本棚フォルダの変更は自動で即座に検知されません。「🔄フォルダと同期」を押す、または`sync_interval_min`で設定した間隔ごとの自動同期(ポーリング)でのみ差分が反映されます |
| SharePointはOneDrive同期経由のみ | SharePoint上のフォルダを直接APIで参照する機能はありません。OneDriveクライアントで同期してローカルパスとして見えるフォルダを`shelf_folder`に指定してください。オフライン時はE0302(ファイルが開けない)として扱われ、次回同期時に再試行されます |
