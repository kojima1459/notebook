## 1. エラーコード表(E0101〜E0901)

利用者が「使い方」で困ったとき、画面には必ず「何が起きたか」+「どうすればよいか」の
2文と、末尾に `(コード: Exxxx)` が表示されます。このコードで下表を引いてください。
「ユーザーに見える文言」列は、実装(`src/core/modLog.bas` の `FriendlyMessage`)から
そのまま転記したものです(言い回しを変えたい場合は必ずコードを直してから再ビルドしてください)。

## 2. 🩺診断レポートの読み方

「ホーム」タブの「🩺 診断」ボタンを押すと、`diag_report` シートが作り直されて
表示されます。実装(`src/core/modDiag.bas`)は次の順に項目を並べます。
各行の先頭が **✅=問題なし** / **⚠️=要確認**、⚠️の行には「→ 対処」が付きます。

| 見出し | 何を見ているか | ⚠️が出たら |
|---|---|---|
| `[バージョン]` | アプリ名・バージョン番号 | 配布物が最新版かどうかの確認材料(常に✅) |
| `[AIリボン]` | `mock_llm`の状態、リボン(`ChatGPT`関数)が見つかるか | ⚠️ならE0201欄を参照。`mock_llm=TRUE`のときはこの項目は✅扱い(意図的な状態なので注意喚起のみ) |
| `[シート]` | 使い方/ホーム/マイ本棚/ダッシュボード/config/my_knowledge/my_vectors/my_manifest/my_stats/usage_log/err_log/ui_stateの12シートの存在+行数 | シートが1つでも無ければE0101欄を参照。配布物の破損を疑う |
| `[設定(config)]` | mock_llm/recommended_model/quick_model/embed_dim/shelf_max_chunks/topk_quick/topk_deep/answer_language/pack_authorの必須キー9個 | キー欠落ならE0101欄を参照 |
| `[本棚の状態]` | 登録資料数(manifest行数)/チャンク数(my_knowledge行数)/AIが読める形にまだ変換していないチャンク数 | 「変換していないチャンク」が0でなければ、🔄同期を押すよう案内(自動で続きから変換される) |
| `[追加機能(opt)]` | tts/vision/markdown/diffdocそれぞれの「モジュールあり/なし」「設定有効/無効」 | 常時参考情報(✅/⚠️の判定はしていない)。有効化したいのに反映されない場合はconfigの`feature_<id>`を確認 |
| `[直近のエラー(最大5件)]` | err_logの末尾から新しい順に最大5件(日時/コード/どこで発生したか) | エラーが1件でもあれば内容を確認し、§1の表と突き合わせる |

画面の指示どおり、内容がよく分からない場合は **この画面をスクリーンショットして
管理者(保守担当)に送ってもらう** のが一番早い一次切り分けです。

## 3. ログシートの見方

`err_log`と`usage_log`は既定で「非表示(hidden)」シートです。まず、直近5件までなら
アプリ内の「❓ → 🩺診断」画面(§2)だけで確認できます。それで足りず全件を見たい
ときだけ、以下の手順が必要です。

**このアプリは通常起動中、シートタブそのものを非表示にしています**(タブが
無いので「タブを右クリック→再表示」はできません)。中身を見るには:

1. アプリ内の「🚪保存して閉じる」で、変更を保存してから一旦閉じる
   (このときシートタブの表示状態がブックに保存されます)
2. もう一度このファイルを開く際、セキュリティの警告バーで
   **「コンテンツの有効化」を押さない**(マクロを無効のまま開く。または
   Shiftキーを押しながら開く)
3. マクロが動いていない素のExcel状態になるので、シートタブを右クリック →
   **「再表示」** → `err_log` または `usage_log` を選んでOK

(`my_knowledge`/`my_vectors`/`ui_state`/`vba_src`は「完全に隠す(veryHidden)」設定の
ため、この方法でも出てきません。中身を直接見る必要は通常ありません。)

**見終わったら必ず再度「非表示」に戻し、保存せずに閉じてください**(右クリック→
非表示 → 保存せずに閉じる)。値を直接編集しないでください。次に開くときは
通常どおりマクロを有効化してください(有効化しないとアプリが動きません)。

### 3-1. err_log の列

| 列 | 内容 |
|---|---|
| timestamp | 発生日時(`yyyy-mm-dd hh:nn:ss`) |
| code | エラーコード(§1の表と対応) |
| context | どのモジュール・どの処理で発生したか(保守者向けの手がかり) |
| detail | エラーの詳細(`Err.Description`等。最大2000字) |
| version | 発生時のアプリバージョン |

### 3-2. usage_log の列

| 列 | 内容 |
|---|---|
| timestamp | 発生日時 |
| event | イベント種別(下表) |
| mode | 質問モード(`quick`/`deep`)等。関係ないイベントは空 |
| detail | イベントの詳細(質問文の先頭200字、件数など) |
| latency_ms | 所要時間(ミリ秒)。関係ないイベントは0 |
| hit_count | 検索ヒット件数。関係ないイベントは0 |

`event`列に実際に記録される値(実装から確認済み):

## 4. 月次の部集計方法

「マイ本棚AI」は1人1ファイルの個人利用ツールです。usage_logは**そのファイルを
使っている本人だけの記録**しか持っていないため、部署単位の集計をするには
**メンバー各自のファイルからusage_logを集めて手元で合算**する必要があります。

1. 集計対象のメンバーに、各自のファイルの `usage_log` シートを§3の手順で表示してもらう
2. `timestamp`〜`hit_count`のデータ範囲を選択してコピーしてもらう
   (見出し行は最初の1人分だけでよい)
3. 集計用に新しく作った空のExcelブック(集計専用ファイル)に、全員分を1つのシートへ
   縦に貼り付けていく
4. 貼り付けたデータを選択し、`[挿入]→[ピボットテーブル]` で集計する
   - 行: `event`
   - 列: `timestamp`の月部分(先頭7文字 `yyyy-mm`。列を追加して`=LEFT(A2,7)`等で
     切り出しておくと集計しやすい)
   - 値: 件数(`event`の個数)
5. 「今月の質問数」は`event="ask"`の件数、「自己解決数」は`event="feedback_green"`の
   件数、というように§3-2の対応表で読み替える

- なぜこの手順か: usage_logに部署名・氏名の列が無く、ファイル自体が個人単位で
  分かれているため、自動で全社集計する仕組みは現状ありません(ダッシュボードの
  「今月の質問数」もこのusage_logを**その人の分だけ**その場で数えているだけです)。
- 個人情報(detail列に質問文の先頭200字が入る)を含むため、集計用ファイルの
  共有範囲には注意してください。

## 8. Ghostscript(画像PDFのOCR取込)の配布・運用

画像PDFのOCR取込(`docs/43_画像PDFのOCR取込設定.md`)に使うGhostscriptは、
`dist/Ghostscript/` に常置でコミット済みです。通常の配布(リポジトリZIPのDL→解凍)では
利用者側の追加作業は不要ですが、保守担当が次の2点を運用することがあります。

### 8-1. IT側で標準配置先を焼き込む(ghostscript_search_dirs)

社内に既に別のGhostscript配置規約がある場合、`config` の `ghostscript_search_dirs`
(既定は空)に、セミコロン区切りで探索させたいフォルダを書いておけます。

```
（configシートの値の例。1セルにそのまま入力する)
C:\Tools\Ghostscript;\\fileserver\share\tools\gs
```

各フォルダについて「直下」と「`bin\`直下」の両方に `gswin32c.exe` が無いか探します。
`config` `ghostscript_path`(明示フルパス)→同梱→この`ghostscript_search_dirs`→
案内カード、の順で解決されます(詳細は`docs/43_画像PDFのOCR取込設定.md`§5)。
配布ビルドを作る前に、このconfig値だけを書き換えて再ビルドすれば全利用者に配れます。

### 8-2. 大規模配布用のzip梱包(--zip)

```
python3 build/build_mybookshelf.py --prod --zip
```

通常の本番ビルド(`dist/MyBookshelf.xlsm`)に加えて、`dist/MyBookshelf_配布.zip`
(`.xlsm` + `Ghostscript/`一式)がワンコマンドで作られます。`--publisher`と併用すると
`dist/MyBookshelf_発行者用_配布.zip`になります。この配布zipは`.gitignore`対象
(`dist/*_配布.zip`)なので、リポジトリ本体を肥大させずに配布物だけを作れます。
既定ビルド(`--zip`を付けない`--prod`/`--dev`)の挙動は変わりません。

## 9. R8/R8b における共有GCと発行ロック運用

### 9-1. 共有フォルダ上のQ&A/ギャップの自動整理(GC)

**送信される内容(2026-08-01 R12-2-2追記):** 「✅解決した」を押したとき・
「違う/微妙」で訂正を書いたとき・そして**検索が0件だったとき自動的に**、
質問文(全文)・氏名・部署が、部門の共有フォルダ配下の `insight\qa` または
`insight\gap` へテキストファイルとして書き出されます。検索0件時の自動送信は
利用者の操作(ボタン押下)を介さず発火する点に注意してください。宛先は
部門内アクセス制御下の共有フォルダで、社外へは出ません。

**停止方法:** config シートの `insight_share_enabled` を `FALSE` にすると、
これらの送信(共有知の発信)がすべて止まります(既定 `TRUE`。共有知は
本製品の核となる機能のため、既定では有効にしています)。

共有フォルダ上に蓄積した Q&A ファイル(`qa_*.txt`)と
ギャップファイル(`gap_*.txt`)の自動削除(GC: Garbage Collection)は、
**発行者用ブック(`--publisher`でビルド)の端末だけが実行します。**

一般ユーザー端末では GC が走らないため、
発行者用ブックを **月1回以上起動** する運用を確保してください。

**注意: 部門に発行者用ブックの端末が1台も無い場合、共有フォルダの
qa/gap ファイルは誰にも掃除されず増え続けます**(警告は出ません)。
その場合は起動が遅くなる前に、部門に発行者を1人立てるか、
共有フォルダの `insight` 配下を手動で整理してください。

実装: `src/pack/modInsight.bas` の `GcOldInsights`
(保持日数 `thanks_gc_days`(既定60日)を超えた qa/gap ファイルを削除し、
削除件数を `usage_log` に1行記録)。
自端末ローカルの nonce/既読印の GC は全端末で実行されます。

### 9-2. publish.lock の残骸対処

同時発行を制御するため、発行開始時に `publish.lock`(作者ID+時刻) が
共有フォルダに作成されます。通常は発行完了時に自動削除されますが、
実機クラッシュなどで残る場合があります。

**状況別の対処:**

| 状況 | 対処 |
|---|---|
| `publish.lock` が 10分未満 | 他の発行が進行中。完了を待つ |
| `publish.lock` が 10分超（残骸） | 手で削除 → 「📦パックにして渡す」を再実行。E0807がerr_logに記録される |
| 手動削除手順 | 共有フォルダを開き、`publish.lock` ファイルを Shift+Delete で完全削除 |

**時計ズレへの対応:**
実機のシステムクロック(時計)が遅れている場合、lock の年齢判定が`ageMin<0`になります。
この場合、残骸扱い(stale)として扱われ、err_log に E0807 を記録したうえで
上書き続行されます。(時計が遅れた端末が永久に発行不能になるより、
同時発行の窓が開く方が害が小さい)

## 11. 「応答なし」表示中も処理は動いています(freeze_keep_banner)

AIへの問い合わせ(`ChatGPT()`/`ChatGPTV()`)は秒数指定のできない同期呼び出しのため、応答が返るまでこのブックのExcelプロセスは他の操作を受け付けられません(公式仕様。VBA側からは制御不能)。Windows既定ではこの状態が約5秒続くとDWM(デスクトップウィンドウマネージャ)が「応答なし」と判定し、画面を白いゴースト画像に置き換えます。**これは異常ではなく、AIからの応答・資料の読み取りを待っているだけです。**

### 白画面抑止(既定on)の帰結

本製品は`user32.DisableProcessWindowsGhosting`を1度だけ呼び、白画面化を抑止しています(取込・質問の進捗バナーの文字が最後まで読めるようにするため)。ただし公式の既知の制約として、抑止が効いている間(=処理が終わるまで)は次の操作ができません:

- ウィンドウの移動・サイズ変更・最小化
- タイトルバーの×での終了

これは「フリーズした」のではなく、白画面化を止めた副作用です。処理が終われば(通常は進捗バナーの文字が変わるか消えます)、通常どおり操作できる状態に戻ります。

### 強制終了が必要なとき

進捗バナーが5分以上まったく動かない場合は、ハングと判断して構いません。`Ctrl+Shift+Esc`でタスクマネージャーを開き、「マイ本棚AI」(または`EXCEL.EXE`)を選んで「タスクの終了」を押してください。取込はチェックポイント機能があるため、再度取り込むと続きから再開できます。

### freeze_keep_banner を切るには

白画面抑止そのものを止めたい場合(実機で挙動に問題が出た等)は、`config`シートの`freeze_keep_banner`を`FALSE`にしてください(既定`TRUE`)。FALSEにすると、従来どおり約5秒で画面が白くゴースト化する挙動へ戻ります(処理自体への影響はありません)。取込・質問の途中でも別のExcelプロセスで作業したい場合は、進捗バナー内の「🗔作業用Excel」ボタン(またはヘルプカードの同ボタン)を使うよう案内してください(`docs/10_使い方ガイド.md`参照)。

**この設定の変更はExcelを開き直したときに反映されます**(判定はプロセス起動後の1回だけで、on/offどちらの結果もそのプロセスの間は覚えたままになります。長時間処理では1ページ・1段ごとに通る経路のため、毎回`config`シートを引き直さない設計です)。

### 「🗔作業用Excel」が開かないとき(EDR/AppLocker)

「🗔作業用Excel」は`WScript.Shell`から`excel.exe /x`(新しいプロセスでExcelを起動する公式スイッチ)を実行します。**`/x`が公式ドキュメントに明記されているのはExcel 2021/Microsoft 365です。Excel 2016での動作は実機で確認してください**(スイッチ自体は受け付けられますが、公式の記載がありません。動かない場合は「タスクバーのExcelアイコンをAltキーを押しながらクリック」でも新しいプロセスが起動します)。

また、端末のEDRやAppLockerは**Officeからの子プロセス起動を検知・遮断する**ことがあります(Ghostscript起動と同種の事象。§8参照)。遮断されると`err_log`に**E0904**が残り、画面には短い案内だけが出ます(取込中にモーダルを出すと取込全体が止まるため)。恒久対応が要る場合は、IT部門へ「マイ本棚AIから`excel.exe /x`を起動することの許可」を依頼してください。

### IT向け脚注: DisableMergeInstance との違い

Windowsには類似の挙動制御としてレジストリ`DisableMergeInstance`がありますが、**本製品はこのレジストリを一切書き込みません**。有効化するとOffice全体でウィンドウの結合(インスタンスマージ)挙動が変わり、複数のExcelウィンドウが別プロセスとして完全に分離されますが、副作用として別インスタンス間でのコピー&貼り付けが劣化する(書式や一部データがそのまま渡らないことがある)ことがOfficeの既知の制約として知られています。既に組織のポリシーで設定されている場合の参考情報として記載します(本製品を使うためだけにこのレジストリを設定する必要はありません)。

**書き込まないことの帰結(2026-08-06 R19H FB-8)**: このレジストリを書き込まない結果、**Excelの既定のマージ挙動がそのまま残ります**。つまり、他のExcel(利用者が仕事で開いている作業用Excelなど)が生きている状態でMyBookshelf本体をダブルクリックすると、**本体はそのExcelのプロセスへ吸い込まれます**。このときエラーは何も出ませんが、後で本体が資料の取込を始めた瞬間に、**巻き込まれた側のブックも一緒に固まります**(本体の「■中断」ボタンも押せなくなり、強制終了しか手が無くなります)。`DisableMergeInstance` はダブルクリック起動には効かないことがMicrosoft公式に明記されているため、レジストリを書いてもこの経路は塞げません。本製品の対策は**レジストリではなく運用側**にあります: (1) 同梱のランチャー「MyBookshelfを起動.bat」からの起動(`excel.exe /x` で必ず別プロセス)、(2) 起動時と取込直前の**同居警告**(`modIntegrity` の `cohabit_detected`。他のブックが同じプロセスにあると検出したら伝え、取込前は続行するか確認します)。利用者から「取込中に関係ないExcelまで固まった」という申告があったら、まずこの経路を疑ってください(usage_log の `cohabit_detected` 行が証拠になります)。

## 12. 資料の自動整理(enrich)のコストと制御

R17 Phase3(2026-08-05)から、資料を取り込んだあとに**AIが自動で要約・キーワード付け・
用語の名寄せ辞書づくりを行う**ようになりました(`config` `enrich_mode` 既定 `light`、
`graph_synonyms` 既定 `on`)。検索精度を上げる下ごしらえで、質問の応答には影響しません
(整理が終わっていない資料でも普通に質問できます)。ここでは、この機能が**AIリボンの
呼び出し回数(コスト)にどう影響するか**と、**元に戻す方法**をまとめます。

### 何回AIを呼ぶか

- **バッチ富化(summary/keywords)**: チャンク10件ごとに1回。1回の`EnrichPending`実行で
  最大30チャンク(=最大3回のAI呼び出し)まで処理し、それ以上は次の機会に持ち越します。
  「次の機会」とは、資料を追加で取り込んだとき・「🔄フォルダと同期」を押したとき・
  自動同期(`sync_interval_min`)が働いたときで、**1回の取込・同期で本棚全体を一気に
  処理することはありません**(254頁級の資料をまとめて処理すると1時間級になるため、
  意図的に小分けにしています)。
- **章の要約(doc_outline / `graph_outline` 既定 `on`)**: 資料1本につき
  **章の数だけ**AIを呼びます(1章=1回)。上限は**1資料60章**で、そこで打ち切ります
  (章見出しが取れない資料は条単位に割れるため、暴走を止める安全弁です)。
  254頁級の規程で20〜30回=取込が+3〜8分。進捗バナーに
  「章の要約中… 3/20章(資料名)」と残り時間が出て、**■中断**で止めれば
  そこまでの章は保存されます。**自動同期(バックグラウンド)では、13章以上に
  割れる資料の章要約を先送りします**(誰も見ていないところで数分〜十数分
  ブロックしないため。usage_log に `outline_deferred` が1行残ります)。
  手動取込・手動の「🔄 フォルダと同期」なら同じ資料でも全量作られます。
- **名寄せ辞書(synonyms)**: 章の要約(R17 Phase2・`graph_outline`)が終わったあとに、
  資料1本につき**最大1回**だけAIを呼びます。用語候補が無ければ呼びません。
  **`graph_outline` が `off` の本棚と、章・条の見出しが取れない資料では、
  `graph_synonyms` が `on` でも辞書は増えません**(名寄せは章要約の直後に
  走る配線になっているため)。作れた件数は usage_log の
  `synonyms_built`(detail の `groups=N`)で確認できます。
- **質問時**: 検索にはAI呼び出しを追加していません。synonymsシートを読んで質問文へ
  同義語を足すのは文字列処理だけで、シート自体も1回の質問セッションで1回しか読みません。

### 元に戻すには(offへの戻し方)

- **バッチ富化を止める**: `config`シートの `enrich_mode` を `off` にしてください
  (既定 `light`)。以降は要約・キーワード列が空のまま残ります(検索は本文だけで行われ、
  従来どおり動きます)。既に作った要約・キーワードは削除されません。
- **章の要約を止める**: `config`シートの `graph_outline` を `off` にしてください
  (既定 `on`)。以降は取込時に章要約を作らなくなり、取込は R16 までの速さに戻ります。
  質問側では俯瞰(「全体像は?」「全部教えて」型)が従来の検索で答えるようになります
  (エラーにはならず、usage_log に `global_zero why=no_outline` が1行残るだけです)。
  既に作った doc_outline の行は残り、`off` の間も俯瞰の材料として読まれます。
  なお `graph_outline` を `off` にすると、その配線に相乗りしている**名寄せ辞書も
  新しく作られなくなります**(上記「何回AIを呼ぶか」の注記)。
- **名寄せ辞書を止める**: `config`シートの `graph_synonyms` を `off` にしてください
  (既定 `on`)。以降は synonyms シートを作らなくなり、質問文への同義語追記もしません。
  既に作った辞書はシートに残りますが、offの間は読まれません。
- `enrich_mode`・`graph_synonyms` を `off` にする効果は、ブックを開き直さなくても
  **次の取込・同期・質問からすぐに反映されます**。一方、synonymsシートの**中身**
  (取込・同期で追加された同義語)は1セッションにつき1回だけ読み込んでキャッシュする
  設計のため、既に開いているセッションでは**新しく追加された同義語だけ**は次に
  ブックを開き直すまで質問に反映されません(offにする分には影響ありません)。
