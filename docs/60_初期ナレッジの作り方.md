# 初期ナレッジ(シード)の作り方

配布した .xlsm を開いた瞬間から、実物の社内資料に対して出典付きで答えられる
状態を作るための手順。**ここを飛ばすと、開いた人は「本棚が空です」を見て終わる。**

---

## なぜ「それっぽい知識」を入れないのか

保険業界用語辞典のような一般知識を詰めると、初手の回答が微妙にズレる。
損保でズレた答えが1回出れば、その人はもう二度と開かない。空っぽより悪い。

入れるのは**実物だけ**。答えは実物の条文から出て、出典は実物のページを指す。
そのかわり、入っている資料の名前を最初に名指しし、
**押すだけで試せる質問**を並べる。利用者が考える量をゼロにする。

---

## 全体の流れ

```
  PDF(実物の社内資料)
        │
        │  ① tools/make_seed_pack.py     … 丁寧に切る(条文単位)
        ▼
  seed_pack.xlsx  (チャンクのみ・ベクトル空)
        │
        │  ② リボンのあるPCで1回だけ実行  … ★これを飛ばすと初回が遅い
        ▼
  seed_pack.xlsx  (ベクトル入り)
        │
        │  ③ build_mybookshelf.py --seed
        ▼
  dist/MyBookshelf.xlsm  (開いた瞬間から使える)
```

---

## ① チャンクを作る

```bash
python3 tools/make_seed_pack.py seed/seed_pack.xlsx \
  "path/to/瑕疵保証責任保険_引受ガイドライン.pdf:瑕疵保証責任保険 引受ガイドライン" \
  "path/to/顧客サービス費用保険_引受ガイドライン.pdf:顧客サービス費用保険(債務履行型) 引受ガイドライン" \
  "path/to/リコールプロテクション.pdf:リコールプロテクション(生産物回収費用保険)" \
  "path/to/家主費用利益保険.pdf:家主費用・利益保険" \
  "path/to/約定履行保険_約款.pdf:約定履行保険 約款" \
  "path/to/費用利益保険_約款.pdf:費用・利益保険 約款"
```

`PDF:表示名` の `表示名` が、そのまま**回答の出典に出る名前**になる。
利用者が見て一目で分かる名前にすること(ファイル名をそのまま使わない)。

このツールが実行時の取込より丁寧にやっていること:

| やること | 理由 |
|---|---|
| 文字化けページを落とす | 約款の表紙・裏は装飾フォントで、抽出すると制御文字とギリシャ文字の羅列になる。本文は正常なので既存の画像PDF判定では気づけない |
| 「第N条」で切る | 条文が意味の単位。固定長で切ると1つの条が2つに割れ、「第12条は?」に条文の後半だけが当たる |
| ページ境界で切らない | 条文はページをまたぐのが普通 |
| 見出しを各チャンクの先頭に復元 | 「第12条(保険金を支払わない場合)」が本文にあれば、AIが何条の話か取り違えない |
| 小見出しを条にぶら下げる | 「第24条 > (2)…」。条を見失わない |
| 「第2 0条」→「第20条」 | PDFの字詰めで数字が空白で割れる。そのままだと利用者が「第20条」と聞いても一致しない |
| ページ番号「- 19 -」を除去 | 条文の途中に挟まって文を分断する |
| 目次ページを捨てる | ドットリーダーだらけで検索の邪魔にしかならない |

出力の最後に、**すぐ押せる質問**も自動生成されて同梱される。
質問は資料の見出しから作るので、**全ての質問に対して答えのチャンクが必ず存在する**。
手で書くと「資料に無いこと」を聞いてしまい、初手で外す。

## ② ベクトルを入れる ★必須

**埋め込み(ベクトル)は社内AIリボンでしか作れない。** ビルド環境では生成できない。

| 状態 | 初回起動 |
|---|---|
| ベクトル入りで配布 | **一瞬**。API呼び出しゼロ。開いた瞬間から出典付きで答える(これが本来の姿) |
| ベクトル無しで配布 | 取り込みは一瞬だが、検索に使えるまで約180回のAPI呼び出しが必要。数分かかる |

### 手順(リボンのあるPCで1回だけ)

1. `--seed` を付けずにビルドした .xlsm を開く
2. ナレッジ画面 → 「📥 パック取込」で `seed_pack.xlsx` を取り込む
3. 埋め込みが終わるまで待つ(進捗は画面下の状態表示に出る)
4. ナレッジ画面 → 「📦 パック出力」で全体を書き出す
5. 書き出されたファイルを `seed/seed_pack.xlsx` に置き換える

これで `pack_vectors` が埋まる。以降、配布を受けた全員は待たされない。

> ベクトル無しのまま配ってしまった場合でも壊れはしない。
> 起動時の挨拶が「⏳ いまAIが読み込み中です」に変わり、
> 終わるまでは一般知識で答える。ただし**初手の感動は失われる**ので、
> 必ず②を通してから配ること。

## ③ 焼き込んでビルド

```bash
python3 build/build_mybookshelf.py --prod --seed seed/seed_pack.xlsx
```

`seed_meta` / `seed_chunks` / `seed_vectors` の3シート(veryHidden)として
.xlsm に入る。初回起動時に `modSeed.EnsureSeedLoaded` が `my_knowledge` /
`my_vectors` へ写す。**チャンク分割も埋め込みも実行時には走らない**ので速い。

`--seed` を付けなければシード無しでビルドされる(従来どおり)。

## 配布時の注意

### 機密区分

同梱した資料の機密区分が、**そのまま .xlsm の機密区分になる**。
「社内限」の資料を入れたら、その .xlsm は社内限として扱うこと。

推奨: `config` で端末ガードを有効にする。

| キー | 設定 | 効果 |
|---|---|---|
| `allowed_domain` | 自社のドメイン名 | 許可外の端末では知識を消して起動を止める |
| `knowledge_expire_days` | 30 など | 社内ネットに一定期間つながらない端末の知識を自動失効 |

### チャンク予算

| 内訳 | 目安 |
|---|---|
| 初期ナレッジ(6資料) | 約 180 |
| 部門の公式ナレッジ(6部門) | 3,000〜6,000 |
| 個人の本棚(20冊) | 〜2,800 |
| **合計** | **6,000〜9,000** |

上限は `config shelf_max_chunks` = **20,500**。十分な余裕がある。

## 更新するとき

資料が改定されたら ①〜③ をやり直して再配布する。
既に配った端末では `my_stats` の `seed_loaded` が立っているため、
シードの再取り込みは起きない(利用者が消した資料が勝手に復活しない)。
新版を行き渡らせたい場合は、**部門チャンネル**として配信するのが本筋
(`docs/DESIGN_v3_運用設計.md` §2)。シードはあくまで「初日の入口」。
