> **何が分かるか**: 配布先と同じ実機(リボン入りWindows Excel)で15分ほどかけて行う、チェックボックス形式の最終確認手順が分かります。

## 0. 事前準備

- 対象: `dist/MyBookshelf.xlsm`(`--prod` ビルド。開発確認だけなら `MyBookshelf_dev.xlsm` でも可)
- 実行環境: 社内AIリボン(「リボンちゃん」・`ChatGPT()`/`GetEmbeddings()`)が入った**実機のWindows Excel**
- 用意するもの: 中身が異なる短いテキストファイル(`.txt`)を2〜3個。うち1組は「同じファイル名・別フォルダ・別内容」にしておく(項目8で使います)
- 所要時間の目安: 各項目の見出しに分単位で記載(合計 約15〜20分。資料やPCの速度により前後します)
- なぜ実機で行うか: Lint(静的チェック)とLibreOffice実行テストはソースコードの検査です。**実際にリボンへ接続して回答が返ってくるか**は、この実機チェックでしか確認できません。

チェックは上から順に行ってください。**1つでも失敗したら、そこで止めて原因を直してから最初からやり直してください**(配布はその後です)。

**失敗したら**: 出力中の `NG: ` で始まる行がテスト名と失敗詳細。該当モジュール(`modChunker`/`modPii`/`modUtil`/`modPrompts` など)を確認し、1件でもFAILがあれば配布しない。

### [ ] 12. 終了 → 再起動でOnTime残存なし(1分)

1. [ ] VBEのイミディエイトウィンドウ(`Alt+F11`→`Ctrl+G`)で次を実行し、`sync_interval_min` を
   `1`(1分)に変更して保存する(このアプリは通常起動中シートタブを隠すため
   「タブを右クリック→再表示」は使えない。手順5と同じ`modConfig.SetValue`が確実):

   ```
   modConfig.SetValue "sync_interval_min", 1
   ActiveWorkbook.Save
   ```
2. [ ] いったんブックを閉じる(保存する)
3. [ ] もう一度ファイルを開き直す(この起動で `modBoot.Boot` が `sync_interval_min=1` を読み込み、`Application.OnTime` の予約が実際に張られる)
4. [ ] 再度ブックを閉じる(保存する)
5. [ ] Excelを開いたまま(他のブックが無い状態でもよい)1分以上待つ

**期待結果**: 「マクロ 'AutoSyncTick' を実行できません」のようなエラーダイアログが**出ない**こと。ブックを閉じる際に `modBoot.Auto_Close` が `modShelfSync.CancelAutoSync` を必ず呼ぶ設計になっているため、閉じた時点で自動同期の予約(`Application.OnTime`)は解除されているはずである。
(手順3の開き直しを省略すると、`sync_interval_min` を1に変更する前の起動時点=既定値0のままOnTimeが一度も予約されないため、テストが常に見かけ上パスしてしまい不具合を検出できない。)

**失敗したら**: エラーダイアログが出た場合はOnTime予約が残っている不具合。`src/ui/modBoot.bas` の `Auto_Close` が実際に呼ばれているか(ブック側のイベント、または自己インストール後の `ThisWorkbook` 占有状況)を確認する。確認後、`modConfig.SetValue "sync_interval_min", 0` (+ `ActiveWorkbook.Save`)で元の値(既定 `0`)に戻しておくこと。
