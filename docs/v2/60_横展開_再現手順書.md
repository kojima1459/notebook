# 横展開・再現手順書（別グループ向けに同じボットを作る）

> **この文書の目的**：団体障害グループなど、別グループから約款・ガイドライン・マニュアルの提供を受けたら、
> **ミスなく・最短で**「費用利益保険チームと同じレベルのボット」を作れるようにする。
>
> 次スレッドで Claude に依頼するときは、**「`docs/v2/60_横展開_再現手順書.md` を読んで、このファイル群でボットを作って」** と
> リポジトリ名＋資料を渡すだけでよい。この手順書がそのまま作業指示書になる。

---

## 0. 前提と全体像

このツールは **ナレッジ入れ替え式**。VBAコードもプロンプトも商品非依存なので、
**変えるのは「ナレッジ（チャンク）」と「部署設定」だけ**。コードは原則さわらない。

```
新グループの資料（約款/GL/マニュアル/重説/商品部Q&A）
  ↓ ①チャンク化       structure_chunker.py  または  add_*_chunks.py
  ↓ ②富化            enrich_chunks.py（要約・キーワード・領域・書類種別を付与）
  ↓ ③部署設定         department / dept_scope を新グループ用に
  ↓ ④ビルド          build_chatbot_v2.py → dist/Chatbot_v2.xlsm
  ↓ ⑤ベクトル化       社内PCで admin パネル → 全件ベクトル化 → rag_enabled=TRUE
  ↓ ⑥精度検証→配布
```

所要：①〜④は開発者PC（Mac/Python）で1〜2時間（資料量による）。⑤は社内PCで数分〜十数分。

## 1. 必要なもの（依頼時に新グループからもらう）

| もらうもの | 形式 | 用途 |
|---|---|---|
| 普通保険約款 | PDF または テキスト貼り付け | 第一次根拠①（可否の最終根拠） |
| 引受ガイドライン | PDF または テキスト | 第一次根拠① |
| 商品マニュアル/ハンドブック | PDF または テキスト | 補足・解説 |
| 重要事項説明書 | PDF または テキスト | 手続き事実（告知/通知/解約等） |
| 商品部公式Q&A | Excel（`build/source_data/shohinbu_qa.xlsx` 形式） | 強い参考②（過去の回答事例） |
| 部署名・dept_id | テキスト | 部署マスタ登録 |

> **社内PCからPDFを出せない場合**：本文をそのまま貼り付けてもらえばよい（実績あり）。
> `add_pdf_chunks.py` がその「貼り付けテキストを取り込む」パターンの実例。

## 2. データ構造（これを満たせば動く）

### 2-1. チャンクの最終形（`dist/index/chunks_enriched.json` の1要素）

```json
{
  "source": "group_disability_yakkan.pdf",         // ファイル識別子（実在しなくてよい）
  "display": "団体障害保険 普通保険約款 (令X.X.X)",   // 出典として画面表示される名前
  "chunk_id": "group_disability_yakkan.pdf#0001",   // 一意ID
  "domain": "団体障害保険",                          // 業務領域タグ
  "doc_type": "普通保険約款",                        // 書類種別（下記の語彙から選ぶ）
  "section_header": "第1条（用語の定義）",            // 条文見出し
  "summary": "本約款で用いる主要用語の定義を定める。", // 1行要約（〜60字）
  "keywords": "定義, 被保険者, 保険金, 補償, 団体",    // キーワード5〜10語
  "full_text": "第1条 この約款において...",           // 本文
  "dept_scope": "common,group_disability"            // 可視範囲（後述）
}
```

### 2-2. `doc_type`（書類種別）の語彙（既存と揃える）
```
商品部公式Q&A / 普通保険約款 / 引受ガイドライン / 重要事項説明書 /
研修資料 / 解説 / FAQ / ハンドブック / 法令 / 監督指針
```

### 2-3. `dept_scope`（可視範囲）の考え方
- 新グループ専用ナレッジ → `group_disability`（dept_id と同じ文字列）
- 全グループ共通 → `common`
- 複数可視 → カンマ区切り `common,group_disability`

ルーターは「ユーザーの部署で可視なチャンク」だけを対象にする。これで部署間の情報混在を防ぐ。

## 3. 手順詳細

### ステップ① チャンク化
資料の入手形態で2通り：

**(A) きれいなPDFがある場合**
```bash
# PDF を build/source_data/ に置く
python3 build/structure_chunker.py     # 条文単位で chunks.json を生成
```

**(B) テキスト貼り付けの場合**
`build/add_pdf_chunks.py` を雛形にして、新グループ用の取り込みスクリプトを作る。
各チャンクは `C(source, display, cid, domain, doc_type, header, summary, keywords, text)` で1件追加。
**冪等**（再実行で該当 source を作り直す）に作ること。

### ステップ② 富化（要約・キーワード自動付与）
```bash
export GEMINI_API_KEY="（開発者の個人キー。社内のものではない）"
python3 build/enrich_chunks.py
```
- `enrich_chunks.py` の冒頭 `PDF_MANIFEST` に、**新グループの各ファイルの domain と doc_type を手で登録**する（ここだけは目視判断）。
- 出力：`dist/index/chunks_enriched.json`

> 富化は Gemini（`gemini-2.5-flash`）を使う安価なバッチ処理。1チャンク約1秒・並列。
> これは**前処理専用**で、本番ボットとは無関係（本番はリボン経由のGPT-5.5）。

### ステップ③ 商品部Q&Aの取り込み（あれば）
```bash
# build/source_data/shohinbu_qa.xlsx を新グループのQ&Aに差し替え
python3 build/add_shohinbu_qa_chunks.py     # doc_type="商品部公式Q&A" で追加
```

### ステップ④ 部署設定
`build/build_chatbot_v2.py` の：
- `DEPARTMENTS` に新グループを追加
  ```python
  DEPARTMENTS = [
      ("expense_profit", "費用利益保険チーム", "common,expense_profit"),
      ("group_disability", "団体障害グループ", "common,group_disability"),
  ]
  ```
- 単独配布なら `department_id` の既定を新グループにしてもよい（初回起動で選ばせる作りなのでなくても可）。

### ステップ⑤ ビルド
```bash
python3 build/build_chatbot_v2.py
# → dist/Chatbot_v2.xlsm が出力される
```
ビルドが通れば、ナレッジ埋め込み済みの配布ファイルができる。

### ステップ⑥ 社内PCでベクトル化（一度だけ）
1. `dist/Chatbot_v2.xlsm` を社内PCへ（GitHub/Teams/共有フォルダ/USB）
2. 開く（自己インストールが走る）
3. シートタブ右クリック → 再表示 → `admin`
4. 「① 埋め込み接続テスト」→ 成功 ✅・次元数1536 を確認
5. 「② 全件ベクトル化」→ 完了まで押す（中断されたら再度押す＝続きから再開）
6. シートタブ右クリック → 再表示 → `config` → `rag_enabled` を `TRUE`
7. Ctrl+S で保存 → **これが本番配布ファイル**

### ステップ⑦ 精度検証 → 配布
`docs/v2/50_ロードマップ.md` の検証方針に沿って、合格基準を**事前合意**してから検証する。

## 4. つまずきポイント（再現時の注意）

| 症状 | 原因 | 対処 |
|---|---|---|
| ビルドで `Missing chunks_enriched.json` | ②富化を実行していない | enrich_chunks.py を先に走らせる |
| 接続テストで「error」 | リボン無効/社外ネット/mock_llm | リボン有効・社内ネット・mock_llm=FALSE を確認 |
| ベクトル化が何度も中断 | ネットワークのタイムアウト | **正常。押し続ければ続きから再開**。最後に「成功/既存スキップ」で全件到達 |
| 回答が的外れ | チャンクの domain/summary が雑 | 富化のメタデータを見直す（ルーターは summary を強く見る） |
| 別部署のナレッジが出る | dept_scope の振り間違い | 専用ナレッジに `common` を付けていないか確認 |
| 開いても何も起きない | 自己インストール後 Boot 未発火 | 一度閉じて開き直す。または VBE で `modBoot.Boot` 実行 |

---

## 5. 絶対に守ること

- **VBAコード（src/chatbot_v2/*.bas）は原則さわらない。** ナレッジ差し替えだけで横展開できる設計を壊さない。
- **API キーを成果物に書かない。** リボン相乗りなので、そもそも書く必要がない。
- **ベクトル化前に `rag_enabled=TRUE` にしない。** 先にベクトル化 → 後で有効化（順序厳守）。失敗しても全件フォールバックするので致命傷にはならないが、順序は守る。
- **mock_llm を本番配布ファイルに TRUE のまま残さない。**
