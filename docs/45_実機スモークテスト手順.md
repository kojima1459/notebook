# 実機スモークテスト手順(R11完成版)

> **この文書は何か**: 配布zip・実機での「全機能を一通り動かす確認」。全35項目・
> 目安60〜90分(OCR待ちを除く)。**15分で済ませたい場合は、社内リポジトリの
> `docs/40_受入チェックリスト15分.md`(配布zipには同梱されていません)を
> 別途お使いください。** 探索ではなく、決められたチェック項目(各1-2分。
> 項目13は大きめの本棚がある人だけ、
> 項目19-23はスキャンPDF(画像PDF)の取込が必要。項目24は数十秒以上かかる処理なら
> 何でもよい(スキャンPDFは不要)。項目25-27は本棚に資料が
> 数件入っている状態で行う。項目28-31は画面の見た目・操作性の確認で、
> **Excel実機でしか確かめられない**もの=R18/R19の修正の当たり判定
> (特に項目28は今回の最重要項目です)。
> 項目32-34は条文形式の資料(社内規程・約款)がある人だけ
> (R17 Phase1 / Phase2 / Phase3)を順番に進めるだけです。R19以降に取り込んだ
> 資料はそのまま対象になり、それより前の資料はマイ本棚の「⚡仕上げ」
> (再取込不要・R20-3)で有効化してから進めます。
> 項目35は起動方法そのものの確認で、R19の要検証項目です。
> 不具合が見つかったら err_log のコードをメモして報告してください。

**前提**:
1. 配布zip(`MyBookshelf_配布.zip` 等)を右クリック → すべて展開
2. 展開されたフォルダの **`MyBookshelfを起動.bat`** をダブルクリックする
   (2026-08-06 R19-5c・実機第6報⑤。xlsm を直接ダブルクリックすると、
   開いたままの他のExcelへ吸い込まれ、取込中にそちらも一緒に固まる)
3. 黄色い警告バーが出たら「コンテンツの有効化」を押す(セキュリティ許可)
4. 画面が自動で組み上がるまで待つ(初回は10-30秒)
5. **新版を導入した直後は、他の項目より先に小さな資料を1件取り込み、
   コンパイルエラーが出ないことを確認する**(開発環境のLibreOfficeテストは
   実Excelの型検証を代替できない。実機コンパイルは実機でしか検証できない。
   2026-08-06 R19-2・実機第6報②)

**注**: 別ドキュメント `docs/44_P2P実機テスト手順.md` は「複数台・共有フォルダ連携」の詳細手順です。
このドキュメントとは独立した内容なので、P2P機能は不要な場合は 44 を読む必要はありません。

### 12. 終了 → 再起動 — データ保持確認
**操作**:
1. 取込した資料やチャット履歴がある状態で、チャット画面上部の **「❓ ガイド →「🩺 診断を開く」」** を押し、
   **`[本棚] チャンク数(my_knowledge): N 件`** の N をメモする(数字で比べるため)
2. 「🚪 終了」を押す
3. **必ず「保存して終了する」を選ぶ**(2026-08-05 R18-2g: 以前この手順書には
   「何もしなければ自動保存」と書いてあったが**事実と違う**。自動保存は存在せず、
   「保存しない」を選ぶとその日の取込は全て失われる)
4. ファイルを閉じる
5. 同じ `MyBookshelfを起動.bat` で開く
6. もう一度 **「❓ ガイド →「🩺 診断を開く」」** を押し、チャンク数が **手順1でメモした N と同じか** を見る

**期待**:
- 起動時の「数秒待機」中に共有フォルダへの接続を試みる(設定されている場合)
- 以前のデータ(資料・チャット履歴・ダッシュボード情報)が全て残っている
- **再起動前後でチャンク数が同じ**(減っていない)
- マイ本棚のカードに出る「◯件」も、診断のチャンク数と食い違わない
  (食い違っていたら自動で直り、usage_log に `manifest_fix` が1行残る。R18-2b)
- 起動時に「前回このアプリを保存したときは…件ありましたが、今は…件になっています」

**NGだったら**: データ消失は重大。err_log + 再起動時の e_log と、
**手順1と手順6のチャンク数の両方**をメモして報告。
`ファイル → 情報 → パスをコピー` の結果も添えること
(パスに `Temp1_...zip` や `\Temp\` が含まれていれば、zip の中から直接開いている)

### 13.(大きめの本棚がある人だけ)検索の待ち時間を測る
**なぜ**: 検索の速さは資料の量で決まります。開発環境では実際の待ち時間を
測れないため(ロジックしか実行できない)、**ここだけは実機の数字が正**です。

**操作**:
1. 診断画面で現在のチャンク数をメモする(例: 1,200件 / 5,000件 / 20,000件)
2. アプリを開き直した直後に、1回目の質問をして**回答が出るまでの秒数**を測る
3. 続けて別の質問を2回して、**2回目・3回目の秒数**を測る

**期待**:
- 1回目は「🔍 検索の準備をしています… N/N件」という表示が出て、そのあと回答。
  ここでベクトルを1回だけ読み込むため、**1回目だけ数秒〜十数秒長くなる**のは正常です
- 2回目以降はその準備表示が出ず、1回目より明確に速い
- 待っている間、画面が真っ白(応答なし)にならない。必ず「検索中 N/N件」等が動く

**報告してほしい数字**: チャンク数 / 1回目の秒数 / 2回目以降の秒数 / 途中で
無反応になったか。この3つの数字が、公称値(docs/70)を実測で裏づける根拠になります。

**NGだったら**: 2回目以降も1回目と同じだけ待つ場合は、usage_log に
`veccache_fallback` の行が無いか確認してください(メモリ不足でキャッシュを
諦めて従来の経路で動いています)。あれば、その行の内容も一緒に報告してください。

### 18. 着せ替え: ナレッジ/ダッシュボード画面でも🎨で即座に画面の色が変わること
**なぜ**: 「押しても何も変わらない」は故障と同じです(憲章§3-1)。配色の切替は

**操作**:

2. 「📊 ダッシュボード」でも同じく「🎨」を押す

**期待**:

### 33. 「〜を全部教えて」で章をまたいだ回答が返る(規程・約款を取り込んでいる人だけ)
**なぜ**: 「この規程を全部教えて」「全体像は?」「どんな種類がありますか」のような
**俯瞰の質問**は、これまで一番苦手でした。検索は質問の言葉に近い箇所を数件拾う
仕組みなので、一覧を聞いても「そのうちの1箇所だけ詳しく」返ってきます(合っては

**R19以降に取り込んだ資料はそのまま有効です(再取込不要)。それより前の資料は
マイ本棚の「⚡仕上げ」で有効化できます(再取込不要・R20-3)。**仕上げ(または
新規取込)は章の数だけAIを呼ぶので**資料によっては数十秒〜数分かかります**

残り時間が出ます)。**スキャンPDFでなくても**(文字がそのまま入っているPDFでも)、
大きな資料は数分かかります。新規に取り込む場合は、取込前の確認文にも
「(完了後に検索用の準備と章の要約が続きます。数分かかることがあります)」と
出ることを、あわせて確認してください。
**OCR資料(スキャンPDF・画像)は、章の境界(見出しがどこにあるか)が取込時に
確定するため、⚡仕上げでは章の要約は作り直せても見出し自体の精度は上がりません
(R21-3)。もっと正確な章立てにしたい場合は、⚡仕上げの完了メッセージが案内する

2. チャットで **「入念に調べる」** を選び、俯瞰の質問をする

3. 実況行に「🔭 俯瞰 1/3段…」「2/3段…」「3/3段…」と出ることを確認する
4. 回答と、その下の**信頼度バッジ**・**出典チップ**を見る
5. 診断画面 → usage_log を開き、`outline_built` と `global_answer` の行を探す
6. **短い俯瞰質問でも同じことが起きるか**を続けて確認する(R17H FA-6)。
   「入念に調べる」のまま **「全体像は?」**(6字)とだけ送る
   - 「もう少し詳しく教えてください」のような**聞き返しが出ないこと**
   - 2〜5と同じように俯瞰の実況・回答・`global_answer` が出ること
   - 同様に「概要を知りたい」「どんな種類がありますか」「補償の一覧」でも試す

**期待**:

### 34. 語彙が違っても資料が見つかる(名寄せ辞書。カタログ・約款・規程を取り込んでいる人だけ)
**なぜ**: 検索は言葉の一致に頼っているため、同じ意味でも資料と質問で書き方が
違うとヒットしないことがあります(例: 資料は「リコール」と書いているのに、

AIが用語の表記ゆれ(「回収」⇔「リコール」等)をグループにまとめた辞書

検索します(検索の仕組み自体は変えていません。質問文に語を足すだけです)。

**前提**: 「リコール」「回収」のように、意味は同じでも書き方が複数考えられる
用語を含む資料が必要です(保険商品のカタログ・約款・規程等)。**R19以降に
取り込んだ資料はそのまま有効です(再取込不要)。それより前の資料はマイ本棚の
「⚡仕上げ」で有効化できます(再取込不要・R20-3)**(章の要約=項目33の直後に
1回だけ生成されます)。**章の要約の直後に走る配線なので、`graph_outline` が
`off` の本棚と、章・条の見出しが取れない資料では辞書は増えません**
(項目33を先に通してください)。

**操作**:
1. (旧資料のみ)マイ本棚のツールバーで「⚡仕上げ」を実行する(項目33を先に。
   R19以降に取り込んだ資料はそのままで良い)
2. 診断画面 → usage_log を開き、`synonyms_built`(または `synonyms_fail`)の行を探す
3. チャットで、資料の中の言葉とは**違う書き方**で質問する
   (例: 資料が「リコール」と書いているなら「回収の保険は?」と聞く)
4. 回答と、その下の**出典チップ**を見る

**期待**:

    報告してください(R17H FA-1 で直した箇所の再発確認。以前は添字の誤りで

  - 表記ゆれの無い資料しか無い場合に限り、N=0 は正しい結果です

- 3の回答が、書き方の違いに関わらず該当資料を根拠にしている
  (「資料からは確認できません」にならない)
- **取り込み直していない資料しか無い人・表記ゆれの無い資料しか無い人**: これまで

その資料名と質問文を報告してください(用語がAIの名寄せ対象から外れた可能性が
あります)。辞書が意味の違う語をまとめてしまう・回答が的外れになると感じる
場合は、config シートの **`graph_synonyms` を `off`** にすると質問文への
同義語追記をしなくなります(既に作った辞書は残ります)。

### 35. 同居検出: 他のExcelを開いたまま本体をダブルクリックすると警告が出る(R19-5・今回の要検証)
**なぜ**: 「再起動したら、開いたままの作業用Excelごと固まって強制終了しかなかった」
への対処です。Excelは**既定で複数ブックを1つのプロセスへ結合**します。
本体xlsmをダブルクリックすると、生き残っていた別のExcelのプロセスへ本体が
吸い込まれ、以後は本体の取込(OCRの同期呼び出し)が**プロセス全体**を止めます
=相手のブックも、本体の「■中断」ボタンも、まとめて反応しなくなります。
VBAからこの結合を防ぐ手段は公式仕様上存在しない(`DisableMergeInstance` は
ダブルクリックには効かないとMicrosoftが明記)ため、**検出して伝える+正しい
入口(ランチャー)を配る**の二段構えにしました。**Excel実機でしか確かめられません。**

**操作**:
1. MyBookshelf本体をいったん**閉じる**
2. Excelを1つ、普通に起動して空のブックを開いたままにする
   (または本体の「🗔作業用Excel」で開いたものを閉じずに残す)
3. その状態で、エクスプローラーから **`MyBookshelf.xlsm` をダブルクリック**する
4. マクロを有効化して起動を待つ
5. 起動後、「📚 ナレッジと本棚」→「📁 資料を追加」でファイルを1件選ぶ
6. いったん全部閉じ、今度は **`MyBookshelfを起動.bat`** から起動して、
   同じく「📁 資料を追加」でファイルを1件選ぶ

**期待**:
- **① 手順4のあと、「他のExcelブックと同じプロセスで開かれています。…
  同梱の「MyBookshelfを起動」から開き直すことをおすすめします」という警告が
  1回だけ出る**(起動のたび何度も出ない。相手のブック名は出ない)
- **② 手順5でファイルを選んだ直後に「他のブックが同じプロセスにあります。
  取込中はそれらも操作できなくなります。続行しますか?」が出る。
  「いいえ」を押すと取込は始まらない**(何も取り込まれない)
- **③ 手順6(ランチャー起動)では、①②のどちらの警告も出ない**
  ——これが「ランチャーから開けば安全」の確認です
- usage_log シートに `cohabit_detected` の行が残る
  (「いいえ」を選んだときは `cohabit_abort` も)
- 文字化けした記号(□や?)がダイアログに出ていない

**NGだったら**: ①が出ない場合は、そのとき開いていたExcelの数と開き方をメモ。
③で警告が出てしまう場合は**ランチャーが効いていない**ので最優先で報告
(bat の中身と、タスクマネージャーの `EXCEL.EXE` の数を一緒に)。
なお、警告が出た状態でも取込・質問そのものは従来どおり動きます
(この機能は止めるのではなく**知らせる**ためのものです)。

## 不具合が見つかったら

各項目の説明の「NGだったら」に従い:
1. err_log シートを開く(診断画面 → 下へスクロール)
2. 最新のエラー行を見つけて **「コード」列の値(E0xxx)** をメモ
3. 「detail」列に書かれている詳細情報も一緒にメモ
4. 報告する際は、チェックリストの項目番号 + エラーコード + 詳細 の順で報告するとスムーズです

**例**: 「項目3のPDF取込でE0302が出ました。ファイルは PDF形式で権限もあります」

## 注記

- このチェックリストは「問題がないか確認」が目的です。深掘りの探索ではありません。
- チェック順は意図的に設計されており(初期化→質問→取込→ナレッジ→ダッシュボード→終了)、
  スキップすると隔たりが出る可能性があるため、できるだけ順番に進めてください。
- 各項目で「問題なし」なら「✓」をつけて進めると管理しやすいです。
- ネットワーク接続・共有フォルダが無い環境でも動作しますが、質問・OCR・要約には社内 AI が必要です。
- 共有機能を使う場合はヘルプ→共有フォルダ設定で部の共有パスを入力してください
  (未設定なら「みんな」統計は動きません)。
