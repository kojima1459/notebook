> **この文書は誰向けか**: 「マイ本棚AI」を作って社内に配る**非エンジニアの保守担当**向けです。
> **何が分かるか**: ビルドのやり方・配り方・モックから本番への切替時の注意・配る前の確認手順が分かります。

---

## 0. 全体の流れ

```
① 開発ビルドで動作確認(--dev)
     ↓
② 配布前チェック(lint + テスト + 受入チェックリスト)
     ↓
③ 本番ビルド(--prod)
     ↓
④ .xlsm ファイル1個を配る
     ↓
⑤ 相手が初回起動(自己インストール+マクロ有効化)
```

「マイ本棚AI」は **Excelファイル(.xlsm)1個だけ**で完結します。
サーバーもインストーラも別に要りません。

---

## 1. ビルド手順

ビルドとは、ソースコード(`src/` フォルダの中身)から実際に配れる `.xlsm` ファイルを
組み立てる作業です。手を動かすのはパソコン1台とターミナルだけです。

### 1-1. 事前準備(最初の1回だけ)

```bash
pip install openpyxl olefile
```

- なぜ: ビルドスクリプトが Excel ファイルの中身(シート・マクロ)を組み立てるのに使う部品です。
- 一度入れれば、次回以降は不要です。

### 1-2. 開発ビルド(社内テスト用)

```bash
cd /path/to/nexus-agent   # このリポジトリのルート
python3 build/build_mybookshelf.py --dev
```

- なぜ: `--dev` で作ると `config` シートの `mock_llm` が `TRUE` になり、
  社内AIリボン(ChatGPT関数)が無いパソコンでも、ダミー応答で一通りの画面確認ができます。
- 出力先: `dist/MyBookshelf_dev.xlsm`

### 1-3. 本番ビルド(配布用)

```bash
python3 build/build_mybookshelf.py --prod
```

- なぜ: `--prod` で作ると `mock_llm` が `FALSE` になり、実際に社内AIリボンへ問い合わせます。
  **配布する本物のファイルは必ずこちらを使ってください。**
- 出力先: `dist/MyBookshelf.xlsm`

### 1-4. ビルドが失敗したときの合図

ビルドスクリプトは、作ったファイルがおかしい場合は **画面に赤字のエラーを出して止まります**
(`exit code 1`)。「Done.」という文字と `自己検証 OK` が出ていれば成功です。

途中で欠けているモジュール(ソースファイル)があると `--allow-missing` を付けない限り
そこでも止まります。**配布用ビルドでは `--allow-missing` は絶対に使わないでください**
(欠けたまま気づかずに配ってしまう事故を防ぐためのブレーキです)。

### 1-5. よく使うオプション(必要なときだけ)

| オプション | 用途 |
|---|---|
| `--out PATH` | 出力ファイル名・場所を変えたいとき |
| `--modules PATH` | `modules.json`(モジュール台帳)を差し替えたいとき |

詳しくは `build/README.md` を参照してください(このドキュメントと矛盾する場合は
実際に動くビルドスクリプトの挙動が正です)。

## 2. 配布手順

### 2-1. 渡すのは .xlsm ファイル1個だけ

`dist/MyBookshelf.xlsm` を、メールやチャット、共有フォルダなどで
**そのまま1個渡すだけ**です。インストール作業・追加ファイルは一切不要です。

### 2-2. 初回起動は「自己インストール」

相手が初めてこのファイルを開くと、ファイルの中に埋め込まれたインストーラが
自動的に動き、必要な画面(ホーム/マイ本棚/ダッシュボード)を組み立てます。
相手側で何かをインストールする操作は不要です。

### 2-3. 「マクロを信頼する」設定が必要(2項目とも必須)

自己インストールの都合上、Excel側の設定変更が **(A)(B)の2項目とも** 必要です。
どちらか一方だけでは初回起動が失敗します。これは「使い方」タブ(マクロが無効でも読める救済ページ)にも書かれている内容です。

1. ファイルを Excel で開く
2. (A) 黄色い「セキュリティの警告」バーが出たら「コンテンツの有効化」をクリック
3. (B) 続けて `[ファイル]→[オプション]→[トラストセンター]→[トラストセンターの設定]→[マクロの設定]`
   で「**VBAプロジェクトオブジェクトモデルへのアクセスを信頼する**」にチェック→OK→Excel再起動
   (この設定は「バーが出ない場合の代替策」ではなく、初回起動に無条件で必要です)
4. ファイルを開き直すと、数秒で画面が自動的に構築されます
   (設定していないと「VBA Project trust required. See howto sheet.」という英語のダイアログが出て起動が止まります)

- なぜこの設定が要るか: このファイルは開いた瞬間にマクロがマクロ自身を組み立てる
  「自己インストール」方式のため、通常のマクロ有効化(A)に加えて(B)の1項目が必ず必要です。
- 初回起動時、名前(パック共有時の表示名)を聞かれます。空欄のままでも「名称未設定」で進めます。

## 3. モック→本番切替の注意(重要)

### 3-1. mock_llm とは

`config` シートの `mock_llm` を `TRUE` にすると、社内AIリボンを一切呼ばず、
決定的なダミー応答・ダミーの埋め込みベクトル(文章をAIが読める形に変換した数字の列)
で動作します。リボンが無いパソコンでも取込→検索→回答の一通りの流れを確認できる、
開発・デモ用の仕組みです。

**注**: R16-3系(複合質問の論点分け・番号の選択肢による聞き返し)は `mock_llm` では
発火しません(モックの段0は常に `single` = 分解しない、と答えるよう固定してあります)。
これらの動作確認は `mock_llm` を `FALSE` にした実機で行ってください。

### 3-2. 危険なポイント: 埋め込みベクトルが別物になる

**mockのベクトルと本番(実際のAIリボン)のベクトルは、次元数も値も別物です。**
mock時にすでに取り込んで「AIが読める形」に変換済みの資料は、`mock_llm` を `FALSE` に
切り替えても**自動では変換し直されません**。放置すると、検索が資料をうまく
見つけられなくなる(回答の精度が落ちる)おそれがあります。

- 次元数(ベクトルの長さ)が config の `embed_dim` の変更などで実際にズレた場合は、
  検索時に **E0702** としてログに残る安全網があります(§6のエラーコード表参照)。
- ただし **次元数が同じまま値だけが別物**(mockの疑似ベクトル→本番の実ベクトル)の場合は、
  この安全網では検知できません。検索は動き続けますが、精度が黙って落ちます。

### 3-3. やるべきこと(Wave4申し送り事項)

`mock_llm` を `FALSE` に切り替えた後(または `--dev` ビルドで試した後に `--prod` へ
乗り換えた後)は、**次のどちらかを必ず行ってください**:

| 方法 | 手順 | 向いているケース |
|---|---|---|
| 資料を入れ直す | 「マイ本棚」タブの「＋ 資料を追加」で、同じファイルをもう一度選び直す | 資料が少ない・特定の数件だけ確認したい |
| 🗑で削除して🔄同期で入れ直す | 「マイ本棚」タブの「🗑 選んだ資料を削除」で対象資料を削除→本棚フォルダに元ファイルがあれば「🔄 フォルダと同期」で再取込 | フォルダ同期で運用している資料をまとめて直したい |

**注意**: 内容もタイムスタンプも変わっていないファイルに対して「🔄 フォルダと同期」を
そのまま押しても、変更なしと判断されて**再取込は起きません**(同期は「ファイルが
変わったかどうか」だけを見る仕組みのためです)。ベクトルを作り直したい資料は、
上の表のとおり明示的に入れ直してください。

## 4. 配布前チェック

配布用ビルド(`--prod`)を作る前に、必ず次の3段階を通してください。
1つでも赤(エラー・FAIL)が出たら配布しないでください。

### 4-1. 静的チェック(コードの書き方の間違いを検出)

```bash
python3 tools/vba_lint.py
```
- 何をするか: 全モジュールを実行せずに読むだけで、書き方の間違い・契約違反を検出します。
- 合格の目印: `ERROR: 0 件` かつ `結果: OK(exit code 0)`

### 4-2. LibreOffice実行テスト(実際に動かして確認)

```bash
python3 tools/run_lo_tests.py
```
- 何をするか: 純ロジック部分を実際に実行してテスト+全モジュールの構文チェックを行います。
- 合格の目印: `PASS` の件数のみで `FAIL 0`、かつ全モジュールでコンパイル成功

### 4-3. 受入チェックリスト(実機での最終確認)

`docs/40_受入チェックリスト15分.md` に沿って、配布先と同じような実機(Windows Excel)で
15分ほどの手動確認を行ってください。診断→mockでのE2E確認→リボン実接続確認→
資料1件取込→質問→パック書き出し/取込→終了時にOnTimeの予約が残っていないこと、
までを確認する項目です。

上記3段階が終わってから、あらためて `python3 build/build_mybookshelf.py --prod` を
実行し、その出力ファイルを配布してください(チェックはソースコードに対して行うので、
**チェック後に取り直したビルド**を配ることが重要です)。
