## 0. 一行でいうと

**「ポータルで見つけたマニュアルを、読まずに、承認も待たずに、そのままぶちこんで、すぐ聞ける」社内版NotebookLM。** V2の承認制ナレッジ基盤の上に、個人が自由に育てられる「マイ本棚」を載せ、ナレッジパックで人から人へ伝播させる。

### 解決する痛み（現場の実態）

1. ポータル/シェアポが散らかっていて、知りたい情報が**どこにあるか分からない**
2. 見つけたマニュアルも情報量が多すぎて、**どこに書いてあるか探すのに時間がかかる**
3. そもそも**そのドキュメントに載っているのか確証がない**まま探している
4. → 結果「マニュアル探して読むより本社照会した方が早い」→ 照会が本社に重くのしかかる → 営業の理解も進まずナレッジが貯まらない

### UXの北極星

- **説明書なしで直感的に使える**（iPhone基準）
- **承認なしで、今、使える**（即効性）
- **探す・読む・待つを消す**（「読む前に聞ける」が本質価値）
- APIコストは審査条件外 → **速度と体験に全振りする**

## 1. 3層ナレッジモデル（品質担保と即効性の両立）

```
┌─────────────────────────────────────────────┐
│ ①公式ナレッジ（V2既存）                        │
│   990チャンク。承認制。出典[#N]付き精査回答。       │
│   品質担保層。部の資産。                         │
├─────────────────────────────────────────────┤
│ ②マイ本棚（V3新規）                            │
│   個人が無承認でぶちこむ層。即時利用可。            │
│   回答には「※個人取込資料」と出所を明示。           │
├─────────────────────────────────────────────┤
│ ③ナレッジパック（V3新規）                       │
│   マイ本棚を1ファイルに書き出して交換する流通層。     │
│   良いパックは承認会で①へ昇格できる。              │
└─────────────────────────────────────────────┘
```

- 検索時は①＋②を横断（configで②のみ/①のみも選択可）。
- 回答内で出所を必ず区別する：`[#N]`＝公式、`[本棚:ファイル名]`＝個人取込。V2の「根拠3階層」の思想を維持し、**個人取込は精査回答の可否根拠にしない**（ヒント・参照として提示）。
- 昇格経路：パックが部内で広く使われる → ナレッジ承認会で内容確認 → 公式ナレッジへ取込。**個人の即効性 → 仲間内の伝播 → 部の公式資産**という一方通行のエスカレーターが、そのまま組織部門の審査ストーリーになる。

## 2. 2速回答モード

| | ⚡即答モード | 🔍精査モード |
|---|---|---|
| 用途 | 今すぐヒントが欲しい。マイ本棚への質問 | 照会・顧客/代理店回答。公式ナレッジ中心 |
| パイプライン | 検索→ドラフトの**2段** | V2既存の4段（意図解釈→検索→ドラフト→自己検証） |
| モデル | gpt-5.4等 + `reasoning_effort=minimal` + `verbosity=low` | GPT-5.5フル（検証のみ軽量モデル可） |
| 目標時間 | **10〜20秒** | 60〜90秒 |
| 出典表示 | 簡易（ファイル名＋該当箇所） | [#N]完全出典＋自信度🟢🟡🔴 |

- 実装は `modPipeline` に `speed_mode` 分岐を足すだけ。モデル・effort・verbosityは`ChatGPT()`の既存引数（仕様確認済み）＋configシートで制御。**コアのコード変更は最小**。
- デフォルト：マイ本棚宛て質問＝即答、公式ナレッジ宛て＝精査。ワンタップで切替。

### 待ち時間の体感設計（ストリーミング不可の制約下）

1. **ステージ実況**：「🔍 検索中… → 📄 12件ヒット → ✍️ 回答作成中… → ✅ 検証中…」
2. **出典の先出し**：埋め込み検索は約1秒で終わる → ヒットした資料名を即表示してからドラフト生成へ。「自分の入れたあのマニュアルに載ってる」が数秒で分かる＝離脱防止の要
3. **ESCキャンセル**（既存パターン流用）
4. **待ち時間の豆知識**：承認済みQ&A・今週のナレッジパックランキング等をローディング中にランダム表示（学習にもなり一石二鳥）

## 3. 取り込みパイプライン（V1遺産の再生）

### 流用する既存資産（すべて実装済み・純VBA）

| モジュール | 何をするか | 状態 |
|---|---|---|
| `src/admin/modExtractor.bas` | 拡張子で振り分け：txt/md/csv（ADODB直読）、**PDF（Word PDF Reflow→Acrobat COMフォールバック）**、docx/doc（Word COM）、xlsx/xls/xlsm（Excel） | V1実装済み。ページ番号付き抽出 |
| `src/admin/modExtractorWord.bas` | Word COMでPDF/docxをページ単位抽出（`ConfirmConversions:=False`でReflowプロンプト抑止） | V1実装済み |
| `src/admin/modChunker.bas` | 段落対応スライディングウィンドウ（目標700字・オーバーラップ150字・文境界優先）＋L2正規化 | V1実装済み |
| `modKnowledgeBuilder.PickFiles` | 複数ファイル選択ダイアログ（フィルタ付き） | V1実装済み |
| `src/chatbot_v2/modEmbeddings.bas` | リボン`GetEmbeddings()`の防御的窓口 | V2実装済み |
| `src/chatbot_v2/modVectorize.bas` | 進捗バー＋ESC中断＋再開可能のバッチ処理パターン | V2実装済み |

**V1が死んだのはembed工程の外部API直叩きだけ。** そこを`modEmbeddings`（リボン相乗り）に差し替えれば、社内PC単体で完結する取り込みパイプラインが完成する。

### 処理フローと時間予算（100ページのマニュアルの例）

```
ファイル選択（ダイアログ or 取込フォルダ）
 → 抽出（Word COM・数十秒）
 → チャンク分割（純VBA・一瞬）→ 約250チャンク
 → バッチ富化（任意）：10チャンク/1回のChatGPT()呼び出しでJSON一括返し
    （1行要約＋キーワード付与）→ 25回 × 約10秒 ≒ 4分
 → ベクトル化：GetEmbeddings() 250回 × 約1秒 ≒ 4〜5分
 → my_knowledge / my_vectors シートへ保存
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
合計：富化あり 約10分 / 富化なし 約5分
```

- 富化はconfigで「なし／軽量（gpt-5.4-nano）／フル」を選択可。**個人ナレッジのデフォルトは軽量**（速度優先。精度が欲しくなったら後から富化を追い掛け実行できる設計に）。
- 全工程は`modVectorize`の再開可能パターンを踏襲：途中でExcelを閉じても続きから再開。
- スキャン画像PDF（文字が画像）はWord Reflowで抽出不可 → 検知したら「画像PDFのため取込不可（Vision対応は将来拡張）」と明示して**静かに失敗しない**。

## 4. OneDrive差分同期（「エクスプローラーがナレッジ管理画面」）

リアルタイム監視（FileSystemWatcher）はVBA単体不可。**ポーリング差分方式**で同等のUXを実現する。

```
マイ本棚に「本棚フォルダ」を登録（OneDrive/シェアポ同期フォルダ＝ただのローカルパス）
 → 同期契機：ブック起動時 ／「🔄同期」ボタン ／ Application.OnTime（N分おき・config）
 → フォルダを走査し、my_manifest（ファイル名・更新日時・サイズ）と突合：
    ・新ファイル        → 自動取込
    ・更新日時が変わった → 旧チャンク削除 → 再取込
    ・消えたファイル     → チャンク＋ベクトルを自動削除
```

- **「OneDriveから消せばボットからも消える」「入れれば翌朝使える」**がこの方式でそのまま成立。ゴミ箱UIを作る必要すらない — ファイル操作がそのままナレッジ操作になる。
- シェアポのドキュメントライブラリも「OneDriveに同期」すればローカルパスになる＝**実質シェアポ接続**（Graph API不要・外部API制約に非抵触）。
- 段階リリース：v1＝フォルダ登録＋手動同期ボタン → v2＝起動時自動差分 → v3＝OnTime定期ポーリング。
- 手動の複数ファイル選択ダイアログも並存させる（フォルダを作るまでもない単発取込用）。

## 5. ナレッジパック交換（skills.md的な伝播設計）

- **書き出し**：マイ本棚から資料単位（または本棚全体）を選び、1つの`.xlsx`パックに出力。中身＝チャンク表＋ベクトル表＋メタ（作成者・作成日・元ファイル名・説明文・パック名）。
- **読み込み**：同僚のパックを開いて「取込」ボタン → 自分のマイ本棚にマージ。出所（`pack:作成者名`）をチャンクに刻む。
- **互換性の根拠**：全員が同じリボン（同じ`text-embedding-3-small`・L2正規化済み）でベクトル化しているため、**ベクトルごと交換しても検索互換が保たれる**。再ベクトル化不要＝取込は数秒。
- 重複対策：chunk_idにコンテンツハッシュを含め、同一チャンクの二重取込をスキップ。
- **PII注意**：パックは人に渡るファイル。書き出し時に`modPii`（既存）でスキャンし、個人情報らしき文字列があれば警告を出してから出力する。
- ゲーミフィケーションとの接続：パックに作成者名が入る → 「自分のパックが何人に取り込まれたか」がダッシュボードに載る（§7）。**作る動機＝配る動機**になる構造。

## 6. UI/UX設計原則

1. **メイン画面はV2踏襲＋モード切替タブ**：「⚡すぐ聞く｜🔍しっかり調べる」の2タブ。迷わせない。
2. **マイ本棚画面**：本棚の中身を「資料カード」の一覧で表示（ファイル名・取込日・チャンク数・状態）。ボタンは「＋追加」「🔄同期」「📦パック書き出し」「🗑削除」の4つだけ。
3. **多言語**：configに`answer_language`（日本語/English/中文…）→ システムプロンプトで回答言語を指定するだけ。UIラベルは文字列シート化して切替。`Translate()`関数には依存しない（未検証関数を初期リリースの必須経路に置かない）。
4. **すべてフェイルセーフ**（V2の肝⑥踏襲）：取込失敗はスキップして続行・要因を資料カードに表示。「動かない」を構造的に潰す。
5. **自由度**：ナレッジに何を入れるか・どう使うかはユーザーに委ねる。「型」を渡して運用は現場の創意に任せる（横展開しやすさ＝規定しすぎないこと）。

## 9. データモデル（新規シート）

| シート | 役割 | 主な列 |
|---|---|---|
| `my_knowledge` | マイ本棚チャンク本体 | chunk_id, source, origin(自取込/pack:作成者), summary, keywords, full_text, added_at |
| `my_vectors` | マイ本棚ベクトル（veryHidden） | chunk_id, vector_csv |
| `my_manifest` | 本棚フォルダ同期台帳 | file_path, file_name, modified_at, size, chunk_count, status(取込済/失敗/画像PDF) |
| `my_stats` | 個人ダッシュボード集計 | 期間, 自己解決数, 削減分, パック取込られ数, バッジ |
| （パックファイル） | 独立`.xlsx` | pack_meta（名前/作成者/説明/日付）＋chunks＋vectors |

公式側（`knowledge_base`/`kb_vectors`/`feedback`/`usage_log`）は無変更。**V2の本番稼働に一切手を触れずに載せられる**（configフラグ`my_shelf_enabled`で丸ごとON/OFF、V2の`rag_enabled`ゲートと同じ思想）。

## 11. 性能予算とスケール設計

| 論点 | 設計 |
|---|---|
| チャンク総数の増加（公式990＋本棚で数千へ） | 埋め込み検索は純VBA全件走査＝件数に線形。3000件で約3倍だが、**Phase2.5の次元削減（1536→256、MRL対応で精度劣化小）で約6倍速**を同時投入し、1秒以内を維持。LLMに渡す件数は40→12で一定のため、母数増でも回答時間・コストは不変 |
| チャンク粒度 | 増やす方向は「範囲を広げる」が正。**細かく刻みすぎは文脈が痩せて逆効果**。700字/150字の現行パラメータを維持し、精度が必要になったら親子チャンク（検索は子・LLMには親条文）を次の一手に |
| ファイルサイズ | ベクトルはシート文字列保存。数千チャンクで数十MB級 → 次元削減で1/6。本棚上限（例：5000チャンク）をconfigで持ち、超過時は古い資料の整理を促す |

## 12. 未確定事項（仕様照会の回答待ち）と依存関係

| 未確定 | 影響する機能 | 回答が得られない場合の退避 |
|---|---|---|
| `LimitCheck`の閾値（回数/サイズ上限） | 取込バッチ全般 | 呼び出し間隔スロットリング＋再開可能設計で安全側に倒す（既存パターン） |
| `ChatGPTV`（Vision）仕様 | 画像PDF・画像で質問 | 将来拡張から外すだけ。コアに影響なし |
| `ttsFile/ttsSpeak`仕様 | 読み上げ・聴く約款 | 同上 |
| `CellMarkDown`仕様 | 回答リッチ表示 | 通常セル出力で代替（見た目のみ劣化） |
| `Translate/TranslateS`仕様 | （非依存に設計済み） | 影響なし（多言語はプロンプトで実現） |

**コア（本棚・同期・パック・2速・ダッシュボード）は★確認済みの`ChatGPT()`/`GetEmbeddings()`と純VBAのみで完結する** — 未検証関数の回答待ちがクリティカルパスに乗らないのがこの設計の要。

## 14. コンテスト戦略への接続

- エントリーの背骨は据え置き：**「部一体・照会ダイエット運動」**（V2基盤＋計測＋承認会体制＋横展開）。
- マイ本棚は「なぜ営業は照会よりボットを使うのか？」という審査の急所への回答として組み込む：**探す・読む・待つが消えるから使う**。
- 審査員への一言説明：「**社内版NotebookLM。公式ナレッジは部が承認し、個人ナレッジは各自が育て、良いものはパックで伝播して公式に昇格する**」— 個人の即効性と組織の品質担保の両立、が組織部門の審査基準（部一体・継続体制・横展開）にそのまま重なる。
- 優勝はこのツール最大のマーケティング：「興味本位で使ったらハマる」導線（即効性＋ゲーミフィケーション）を仕込んでおく。
