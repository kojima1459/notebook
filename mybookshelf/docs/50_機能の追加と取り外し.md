> **この文書は誰向けか**: 「マイ本棚AI」の追加機能(画像読み取り・Markdown表示/Wordで開く・約款差分)を**取り外す・有効化する・新しく追加する**作業を行う、非エンジニアの保守担当向けです。
> **何が分かるか**: `build/modules.json` の何行目を消せばよいか、`config` のどのフラグをFALSE/TRUEにするか、仕様が判明したときに `src/opt/*.bas` のどこだけを直せばよいかが、実際のコードを引用しながら分かります。

---

## 0. 前提: opt機能とは何か

「マイ本棚AI」の追加機能(**opt機能**)は4つあります。いずれも「無くても本体(取込・同期・質問・パック・ダッシュボード)は完全に成立する」設計です。

| featureId | モジュール | できること | 既定フラグ(`config`) |
|---|---|---|---|
| `tts` | `optTts` | 回答の読み上げ(**非提供確定・ビルド対象外**) | `feature_tts` = `FALSE`(固定) |
| `vision` | `optVision` | 画像の文字読み取り・スクショ取込 | `feature_vision` = `TRUE`(公式仕様確定済み) |
| `markdown` | `optMarkdown` | Markdown整形表示・回答をWordで開く | `feature_markdown` = `TRUE`(公式仕様確定済み) |
| `diffdoc` | `optDiffDoc` | 約款(新旧2ファイル)の差分分析 | `feature_diffdoc` = `TRUE`(確認済みのAI関数だけを使うため既定で有効) |

`tts`/`vision`/`markdown` は、社内AIリボンの該当関数(`ttsSpeak`/`ChatGPTV`/`CellMarkDown`)の**正式な仕様(引数の順番や戻り値の形式)がまだ確認できていない**ため、既定でオフ(`FALSE`)になっています。`diffdoc` は仕様確定済みの `ChatGPT()` 関数だけを使うため既定でオンです。

## 1. 撤去手順(機能を丸ごと消したいとき)

**やることは2つだけです。**

### 手順A: `build/modules.json` から該当1行を削除する

現在、4つのopt機能は `build/modules.json` の `modules` 配列にこう書かれています(実際の行)。

```json
    { "name": "optTts",              "path": "src/opt/optTts.bas",                     "role": "opt",  "type": "std",   "wave": "2-G" },
    { "name": "optVision",           "path": "src/opt/optVision.bas",                  "role": "opt",  "type": "std",   "wave": "2-G" },
    { "name": "optMarkdown",         "path": "src/opt/optMarkdown.bas",                "role": "opt",  "type": "std",   "wave": "2-G" },
    { "name": "optDiffDoc",          "path": "src/opt/optDiffDoc.bas",                 "role": "opt",  "type": "std",   "wave": "2-G" },
```

たとえば読み上げ機能(`optTts`)を撤去したい場合は、上の1行目(`"name": "optTts"` の行)だけを削除して保存します。カンマの位置がずれないよう、前後の行の `,` は変えないでください(JSON構文が壊れます)。

### 手順B: `config` の対応フラグを `FALSE` にする

`build/build_mybookshelf.py` は、ビルド時に `config` シートへ次の初期値を書き込みます(実際の行)。

```python
        ("feature_tts", False, "opt機能フラグ: 読み上げ(AIリボン非公開機能のため提供不可。既定FALSEのまま変更しない)"),
        ("feature_vision", True, "opt機能フラグ: 画像読み取り・スクショ取込(公式仕様確定済み。問題があればFALSEで無効化)"),
        ("feature_markdown", True, "opt機能フラグ: Markdown表示・Wordで開く(公式仕様確定済み。問題があればFALSEで無効化)"),
        ("feature_diffdoc", True, "opt機能フラグ: 約款差分比較(確認済み関数のみ使用のため既定TRUE)"),
```

`optTts` を撤去する場合、この `("feature_tts", False, ...)` の1行目はすでに `False` なので、実は**何も変更しなくてもよい**ことが多いです。もし配布済みのブックで一度 `TRUE` にしたことがある場合は、`config` シートを再表示し、`feature_tts` の行のB列を `FALSE` に書き換えてください(すでに撤去する機能を使っていた既存ブックの場合のみ必要な手順です)。

### 手順C: 再ビルドする

```bash
python3 build/build_mybookshelf.py --prod
```

これで完了です。`optTts.bas` はビルドされた `.xlsm` の中に一切含まれなくなります。

### optTts(読み上げ)について — 非提供確定

**社内AIリボンの公開仕様により、読み上げ機能(`ttsSpeak`)はリボン拡張ツールへの提供が非提供と確定しています**。
このため、マイ本棚AI では `optTts` は既定で撤去してあります。
読み上げ機能が必要な場合は、AIリボンのUIから直接利用してください。

## 2. 撤去してもコアが無傷である理由(保守者向け・3行)

1. コア側のどのモジュールにも `optTts.` のような直接参照は一切書かれていません(`tools/vba_lint.py` がこれを機械検査しています)。呼び出しは常に `modFeatures.InvokeFeature` 経由の**文字列からの遅延バインド**(`Application.Run`)です。
2. `modFeatures.ModulePresent` はモジュールの実在を `Application.Run "optTts.Ping"` で**その場で試すだけ**なので、モジュールが無ければ単にエラーを検知して `False` を返すだけで、コア側は落ちません。
3. UI側のボタンは `modFeatures.FeatureEnabled` が `True` のときだけ生成されるため(例: `modUIMain.EnsureLayout` 内の「📝 Wordで開く」ボタン)、モジュールが無い/フラグがOFFのときはボタン自体が最初から表示されません。

## 3. 有効化手順(リボン仕様の回答が来たとき)

> **お知らせ(2026-07)**: `ChatGPTV`/`CellMarkDown` 等は社内公開ページで正式仕様が確定し、
> `feature_vision`/`feature_markdown` は**既定で有効化済み**です。この章の手順は、今後
> 「仕様が未確認の新しいリボン関数」に依存するopt機能を作るときの参考として残しています
> (例として引用しているoptTtsは、音声合成の非公開確定によりビルド対象外のソース保管品です)。

将来、仕様未確認のリボン関数に依存する機能の正式仕様が判明したら、以下の手順で有効化します。

### 手順A: 該当opt モジュール先頭の `SIGNATURE ASSUMPTION` ブロックを直す

各opt モジュールの冒頭には、未確認の関数仕様について「今こう仮定している」ことと「仕様が判明したら**どこだけ**を直せばよいか」がまとめて書かれています。**このブロックの指示どおりに、指定された関数だけを直してください**(他の箇所は触らない)。

**`src/opt/optTts.bas`(読み上げ)の実物**:

```vba
' === SIGNATURE ASSUMPTION ===
'   仮定シグネチャ: ttsSpeak(text As String) -> 戻り値は空文字("")で成功、
'                   もしくはエラー文字列("error"等)を返す想定。
'   根拠: MASTER_SPEC §7.7 optTts.bas の記載「ttsSpeak仮定: (text)」のみが
'     根拠であり、他に一次情報は無い。第2引数(音声種別/速度等)や戻り値の
'     成功時フォーマットは未確認。リボンちゃんの他の関数(ChatGPT/
'     GetEmbeddings)が「成功時は文字列、失敗時はエラーを示す文字列」を
'     返す設計であることに倣い、同型を仮定した。
'   仕様回答が来たら直す行:
'     ・引数の数/順序が違う場合 -> BuildTtsArgs() の Array(...) 部分のみ修正。
'     ・戻り値の成功判定基準が違う場合(例: 空文字ではなく"OK"を返す等)
'       -> IsTtsSuccess() の判定式のみ修正。
'     ・関数名自体が違う場合(ttsSpeak以外) -> Private Const RIBBON_FUNC_NAME
'       の値のみ修正。
' ================================================================================
```

**`src/opt/optVision.bas`(画像PDF読み取り)— 仕様確定済み**

画像解析の公開仕様が確定しました。対応形式は **png/jpg/jpeg のみ**です。
(出典: `mybookshelf/docs/dev/RIBBON_API_CONFIRMED.md` D5)

- `ChatGPTV(Text, imageInputs, [roleSystem], [resolution], [toolN])`
- `imageInputs`: Base64文字列(複数はカンマ区切り、最大10枚)
- `resolution="high"` で高精細オプション

実装では、`Base64FromFile()` 等の補助関数を用いて画像をBase64エンコードし、上記シグネチャで呼び出します。
PDFは従来どおり、文字抽出を試みて失敗した場合は「画像PDF」扱いになり、E0303が表示されます。

**`src/opt/optMarkdown.bas`(Markdown整形表示)— 仕様確定済み**

Markdown表示の公開仕様が確定しました。
(出典: `mybookshelf/docs/dev/RIBBON_API_CONFIRMED.md` D6)

- `CellMarkDown(rng As Range, [isComment As Boolean=False])`
- **セルに既に入っているMarkdown 文字列を書式付き表示に変換する**
  (文字列を別途渡す方式ではなく、対象セルに既に入っているMarkdownを読む設計)
- 追加の関数 `OpenWordMark(Text As String)` でMarkdown をWord形式で開く

実装では、セルに Markdown 文字列を先に書き込んでから `CellMarkDown(rng, False)` を呼び出す流れになります。

`src/opt/optDiffDoc.bas`(約款差分)にも同じ形式の `SIGNATURE ASSUMPTION` ブロックがありますが、こちらは確認済みの `ChatGPT()` 関数しか使っていないため未確認の引数仕様はありません。ブロックの内容は「対応ファイル形式をtxt/md/csvに限定した設計判断とその見直し案」です。対応形式を広げたい場合はこのブロックの指示に従ってください(既定で `feature_diffdoc` は `TRUE` のため、フラグ操作は不要です)。

### 手順B: 対応する `config` フラグを `TRUE` にする

`config` シートを再表示し、該当行のB列を `TRUE` に書き換えます(または `modConfig.SetValue "feature_tts", True` のようにVBEのイミディエイトウィンドウから実行)。

| 直したモジュール | フラグ名 |
|---|---|
| `optTts` | `feature_tts` |
| `optVision` | `feature_vision` |
| `optMarkdown` | `feature_markdown` |

`build/build_mybookshelf.py` の既定値を恒久的に変えたい場合は、1節で引用した `build_config_rows()` 内の該当行の `False` を `True` に書き換えてから再ビルドしてください。

### 手順C: スモークテストを1回実行する

1. `Alt+F11` → `Ctrl+G` でイミディエイトウィンドウを開く
2. 対象機能を1回だけ手動で呼び出して結果を確認する(例: Wordで開くなら「ホーム」で回答を1件出してから **「📝 Wordで開く」** ボタンを押す。ボタンが出ていない場合は `modUIMain.EnsureLayout` を再実行してから確認する)
3. `🩺診断` を押し、`[追加機能(opt)]` の該当行が「モジュールあり / 設定有効」になっていることを確認する
4. 失敗する場合は手順Aで直した `SIGNATURE ASSUMPTION` の仮定(引数の順番・成功判定式)が実際のリボン仕様とズレていないか、`err_log` シートの詳細(`detail`列)と突き合わせて再修正する

## 4. 新しいopt機能を追加する手順

新しい追加機能(例: 要約専用ボタンなど)を増やす場合も、既存4機能と同じ形に揃えます。

### 手順1: `src/opt/optXxx.bas` を新規作成する

- `Public Function Ping() As Boolean`(常に `True` を返すだけ)を必ず持つ(`modFeatures.ModulePresent` が実在確認に使う契約)
- リボン呼び出しは `modGateway.TryRibbonRun` のみを使う(自前で `Application.Run` しない)
- コアモジュールへの参照は基盤層(`modAppDef`/`modConfig`/`modLog`/`modUtil`/`modGateway`/`modTypes`)+ `modUIMain.SetStage` のみ
- 例外を外に出さない(失敗は `"#ERR:..."` という文字列で返す)
- 仕様が未確認な関数を呼ぶ場合は、既存4モジュールと同じ形式で `' === SIGNATURE ASSUMPTION ===` ブロックをファイル冒頭に書く

### 手順2: `build/modules.json` に1行追加する

1節で引用した4行と同じ形式で、`role` を `"opt"` にして追記します。

```json
    { "name": "optXxx",              "path": "src/opt/optXxx.bas",                     "role": "opt",  "type": "std",   "wave": "N-X" },
```

### 手順3: `build/build_mybookshelf.py` の `build_config_rows()` にフラグ行を追加する

1節で引用した4行と同じ形式で、既定 `False` の行を追記します(日本語の説明も必ず添える)。

```python
        ("feature_xxx", False, "opt機能フラグ: (新機能名)(仕様確認後にTRUEへ)"),
```

### 手順4: `src/core/modFeatures.bas` の3箇所にfeatureIdを登録する(Ping契約・対応表)

`modFeatures.bas` は featureId(`"xxx"`)とモジュール名(`"optXxx"`)の対応をここに持っています(実際の行)。

```vba
Private Function ModuleNameOf(ByVal featureId As String) As String
    Select Case featureId
        Case "tts": ModuleNameOf = "optTts"
        Case "vision": ModuleNameOf = "optVision"
        Case "markdown": ModuleNameOf = "optMarkdown"
        Case "diffdoc": ModuleNameOf = "optDiffDoc"
        Case Else: ModuleNameOf = ""
    End Select
End Function
```

この `Select Case` に `Case "xxx": ModuleNameOf = "optXxx"` を1行追加してください。あわせて `ModulePresent` の結果キャッシュ用に、4機能と同じ形の `Private mChkXxx As Boolean, mValXxx As Boolean` 変数と、`GetCache`/`SetCache` 内の `Select Case` にも `"xxx"` の分岐を追加します(既存の `"tts"`/`"vision"`/`"markdown"`/`"diffdoc"` の書き方をそのまま踏襲すればよい機械的な追加です)。

### 手順5: `tools/vba_lint.py` の `CONTRACT` に追記する

Lintは各opt モジュールが「契約どおりのPublic関数だけを持っているか」(`"closed": True`)を検査します。現在の4行(実際の行):

```python
    "optTts": {"closed": True, "required": ["Ping", "SpeakAnswer"]},
    "optVision": {"closed": True, "required": ["Ping", "ExtractImagePdf", "ExtractImagePdfText"]},
    "optMarkdown": {"closed": True, "required": ["Ping", "RenderMarkdownAt"]},
    "optDiffDoc": {"closed": True, "required": ["Ping", "CompareTwoDocsDialog"]},
```

同じ形式で1行追加します(`Ping` に加えて、あなたが新設したPublic関数名を全て列挙する)。

```python
    "optXxx": {"closed": True, "required": ["Ping", "YourFunctionName"]},
```

この行を追加し忘れると、Lintは新モジュールの契約を検査しないまま通してしまう(=不整合の見逃し)ので、**必ず追記してください**。

### 手順6: UIボタン(必要な場合のみ)を追加する

ホーム画面に操作ボタンが必要な機能の場合、`modUIMain.EnsureLayout`(または `modUIShelf.EnsureLayout`)の中で `modFeatures.FeatureEnabled("xxx")` が `True` のときだけボタンを生成し、ボタンの `OnAction` は同モジュール内のラッパー(`OnXxxButton`)経由で `modFeatures.InvokeFeature` を呼ぶようにします。「📝 Wordで開く」ボタンの実物(`src/ui/modUIMain.bas`)がそのままテンプレートになります。

```vba
    ' ---- opt機能: Wordで開く(有効な時だけ生成。§7.7) --------------------------
    If modFeatures.FeatureEnabled("markdown") Then
        AddButton ws, ws.Range("E31:H32"), "btn_word", "📝 Wordで開く", "modUIMain.OnOpenWordButton"
    End If
```

### 手順7: 検証してから配布する

1. `python3 tools/vba_lint.py` を実行し `ERROR: 0件` を確認する
2. `python3 tools/run_lo_tests.py` を実行し `FAIL 0` を確認する
3. `python3 build/build_mybookshelf.py --dev` でビルドし、`docs/40_受入チェックリスト15分.md` の該当項目に準じて実機で1回スモークテストする(フラグは `FALSE` のままでよい。まずは「無くても壊れない」ことを確認する)
4. 実際のリボン仕様が判明したら、本文書 §3 の手順でフラグを `TRUE` にする
